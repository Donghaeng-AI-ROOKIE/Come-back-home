## 가입·푸시·후속 검증 한계

공개키로 실제 가입 endpoint를 호출해 새 합성 계정과 로그인 세션이 반환되는 것을 확인했다. 이 계정으로 최종 배포에서 브라우저 로그인→보호자 홈→내 정보→새 탭 세션 복원→로그아웃을 확인하고 정확히 해당 합성 계정만 삭제했다. 사용자 실제 로그인 세션은 변경하지 않았다. 가입 API 연결 검사와 가입 폼의 모든 UI 입력 검증을 구분한다. [가입·브라우저 검사](public-signup-browser.json).

현재 읽기 확인한 Auth 설정은 `disable_signup=false`, 이메일 provider활성, `mailer_autoconfirm=true`다. 이 점검에서 이메일 확인 설정을 끄거나 보안 정책을 바꾸지 않았다. 현재는 가입 확인 메일을 기다려야만 로그인하는 설정이 아니므로10월8일의‘메일 확인 필요/기본SMTP 제한’ 이력과 구분한다. customSMTP의 현재 설정·실제 이메일 도착은 확인하지 않았다. [현재Auth설정](auth-settings.json).

실제 휴대폰 푸시 도착과 위치 권한·수신 후 행동은 미검증이다. 실제 발송0이라는 합성 격리 성공을 실기기 푸시 성공으로 바꾸지 않는다. 이전 동일 이미지의300합성 수신자 판정·stub일치 검사와 이번 실제 발송 차단 검사도 구분한다.
