# 주변 산책 추천 복구 — 2026-10-12

**마포구에서 추천 목록이 비던 원인을 수정하고 서버와 웹에 배포했다. 공개 신촌 지점에서 실제 OSM 장소 4개를 받았고, 배포된 서비스의 인증·작업 대기열을 거친 조회도 통과했다.** 사용자 GPS를 읽거나 검증 입력으로 쓰지 않았다.

## 원인과 수정

- 외부 지도 오류를 `200 + []`로 숨겨 ‘주변 장소 없음’으로 표시했다. 조회 실패는 이제 `503`과 다시 불러오기 안내, 정상 빈 검색은 별도 안내다.
- 대체 서버 `overpass.osm.ch`는 스위스 데이터 전용이다. 한국 조회에 맞는 전 세계 데이터 서버 2개로 정리했다. 이전 kumi 서버의 현재 주소는 private.coffee다. [OSM 공식 서버 목록](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances).
- Overpass HTTP 200 응답의 timeout remark도 실패로 처리한다. 서버별 15초, 클라이언트 45초 대기로 맞췄다.
- 빈 결과를 서버 메모리에 영구 캐시하지 않고 앱 캐시는 5분으로 제한한다. 다시 검색 버튼과 화면 새로고침에 추천 재조회도 연결했다. 위치를 못 얻었을 때는 null 좌표로 요청하지 않는다.
- 이름 있는 400m 이상 OSM 구간·반경 2km 필터와 길이 계산은 유지한다. 모든 산책 가능 도로의 경로 생성이나 접근 가능성 보증은 아니다. 공원 카드의 선은 공원 경계로, 검증된 공원 내부 통행 경로가 아니다.
- 좌표 설명 주석을 정정했다. 산책 조회는 현재 좌표를 서버와 공공 지도에 전송한다. 비용 원장에는 좌표·쿼리·보호자 자료를 넣지 않는다. 실패·재시도도 기록하며 금액은 미확인이다.

## 실제 지도와 서비스 조회

| 공개 대표 지점 | 실제 서비스 응답 | 장소 예시 |
|---|---:|---|
| 마포구 신촌 주변 | 4개 | 경의선 숲길, 와우근린공원, 백양로, 청송대 |
| KINTEX | 4개 | 킨텍스온누리공원, 왕벚나무길, 공개공지, 보행자길 |

첫 온라인 검사는 기존 GPU 서버에서 공개 마포/KINTEX 지점으로 최대 4회, 8초 상한으로 수행했다. 마포는 두 서버 시간 초과, KINTEX는 한 서버 실패 뒤 실제 4개 경로를 수신했다. 사용자 승인 후 추가 최대 2회·각 15초 검사를 진행했고 **1회로 마포 응답을 받았다(6.498초)**. 미사용 1회를 소진하지 않았다. 원본 지도·취득 시각·반경 2km 쿼리·해시는 서버의 격리 검증 폴더에 보존했으며 예측용 KINTEX 자산은 교체하지 않았다. [첫 시도](online-first.json), [승인 후 마포 결과](online-mapo-approved.json).

후속 사용자 승인 후 합성 계정 1개를 생성·삭제하며 실제 Supabase 인증→작업 대기열→새 worker 조회를 확인했다. 최대 30회 중 **12회 전송**으로 두 지역의 실제 좌표열·길이와 res9·5.8㎢ 정책을 확인했다. 추가 지도 조회·모델 호출·실제 푸시는 0회다. 임시 계정도 삭제했다. [실제 연동 결과](service-smoke.json). 앞선 자동 승인 차단은 각 사용자의 명시적 승인 후 해소됐으며 차단을 우회해 실행하지 않았다.

## 배포와 회귀 검사

- Backend: `cbh-cloud-worker:20261012-walk-45b6086`. 기존 이미지에서 `api/geo.py`와 `geo/nearby.py`만 교체했다. 다른 모든 backend Python 소스 해시가 같다. **예측 엔진·개인화30/문헌70·res9·5.8㎢·축OFF는 변경하지 않았다.** [격리 검사](preflight.json).
- 배포 직전 사건·프로필·인터뷰 0을 확인하고 SQLite 온라인 스냅샷·동일 데이터 볼륨·복구 명령을 보존했다. 실제 OSM 성공 응답을 정상 조회 캐시로 준비할 때 추가 외부 호출은 없었다. [worker 배포](worker-deployment.json).
- Web: `315d7811-d59e-4b10-baa1-9f914a2db3c8`, 소스 `45b6086`. 공개 JS 해시와 실제 compiled Supabase 설정이 빌드 결과와 일치한다. [공개 웹 증빙](production-frontend.json).
- geo·bridge·auth·walk **44개 검사**, 프런트 **30개 검사**, TypeScript·운영 빌드 통과. 실제 화면 컴포넌트의 오류/빈 목록 구분, 재검색, 화면 새로고침, null 좌표 차단, 정상 경로 표시를 검사했다.

운영 로그 원문 전송은 자동 승인 검토가 차단해 서버 안에서 오류 종류만 집계했다(HTTPError 3·TimeoutError 3). 좌표나 로그 원문을 가져오지 않았다.

이 결과는 공개 대표 지점의 조회 검증이다. 사용자 기기의 실제 GPS·권한·브라우저에서 모든 추천 카드가 뜨는 것을 대신한 검사는 아니다. 마포구 전체에 항상 4개가 있다는 뜻도 아니며, 같은 구라도 위치와 OSM 등록 상태에 따라 목록은 달라진다. 공공 지도 서버의 과부하가 남아 있어 모든 조회 성공을 보장하지 않는다. 다시 실패하면 ‘장소 없음’으로 숨기지 않고 재시도할 수 있다.
