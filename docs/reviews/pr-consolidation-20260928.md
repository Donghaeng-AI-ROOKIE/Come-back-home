앞단의 #250 → #252 → #253 → #258은 하나의 브랜치 계보다. 앞선 세 PR의 모든 커밋이 #258에 포함됨을 Git 조상 관계로 확인했다. #258을 develop 대상으로 통합하고, #250·#252·#253은 내용이 보존된 상태에서 중복 검토 대상으로 닫는다. 원본 브랜치와 기존 PR 본문·토론은 삭제하지 않는다.

## 충돌을 어떻게 해결했는가

- Mi:dm HTTP 요청은 `logged_json_request` 한 경로만 사용한다. 2.5 전용 12초 제한과 성공·실패 사용량 기록을 동시에 유지한다. 실패 시 예외 종류·HTTP 상태·시간을 기록하며 제공자 오류 본문이나 보호자 원문·키를 로그에 남기지 않는다.
- 지도 결과의 후보 상세(`detail`)와 확인 주소(`address`)를 함께 보존한다. 기존 위치 인자의 의미도 유지한다.
- 집 주소를 그 턴에 확인하고 확인된 좌표를 최종 등록에서 재사용한다. 나이·장소만 정정한 경우 변경하지 않은 집 주소를 다시 검증해 정정을 막는 문제를 방지한다.
- #252에서 제거한 단어 기반 이름·나이·행동 추출을 다시 넣지 않는다. Mi:dm 답변 종류 판정과 원문 대조를 사용한다. 주소 말끝 정리와 지도 조회, 장소 이름의 원문 대조는 유지한다.
- 무관한 발화에 다른 장소 이름과 그 발화의 quote를 붙인 재추출도 차단한다. ‘거기서 발견’처럼 직전 질문의 장소를 가리키는 답은 질문과 원문을 함께 검증한다.
- 과거 규칙 추출기에 의존하던 테스트 준비 방식은 현재 모델 추출 계약에 맞추고, 지도 오류·좌표 재사용·과다추출 방지의 기능 검사는 유지했다.
- 단위 테스트의 외부 소켓 연결을 차단해 향후 로컬 키나 기본 지오코더 설정 때문에 실 API가 호출되지 않도록 했다.

## 검증 범위와 남은 구분

Mi:dm 2.5와 앞단의 호출 규약·실패 처리·주소 처리가 함께 동작하는지 로컬 모의 응답으로 검사한다. KT endpoint 표기의 세 형태가 같은 chat completions URL로 이어지고, 한 번만 요청하며, 12초 설정과 비용 원장을 사용함을 검사한다. 프런트엔드 타입과 신고 시각 처리도 검사한다.

새 K·SAR·Mi:dm 실호출은 실행하지 않았다. #255 본문의 2.5 라이브 평가 결과는 작성자가 남긴 기존 결과이며 이번 세션의 재측정이 아니다. 앞단 보고서의 `midm-pro-fp8-kaic` 실험 결과를 KT 2.5 근거 판독의 동일 품질을 입증한 결과로 전용하지 않는다. 프로브 도구도 실행하지 않았다.

통합 후 백엔드 전체 테스트는 **1,096개 통과·2개 건너뜀(7개 subtest)**이었다. 프런트엔드 TypeScript 검사와 신고 시각 테스트 1개도 통과했고, 변경 파일의 공백 오류 검사도 통과했다. GitHub의 기존 열린 PR에는 필수 CI·리뷰 결과가 표시되지 않았으므로 로컬 통과와 GitHub 승인 상태를 구분한다.
