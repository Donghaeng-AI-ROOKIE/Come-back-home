# 온보딩 정보 보존·정정과 초기 주입 검증

작성일: 2026-09-26. **사전 고정한 정보 해석·보존·초기 주입 기준 통과. K 최종 응답 생성은 2건 중단.**

## 검증 목적

보호자가 온보딩에서 설명한 사람의 특성이 이름 수정, 행동 정보의 정정·삭제, 추가 대화 후에도 올바르게 해석되고 초기 시뮬레이션 입력까지 이어지는지 확인한다. 마음 모델의 시간 경과에 따른 변화나 보행 경로의 현실성을 이번 판정에 포함하지 않는다.

기존 코드에는 이름만 바꿔도 행동 요약이 원문 대화를 대체하는 문제와, 오래된 프로필에 새 목적지를 추가해도 최초 등록일 때문에 과거 정보로 내려가는 문제가 있었다. PR #253은 원문과 변경 이력을 함께 보존하고, 목적지 해석이 실제로 인용한 근거의 수집 시각으로 사건 시점의 적용 여부를 구분한다. 보호자 문장을 단어 규칙으로 분류하는 변경은 아니다.

## 실행 방식

- 고정 커밋: `ade2c77d827f43875ed0d0d0f56034a55bb3efdb`.
- 합성 사례 6개를 각 2회 실행. 입력, 정답 범위, 호출 상한, 코드 해시를 호출 전에 고정.
- 실제 이름 수정·행동 수정·추가 대화 완료 함수로 Persona를 만든 뒤, 제품의 K-EXAONE 초안·재검토와 Mi:dm 검증 경로를 호출. 앱 화면을 직접 조작한 실기기 시험이나 온보딩 질문 생성 전체의 시험은 아님.
- 결과를 JSON으로 저장하고 다시 불러와, 사건 시각에 맞춰 초기 입력으로 변환.
- 기존 저장 검색 결과를 사용. 저장 묶음 4건 중 paper 1건만 핵심 특성 해석·재검토에 제공하고 QA 3건은 제외. 조건 해석은 보호자 근거를 읽는 별도 과업. 이번 실행에서 새 검색·임베딩 없음.
- 새 SAR 호출 대신 동일한 유형 기본값을 사용. 따라서 SAR와 K의 우열 비교가 아니라 수정된 앞단의 정보 해석·보존·주입 검증.
- 자동 재시도 없음. 모델의 최종 JSON, 적용 결과, 근거 연결, Mi:dm 확인 결과를 보존. 모델 내부 사고 과정은 보고 자료에 포함하지 않음.

## 사전 고정한 통과 기준

12회 모두 준비 완료, 사전에 정한 100개 세부 확인 항목 모두 충족, 호출한 Mi:dm 검증에 판정 누락 없음, 초기 입력 적용 성공이 필요하다. 결과를 본 뒤 허용 답이나 기준을 바꾸지 않는다. 100개는 6사례를 반복해 점검한 항목 수이며, 독립된 환자 100명의 정확도를 의미하지 않는다.

## 검증하지 않은 범위

마음 모델·보행 시뮬레이션·지도·새 SAR/GPU 추론은 실행하지 않는다. 실제 환자의 관측 경로와 대조하거나 독립된 보호자·전문가가 채점한 연구도 아니다. 휴식 특성의 저장과 이동 반경 입력의 변경은 확인하지만, 실제 보행 중 쉬는 행동까지 구현·검증했다고 해석하지 않는다. 이번 결과의 적용 범위는 수정한 앞단의 합성 회귀 사례다.

### 실제 원문과 출력 예

합성 보호자 원문: “무릎이 아파서 집 앞에서 5분 정도 걷고 나면 앉아서 쉬어야 해요.”

결과는 `mobility=B`(짧은 보행·휴식 필요)와 `rest_pattern`이었다. 이름 수정·다른 행동 정정·잘못된 목적지 삭제 후에도 이 정보가 유지되었다. 초기 입력의 이동 반경 분포는 같은 유형 기본값보다 작아졌다. **5분마다 실제로 앉는 보행을 구현했다는 뜻은 아니다.**

합성 정정 원문: “길을 잃은 두 번 모두 멈추지 않고 계속 걸으셨어요. 기다렸다는 설명은 철회합니다.”

기다림 기록이 있던 사례의 대처는 `wait_for_help`였고, 정정 후에는 `keep_moving`이었다. 이동 능력 B와 공원 반복 발언은 함께 유지되었다. 신체적으로 쉬어야 한다는 사실을 ‘길을 잃으면 보호자를 기다림’으로 취급하지 않았다.

합성 추가 대화 원문: “밤에 길을 잃었던 두 번은 그 자리에서 저를 기다리셨어요. 낮의 두 번은 계속 걸으셨고요.”

저장된 조건은 다음과 같다. 이는 모델 내부 사고 과정이 아니라 제품에 저장된 최종 구조화 결과다.

```json
{
  "behavior_rules": [
    {"period": "clock_day", "dimension": "persistence", "value": "keep_moving"},
    {"period": "clock_night", "dimension": "persistence", "value": "wait_for_help"}
  ]
}
```

실제 출력에는 각 규칙의 `note_ids`도 저장되어 있다. 같은 저장 결과에 오전 10시 사건을 넣으면 `keep_moving`, 밤 10시 사건을 넣으면 `wait_for_help`가 적용됐다. 머무름 전략의 입력 가중치는 기본값 0.10에서 각각 약 0.0357, 0.25로 바뀌었다. **이 값은 엔진 입력 가중치이며, 실제 환자의 행동 확률을 검증한 수치가 아니다.**

### 통과와 별도로 확인한 문제

K-EXAONE 호출 **48회 중 46회는 최종 JSON을 정상 완료**, **2회는 `finish_reason=length`로 종료**했다. 두 응답 모두 `completion_tokens=28000`, 최종 `content` 없음이었다. HTTP는 모두 200이었으며 통신 오류나 시간 초과가 아니었다. 대기 시간만 늘려 해결되는 문제라고 볼 수 없다.

- 사건 후 목적지 추가 1회차: 핵심 특성 재검토가 중단되어 이미 얻은 초안을 사용했다.
- 같은 사례 2회차: 핵심 특성 초안이 중단됐지만 예정된 재검토 단계가 원문에서 해석을 완성했다.
- 추가 재시도는 하지 않았다. 이 두 실행은 **4단계 모두 정상 완료한 실행으로 세지 않는다**. 기존 복구 경로를 거친 최종 입력이 사전 기준을 충족한 것이다.
- 해당 사례의 재검토가 목적지 이동을 공원·시장 환경 전체에 대한 접근 반응으로 넓힌 출력도 있었다. 근거 상황이 `destination_trip`인 것을 확인하는 코드가 제거했고 최종 입력에는 들어가지 않았다. 이는 K 단독 출력과 검증·주입 파이프라인의 결과를 구분해야 하는 실제 예다.

준비 시간은 최소 **137.92초**, 중앙값 **226.90초**, 최장 **496.33초**였다. 전체 실행은 2개 준비 작업을 병행하여 **1,587.6초(약 26분 28초)** 걸렸다. 초기 온보딩 뒤 백그라운드로 처리되는 준비 시간이며, 사건 예측 요청의 소요 시간 측정은 아니다.

`other_traits` 목록은 이름 수정·행동 정정·삭제의 세 사례에서 반복 간 차이가 있었다. 두 반복 모두 필수 `rest_pattern`은 보존했지만 `help_seeking`, `person_seeking`, `time_pattern` 등 나머지 목록이 완전히 일치하지 않았다. 따라서 **필수 판정 재현 성공과 전체 개인 묘사의 완전한 일치는 다르다.** 이 목록 전체의 정확성·일관성은 이번 100개 기준으로 입증하지 않았다.

## 적용 판단

**PR #253의 입력 보존·수정 처리·사건 시점 주입 수정은 채택할 근거가 확보되었다.** 이번에 설정한 앞단 검증 기준을 통과했다. 기존 SAR와 비교하는 새 실험은 아니므로 이 결과만으로 K 단독의 우월성이나 SAR 완전 제거를 주장하지 않는다. K의 최종 해석과 코드의 근거 검사, Mi:dm의 제한된 확인을 합친 결과다.

K를 제외하는 결론은 아니다. K 개인 해석을 유지하면서 원문과 수정 이력을 보존하는 이 구조를 사용하되, **응답 예산 소진과 보조 특성의 불일치는 앞단 내부의 남은 보완점으로 기록**한다. 이는 마음 모델 검증을 끝낼 때까지 앞단 판정을 미룬다는 뜻도 아니다.

배포 판단은 구분한다. 이번 의미 검증은 통과했지만, 이 실행에서 맥미니 운영 컨테이너를 교체하지 않았다. 앞서 띄운 별도 localhost 검증 후보만 유지한다. 2건의 생성 중단을 포함한 상태를 '전 호출 정상, 앞단 완벽 완료'로 보고하고 운영본을 자동 승격하지 않는다. PR은 수정 검토가 가능한 상태이며, 운영 승격은 별도 판단 항목으로 남긴다.
