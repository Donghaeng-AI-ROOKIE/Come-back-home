# 마음모델 재학습 2차 — 실행 전 준비

2026-09-29 작성한 실행 전 계획의 보존본. 이후 사용자가 승인했고 결과는 README.md에 별도로 기록했다. 아래 pending 표현은 실행 전 시점의 상태다.

## 목적

온보딩된 특정 치매 어르신의 개인 조건을 현재 환경·피로·최근 사건과 연결해 실행 행동과 공개 설명에 함께 반영한다. JSON 형식 통과만으로 성공이라 하지 않는다. 앞단 K 개인 해석이나 SAR 초기 이동 성향 모델의 교체는 이번 범위가 아니다.

## 두 학습군

| 항목 | A | B |
|---|---|---|
| 출발 모델 | EXAONE 3.5 7.8B Instruct, 새 LoRA | 동일 |
| 학습 자료 | 기존 72개 | 기존 72개 + 보강 48개 = 120개 |
| 학습 | 6epoch 1회 | 6epoch 1회 |
| 비교 지점 | 2·4·6epoch | 2·4·6epoch |
| 개발 생성 | 동일 16개 × 3 = 최대 48회 | 동일 16개 × 3 = 최대 48회 |

이전 어댑터를 이어 학습하는 방식이 아니라 같은 베이스에서 새 LoRA 두 개를 학습한다. 어댑터 초기화 전부터 seed 928을 고정한다. rank 16, alpha 32, dropout 0.05, 유효 batch 4, 학습률 1e-4 고정·warmup 0으로 통일한다. 두 군 모두 같은 스케줄을 쓰며, 이전 cosine 2epoch 결과와의 차이를 데이터 효과만으로 설명하지 않는다.

2·4·6epoch는 하나의 6epoch 학습 궤적에서 저장한 체크포인트이다. 서로 독립된 2·4·6epoch 학습 3회를 실행하는 것이 아니다. A는 18 step/epoch, B는 30 step/epoch라 데이터·학습량이 함께 바뀐다. 따라서 A/B 비교는 보강 후보 전체 비교이며 순수한 데이터 효과를 입증하는 계산량 동일 실험은 아니다.

## 보강 데이터

8개 합성 상황 계열 × 6조건 = 48개. 소음/혼잡/미확인, 두 조건의 동시 성립, 같은 소음에 대기하는 다른 사람, 현재 거부, 휴식 종료와 회복, 보호자 지시와 직접 관찰, 최신 정정, 익숙한 장소를 찾는 반응을 명시적으로 작성했다. 단어로 정답을 자동 추출하는 운영 규칙은 만들지 않았다.

- 보호자 원문·조건·정답·공개 설명을 `추가48개_검토.md`에 제공.
- 같은 계열은 모두 학습 분할에만 포함. 기존 학습 72개와 개발·평가 파일은 보존.
- 구조 감사 152개(학습 120·개발 16·평가 16) 통과. 로컬 테스트 18개 통과.
- 실제 환자 데이터·전문가 검수 데이터가 아님. 기존 개발 실패 유형을 보고 보강했으므로 개발 점수 상승은 독립 평가 성과가 아님.
- 기존 평가 16개도 작성자가 이미 볼 수 있었던 자료라 독립 사람 평가로 부르지 않음. 이번에는 생성하지 않는다.
- 실제 tokenizer 길이와 GPU 라이브러리 호환성은 승인 후 서버 사전 검사에서 확인. 로컬 테스트가 GPU 학습 성공을 보증하지 않음.

## 판정

모든 체크포인트에 동일 입력·greedy 생성·출력 한도 900토큰을 적용한다. 개발 원문 응답을 다음 네 층으로 따로 판정한다.

1. 원문 응답 계약 통과.
2. 행동·목표·회피 지시 일치. 코드블록 진단 수치는 원문 통과와 별도 기록.
3. 공개 설명이 개인 원문과 현재 사실에 맞는지. 미확인을 없음으로 바꾸거나 타인의 행동을 개인에게 옮기면 중대한 오류.
4. 조건만 바뀐 같은 계열에서 행동과 설명을 모두 유지·전환하는지.

개발 16개에서 행동과 근거가 모두 맞고 중대한 오류가 없는 후보를 다음 평가 대상으로 삼는다. 이를 실서비스 배포 기준 통과로 간주하지 않는다. 후보가 없으면 실패 사례를 기록하고 해당 실행 묶음을 종료한다. 외부 검토·새 평가 사례·실제 온보딩 연결·KINTEX 연속 행동·예산 재사용 검증은 후속 단계다.

## 실행 상한과 서비스 영향 — 승인 대상

- 기존 A100 80GB GPU 1장, 신규 학습 최대 2회. 각 실행은 로딩·학습·개발 생성을 포함해 최대 20분, 합계 최대 40분.
- 모델 생성 최대 96회. 실패도 포함하고 자동 재시도 없음. 전체 출력 상한 86,400토큰. 입력은 호출당 최대 4,096토큰 이내 전처리 확인 후 실행하며 실제 사용량 기록.
- 신규 K-EXAONE·Mi:dm API, RAG 검색·임베딩·지도 다운로드 없음. 기존 로컬 모델·고정 연구 자료만 사용.
- 서버 GPU 여유가 부족하면 이전처럼 EXAONE 서빙을 일시 중단해야 할 수 있음. 같은 대상 서비스만 중단하고 Mi:dm은 유지. 서빙 중단부터 45분 시점에는 학습 중단·복구를 시작하도록 상한 설정. 다른 작업이 점유하거나 복구 설정이 확인되지 않으면 학습하지 않음.
- 서버 접근은 업로드·읽기 사전 점검, 학습 2회, 기존 EXAONE 제어·복구 및 모델 목록 확인, 기록 회수 범위. 복구 점검은 모델 목록 확인이며 추가 생성 호출 없음.
- 단가·예상 청구액·실청구액·GPU 청구 시간·지원 차수는 미확인. 벽시계 실행 시간과 청구 시간을 구분.
- 원격 시작/종료·실패·생성 usage 원장을 남기고 event_id로 공용 `결선/연구지원_사용기록/usage_events.jsonl`에 동기화. 학습 token 노출량은 별도 학습량이며 API 청구로 중복 계산하지 않음.
- 후보 운영 배포 없음. 종료·오류·상한 도달 시 원래 EXAONE 서빙 복구. 추가 실행은 새 범위가 필요함.

원격 모델 경로·런타임 인벤토리는 승인 후 기존 준비 기록과 서버 상태를 대조해 확정한다. PROPOSED JSON의 승인 상태는 pending이며 현재 그대로는 실행할 수 없다. 운영 중단·복구 wrapper도 서버 상태와 대조 후 준비한다.

PROPOSED JSON과 운영 제어 스크립트는 원본 로컬 아카이브에만 보존한다.
