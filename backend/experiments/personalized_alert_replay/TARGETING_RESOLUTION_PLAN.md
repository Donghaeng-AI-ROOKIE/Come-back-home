# res8 타겟팅 재분석 실행 계획

작성: 2026-09-24, 결과 생성 전 조건 고정. 기존 실험·운영 파일은 수정하지 않는다.

## 질문과 범위

주 질문은 같은 res8 정책에서 C 개인화가 B 비개인화보다 발송면적을 줄이는가,
그리고 정답 위치 포함률은 얼마나 변하는가이다. res7은 보조 비교다.
res9 예측 차이가 부모 셀로 합쳐져 사라지는 빈도를 함께 계산한다.
실제 수신자 감소, 발견 성과, 개인정보 최소화 충족 여부를 입증하지 않는다.

## 고정 조건

- 입력: `results/persona_abc_v2_r1.jsonl`, 9명·27개 시나리오·108시점.
- B/C 동일 시나리오·시간·정답 좌표를 검증한다. invalid·비정규화·짝 불일치는 자동 제외하지 않고 실패 처리한다.
- 운영 함수 `select_alert_cells`, `target_parent_cells`, `relative_prob_by_parent`를 직접 사용한다.
- 커버리지·셀 상한·참여도 문턱은 실행 시 settings에서 읽고 결과에 저장한다. 확인된 값은 0.8, 500, high=.30/normal=.45/low=.60이다.
- res7/res8 × B/C × 참여도 세 등급. 실제 참여도 분포를 가정해 합치지 않는다.
- 정답 위치는 좌표에서 해당 해상도로 직접 계산한다. 기존 res9 부모 대리 결과도 별도 보관한다.
- 부모 점수는 전체 POA의 최고 상대확률이다. 부모 질량 합산/top-N 정책으로 바꾸지 않는다.
- 인물 단위 대응 부트스트랩 10,000회, seed=20260924, 95% 백분위 구간. 비교마다 같은 재표집 인덱스를 쓴다.
- 9명 기반 탐색적 불확실성 구간이며 다중비교 보정은 하지 않는다. 허용 포함률 하락폭 미설정이므로 성공/비열등 판정은 하지 않는다.
- 문턱·예산의 사후 조정이나 동일 포함률을 맞추는 탐색은 이번에 하지 않는다.

## 출력

새 디렉터리에 시점별 `snapshots.jsonl`, 설정/검증/비교/인물별 `summary.json`, 한국어 `REPORT.md`를 저장한다.
기존 출력 디렉터리가 있으면 실행을 중단해 덮어쓰지 않는다.
전체 res9, 선택 res9, 문턱 전 부모, 문턱 후 구역의 수·면적을 기록한다.
면적 감소율은 합산 면적 비율이며 음수는 증가, 분모 0은 미정의다.
선택 res9 집합이 다른데 최종 발송 집합은 같은 시점의 수와 조건부 비율을 기록한다.

## 실행

backend에서:

```powershell
python -B -m pytest tests/test_targeting_resolution.py -q -p no:cacheprovider
python -B -X utf8 -m experiments.personalized_alert_replay.analyze_targeting_resolution --output-dir experiments/personalized_alert_replay/results/targeting_resolution_20260924
```

외부 모델 호출·전송·기기 저장 갱신 없는 짧은 로컬 분석이다. 체크포인트 대신 새 출력 경로로 동일 명령 재실행한다.
검증의 발송 함수 호출은 기기·전송·발송기록 함수를 모두 대체한 메모리 테스트에만 사용한다.

## 후속 운영 작업

실험 후 res8을 채택하면 폰 위치 변환, API/저장 필드·해상도 검증, 알림 조회·앱 판정,
구버전 호환, 갱신 시각, 페이로드와 실기기 동작을 함께 변경·검증해야 한다.
기존 res7 값으로 정확한 res8 위치를 복원할 수 없으므로 폰이 현재 GPS로 계산한 셀 번호를 새로 등록한다.
GPS 원좌표 전송이나 회원가입 재실행을 뜻하지 않는다. 실제 대상 기기 수 비교는 별도 검증이다.
