# 상황별 분리 요청 검증 결과 — 2026-09-30

## 결론

한 요청에서 여러 가정 상황을 함께 해석하는 방식을 요청당 한 상황으로 나눠 12회 실호출했다. JSON은 12회 모두 완성됐지만 행동 선택은 11/12로, 이전 후보의 11/12와 같았다. 설명과 행동이 서로 모순되거나 원문에 없는 조건을 추가하는 문제도 남았다. 호출 수가 4회에서 12회로 늘어난 데 비해 개인 조건 반영이 개선됐다는 근거를 확보하지 못해 이 후보는 채택하지 않는다.

이번에는 사용자가 구체적인 12회 범위 제시 후 “그냥 실행해”라고 지시한 승인을 기록하고 추가 질문 없이 실행했다. 재시도는 없었고 12회 모두 끝났다.

## 목적과 방법

이전 JSON 지시 수정 후보에서 등록 장소 B로 근거 없이 목표를 바꾸는 오류가 발생했다. 서로 다른 가정 상황을 한 응답에 담아 조건을 혼동하는 것인지 확인하려고 상황별 요청을 분리했다.

동일한 합성 인물의 두 입력을 사용했다. 시장 소음이 있고 혼자인 입력은 혼잡 가정 2개, 시장 소음이 있고 동행 미확인인 입력은 혼잡·동행 가정 4개였다. 총 6개 가정을 2회씩 반복했다. 모델, system 프롬프트, 원문, 개인 요약, 관측, 가정값, 선택지, Thinking, 샘플링, 출력 상한은 유지했다. 각 요청의 가정 목록과 응답 스키마에서 해당 가정 하나만 남겼다.

모델에게 정답은 주지 않았다. 모든 가정의 결과를 보존하고 같은 명령이면 그 명령을, 명령이 다르면 판단 유보를 반환하는 기존 집계 규칙을 유지했다. 부분 응답을 임의로 채우거나 틀린 응답을 빼지 않았다.

## 결과 비교

| 항목 | 여러 상황을 한 번에 전달 | 상황별로 분리 전달 |
|---|---:|---:|
| API 호출 | 4회 | 12회 |
| 완전한 JSON | 4/4 | 12/12 |
| 가정별 행동 일치 | 11/12 | 11/12 |
| 모든 가정의 행동이 맞은 입력·반복 | 3/4 | 3/4 |
| 최종 집계 행동·유보 일치 | 3/4 | 4/4 |
| 반복 간 전체 명령 동일 | 1/2 | 1/2 |
| 출력 한도 종료 | 0회 | 0회 |

‘최종 집계 4/4’는 행동이 모두 올바르다는 뜻이 아니다. 동행 미확인 입력은 가정에 따라 결과가 갈리면 판단 유보를 반환한다. 한 가정에서 기존 이동 대신 근거 없는 새 목적지를 골라도 다른 가정과 결과가 달라 유보가 된다. 이 때문에 잘못된 개별 행동이 최종 점수에 가려졌다. 실제 개인 조건 반영 판정에서는 가정별 행동과 설명을 함께 봐야 한다.

## 실제 모델 출력

### 새 목적지 명령과 기존 이동 설명의 충돌

동행이 있고 혼잡하다는 가정에서 다음 명령은 `seek_1`이었다. 이는 등록 장소 B를 새 목표로 삼는 명령이다. 그러나 공개 설명은 다음과 같았다.

> 시장 소음 존재하나 동행자 미확인으로 혼자일 때 돌아감이 원칙이나 동행자 가정 시 continue 진행

같은 응답에서 기존 이동을 계속한다고 설명하면서 새 목적지를 설정했다. 장소 B로 바꿀 근거도 없다. 이는 단순 JSON 문제가 아니다.

### 명령은 맞아도 근거가 틀릴 수 있음

혼자이고 시장 소음이 있는 다른 요청은 `avoid_market`을 선택했지만 설명에는 다음 문구가 포함됐다.

> 시장 소음 상황 단독 회피 조건이 명확하지 않아 행동을 유보하되, 소음만의 영향을 회피하기 위해 시장 멀리 이동.

보호자는 혼자이고 시장이 시끄러우면 돌아간다고 명시했다. 조건이 불명확하다고 설명하거나 판단 유보와 회피를 동시에 주장할 근거가 없다.

또 다른 설명은 “혼잡까지 확인되면 시장 회피가 필요하다”고 했다. 혼잡은 실측 사실이 아닌 가정이고, 보호자 원문에 혼잡을 추가 조건으로 삼는 내용도 없다.

### 일관되게 나온 응답도 있음

같은 혼자임 입력의 두 번째 반복에서는 다음과 같이 개인 원문과 현재 상황을 맞게 연결했다.

> 원문에 따라 시장 소음이 있고 동반자가 없으므로 가정된 혼잡 상황에서도 시장에서 멀어지는 행동이 필요함

좋은 응답이 나온 사실과 반복해서 안정적으로 나온다는 주장은 구분한다.

## 의미 검토와 한계

고정 합성 정답에 대한 행동 일치는 11/12다. 별도로 최종 설명까지 검토하면 6개 통과, 3개 실패, 3개 입력 명확화 필요다. 입력 명확화 필요는 일반 동행 가정을 가족 동행 예외로 적용한 경우다. 원문은 가족을 말하지만 관측·가정 필드에는 관계가 없다는 기존 한계를 그대로 남겼다. 고정 정답이나 이전 점수는 소급 변경하지 않았다.

검토자는 Codex이며 비맹검 평가다. 치매 환자 실측 데이터나 돌봄 경험자 검토가 아니다. 합성 인물 한 명의 두 입력을 반복한 작은 개발 진단으로, 다른 인물 일반화·실제 경로 예측·임상적 재현성을 평가한 결과가 아니다. 이번에는 KINTEX 보행 엔진도 실행하지 않았다.

## 사용량

- K-EXAONE 12회, 입력 27,280토큰, 출력 27,674토큰. 실패·재시도 숨김 없음.
- API 요청당 시간 중앙값 약 17.9초, 최대 약 37.2초. 여러 요청을 합친 입력당 전체 처리 시간이나 앱 지연시간과 다르다.
- 단가·실청구액·지원 차수 미확인. 이번 실험을 포함해 해당 실험 폴더 누적 99회의 시작·종료 이벤트 짝 확인.
- 신규 GPU 학습·RAG 검색·지도 조회·Mi:dm 호출·서비스 중단·배포 없음.

## 다음 개선 방향

요청 분리만 계속하기보다 현재 상태의 전달 구조를 정리할 필요가 있다. 현재 입력은 원본의 미확인값과 별도 가정값을 함께 제시하므로 모델이 어느 값을 현재 가정 상황에 적용해야 하는지 혼동할 수 있다. 이것은 관찰된 오류를 설명하는 가설이며 아직 원인이 확정된 것은 아니다.

후속 후보는 해당 가정에 적용할 상태를 한 구조로 제공하고, 각 값에 실제 관측인지 가정인지 출처를 붙이는 방향이다. 원본 입력은 별도로 보존하며 가정을 실제 관측으로 승격하지 않는다. 동행 존재와 가족 관계도 분리한다. 이 변환은 구조화된 관측의 표현을 정리하는 코드이며, 보호자의 자유 문장을 단어별로 행동에 매핑하는 코드가 아니다. 개인 조건·예외·우선순위는 모델이 원문과 앞단 해석에서 읽도록 유지한다.

후속 실호출은 이번 12회에 포함되지 않았다. 현재 결과로 배포 적합성이나 개선 성공을 선언하지 않는다.
