# 마음모델 개선 결과: 다음 행동 선택과 Thinking

2026-09-29. **개선 신호를 확인했다. 가장 나은 후보는 개발 8개 중 행동 선택 7개, 행동과 설명의 의미 판정 6개를 통과했다. 배포 기준이나 별도 평가 진입 기준을 통과한 것은 아니다.**

이번 범위에서는 K-EXAONE 개발 실호출 40회를 완료했다. 별도 평가 32회는 실행하지 않았다. 기존 EXAONE·Mi:dm 서비스 중단, GPU 학습, 운영 교체 없음.

## 목표

보호자가 온보딩한 특정 사람의 성향·조건·예외가 현재 환경과 피로에 맞는 행동으로 나타나는지를 확인했다. ‘치매라서 보통 이렇게 행동한다’는 일반 규칙으로 개인 정보를 덮어쓰지 않는다. 형식 준수와 실제 개인 조건 반영을 분리해 판정했다.

## 먼저 발견한 데이터 구성 오류

직전 LoRA 학습 기록 96개 중 네 건(T04-3, T07-1, T07-4, T14-4)은 같은 목적지로 이미 걷고 있는데 seek를 정답으로 주었다. 프롬프트는 이를 continue로 정의하고 있었다. Codex가 만든 데이터의 계약 충돌이다.

새 버전에서 행동·목적지 처리·설명·학습 응답·rubric을 함께 수정했다. 이전 원본과 결과는 보존했다. **수정 데이터로 재학습한 결과는 아직 없다.** 이 네 건이 소음·동행 조건 실패 전체의 원인이라는 뜻도 아니다.

## 무엇을 비교했나

같은 합성 개발 8개(두 개인 사례 계열)에 다섯 후보를 각각 한 번 실행했다. 원문·기대 행동은 변경하지 않았다.

1. 기존 전체 문맥 전달.
2. 개인 자료를 보존하고 현재 관측을 필드 경로와 값의 목록으로 전달.
3. 원문 인용과 현재 관측, 조건 적용 여부를 연결한 checks를 함께 출력.
4. 지금까지 실행한 행동과 다음에 선택할 명령을 구분. 실행 가능한 명령 중 하나를 선택. Thinking 끔.
5. 4번과 같은 입력·출력 방식에 Thinking 켬.

출력 카드의 continue/rest/avoid 등을 엔진 명령으로 옮기는 부분은 코드가 담당한다. 어떤 개인에게 어떤 카드가 맞는지는 K가 판단한다. 보호자 단어를 파싱해 정답 행동으로 매핑하거나 잘못 선택한 행동을 코드로 교정하지 않았다.

## 결과를 세 가지로 구분

| 구성 | 행동 명령 선택 일치 | 계약·인용 검증 통과 | 기존 실행 기준 전체 통과 |
| --- | ---: | ---: | ---: |
| 기존 전체 문맥 | 0/8 | 3/8 | 0/8 |
| 현재 사실 목록 | 0/8 | 0/8 | 0/8 |
| 원문·관측 연결표 | 0/8 | 1/8 | 0/8 |
| 다음 행동 선택 / Thinking 끔 | 2/8 | 4/8 | 1/8 |
| 다음 행동 선택 / Thinking 켬 | 7/8 | 6/8 | 5/8 |

‘행동 선택 일치’는 인용 오류와 별도로 선택된 행동·목적지·회피·유보가 기대값에 맞는지 재집계한 진단 지표다. 기존 실패 판정을 소급 통과로 바꾸지 않았다. 마지막 열은 원래 runner의 그대로인 판정이다. 서로 다른 출력 계약을 같은 명령으로 변환해 비교했으며, 단일 모델 가중치 자체의 우월성을 분리한 실험은 아니다.

최선 후보를 Codex가 원문·관측·응답과 대조한 의미 검토는 **6/8**이다. 모델명을 가린 사람 평가나 임상 평가가 아니다. 직전 LoRA 5/8과 이번 K의 7/8을 동일 조건의 모델 단독 성능 비교로 주장하지 않는다. 같은 두 개인의 개발 사례를 반복해서 보고 개선했으므로 별도 사례 일반화는 미검증이다.

## 실제로 무엇이 나아졌나

보호자 원문: “공원 소리를 꺼려 돌아가는 분이지만, 몸이 많이 지치면 우선 앉습니다. 덜 지쳤고 공원이 조용하면 그대로 걸어요.”

| 현재 상황 | Thinking 후보의 선택 | 판정 |
| --- | --- | --- |
| 많이 지침 + 공원 소음 있음 | rest: 우선 휴식 | 행동·조건 의미 맞음. 원문 인용 변형 별도 오류 |
| 덜 지침 + 공원 소음 있음 | avoid_park: 공원 환경 회피 | 맞음 |
| 덜 지침 + 공원 소음 없음 | continue: 이동 유지 | 맞음 |
| 덜 지침 + 공원 소음 미확인 | defer: 판단 유보 | 맞음 |

휴식 예외와 소음 반응을 구분하고 미확인을 조용함으로 바꾸지 않는 결과가 이 사례 계열에서 나왔다. Thinking을 끈 같은 명령 선택 후보는 행동 선택만으로도 2/8이었고, 켠 후보는 7/8이었다. 사례당 한 번이라 반복 안정성이나 통계적 유의성이 확인된 결과는 아니다.

## 남은 오류

보호자 원문: “시장이 시끄러울 때 혼자면 돌아갑니다. 가족이 옆에 있으면 시끄러워도 같이 원래 길을 갑니다. 조용하면 혼자라도 계속 갑니다.”

- 소음 있음·혼자임 확인: avoid_market 선택은 맞지만, 이유는 가족 동행 여부가 ‘미확인’이라고 했다. 맞는 행동을 냈어도 사실을 잘못 읽었으므로 의미 통과로 세지 않았다.
- 소음 있음·동행자 미확인: continue를 선택했다. 미확인을 ‘회피할 필요 없음’으로 연결해 행동을 확정했다. 이 입력의 고정된 rubric은 판단 유보다.
- 원문 인용을 요약해 바꾸거나 개인 해석 요약을 보호자 원문 N1처럼 제시하는 오류가 두 건 있었다. 인용 무결성 문제와 행동 의미 문제를 따로 기록했다.

검사 코드는 ‘잘못 인용했다’는 사실을 탐지하지만, 잘못 고른 행동을 옳게 만들어 주지는 않는다. 또한 모르는 상황에서의 유보는 이 연구 평가의 불확실성 표현이며 실제 환자가 멈춘다는 예측이 아니다.

## 수정까지 준비한 부분과 미검증 부분

입력 요약의 ‘동행자 관측: 없음’은 관측이 없다는 의미로 오해할 수 있었다. 새 후보 파일 `next_action_followup.py`에는 ‘동행자가 없다고 확인됨 / 있다고 확인됨 / 있는지 미확인’을 분리했다. 원본의 Boolean/null은 그대로 보존한다. 이 표시의 모호함이 모든 오류의 원인이라고 단정하지 않는다.

원문 인용은 모델에게 재작성시키지 않고, 모델이 선택한 근거 ID로 서버가 원본을 그대로 연결하는 후보도 준비했다. 이는 인용 복사 작업을 분리하는 구현이며, 개인 조건 판단을 단어 규칙으로 대신하는 작업이 아니다. **이 새 후보는 로컬 검사만 통과했고 실호출하지 않았다. 기존 7/8 결과를 새 후보의 결과로 재사용하지 않는다.**

현재까지 로컬 테스트 16개 통과. 원본 보존, unknown/false 구분, 인용 변조 검출, 원본 근거 연결, 잘못 고른 행동을 자동 교정하지 않는 것을 검사했다. KINTEX 신규 모델 보행 검증은 이번에 하지 않았다. 기존 KINTEX 캐시를 유지했고, 개발 기준 미달로 새 모델 응답을 경로 성공 사례로 제시하지 않았다.

## API 설정과 응답시간

사용자가 제공한 K-EXAONE API 가이드와 대조했을 때 `chat_template_kwargs.enable_thinking` 및 `parse_reasoning` 전달 위치는 가이드와 일치했다. `response_format.json_schema.schema` 구조도 [FriendliAI 공식 API 문서](https://friendli.ai/docs/openapi/dedicated/inference/chat-completions)에 해당한다. 이 대조만으로 제공자 내부 실행의 모든 원인을 확인한 것은 아니다.

이번 8회에서 다음 명령 후보의 API 응답시간 중앙값은 Thinking 끔 1.28초, 켬 26.03초였고 켬의 최댓값은 41.05초였다. 서비스 전체 지연이나 동시 접속 성능이 아니다. 마음모델 호출 예산과 응답 재사용의 타당성은 별도로 검증해야 한다.

## 사용량과 중단 기준

- K-EXAONE **40회**, 입력 **69,224토큰**, 출력 **30,548토큰**.
- 최종 content 없음 0건, 출력 한도 종료 0건. 형식·의미 실패도 사용량에 포함. 동일 요청 자동 재시도 없음.
- 신규 GPU 학습·GPU 모델·Mi:dm·RAG 검색/임베딩·지도 호출 0회. 기존 서비스 중단 없음.
- API 단가·청구액·지원 차수 미확인(null). 공용 원장에 40개 시작/종료 쌍 확인.
- 승인된 개발 40회를 사용했다. 사전 기준 8/8을 통과하지 못해 별도 평가 32회를 사용하지 않았다. 평가용 예산을 개발 재실험에 전용하지 않았다.

## 도입 판단

**다음 행동을 명확히 분리한 입력 + K-EXAONE Thinking은 계속 검증할 근거가 생겼다. 배포 확정 근거는 아직 아니다.** 남은 핵심은 동행 여부 미확인을 임의로 해소하는 의미 오류다. 원문 연결과 명확한 관측 표시를 준비했지만 새 후보의 행동 성능과 반복 안정성을 실호출로 확인해야 한다. 실제 앞단 저장 K 출력 8개를 연결한 평가 16개도 아직 미실행 상태로 유지했다.

보존 자료: `comparison.json`, `response_comparison.jsonl`, `best_candidate_semantic_review.json`, `usage_summary.json`, `data_audit.json`. 원래 응답·요청은 `round1/calls`, `round2/calls`에 있다. 운영 코드 기본 경로와 모델은 바꾸지 않았다.
