# 학습·평가 데이터 확대 및 증강 계획 — 2026-09-30

사용자 추가 지시: 재학습 자료를 늘려도 되며, 16개 수준의 결과로 도입 당위성을 주장하기에는 부족하므로 증강을 포함해 규모를 확대한다. 이 문서는 앞선 계획의 최종 판정 범위를 강화한다. 진행 중인16개 비교의 입력·정답은 변경하지 않는다.

## 기존 자료의 실제 크기

현재 개발16개는 기존2개 인물 계열의8개 상황과 새8개 계열의8개 상황, 총10개 합성 인물 계열이다. 같은 환자16명 자료가 아니다. 별도로 남긴32개도 표현 변형·시간 변형이 섞여 있으므로 독립 환자32명 자료가 아니다. 실제 환자 수는0명이고 임상 전문가 검토도 아직 없다.

16개는 오류 진단·후보 선별용 소규모 검사로 한정한다. 앞선 계획의 별도32개×2회도 중간 일반화 검사로 사용하며, 이것만으로 최종 도입 정당성을 선언하지 않는다. 현재 합격 기준을 낮추거나 실패 사례를 빼지 않는다.

## 확대 목표

| 구분 | 초기 구성 목표 | 의미 |
|---|---|---|
| 학습 원자료 | 합성 서사 계열80개 × 상황8개 =640개 | 특성·조건·우선순위 조합의 범위 확대 |
| 학습 표현 증강 | 각 원자료에2개 추가 표현 =1,280개 추가 | 같은 의미를 다른 보호자 표현으로 전달 |
| 학습 합계 |1,920개 | 독립 인물/근거1,920개라는 뜻이 아님 |
| 개발 | 학습과 다른 계열20개 × 상황8개 =160개 | 후보·체크포인트 선택 |
| 최종 합성 평가 | 학습·개발과 다른 계열40개 × 상황8개 =320개 | 후보 확정 후1회 평가, 안정성은 별도 반복 |
| 스트레스 검사 |80개 | 정보 부족·모순·오래된 관측·형식 손상·허위 인용 |

숫자는 데이터 작성·검사 전에 정한 구축 목표다. 아직 완성하거나 학습한 수치가 아니다. 실제 행동자료의 부족을 합성 수량으로 해결했다고 표현하지 않는다. 의미가 사실상 같은 계열을 여러 인물로 세지 않고 원형/계열 수를 함께 공개한다.

## 무엇을 늘리는가

1. 인물 특성: 피로 시 휴식/목표 유지, 익숙한 장소와 현재 목적지의 구분, 기다림/휴식, 길 잃음 인식, 가족 동행 예외, 낯선 사람과 가족의 차이, 소음/혼잡 반응, 일과와 과거 직업의 구분.
2. 상황 대비: 같은 사람에서 한 조건만 바꾸어 행동이 바뀌는지, 같은 상황에서 개인 특성만 반대로 바꾸어 다른 행동을 선택하는지.
3. 복합 조건: AND/OR, 예외, 우선순위, 충분 조건과 필요 조건, 두 조건이 충돌할 때의 원문상 우선순위. 원문이 정하지 않은 우선순위는 정답을 강제하지 않는다.
4. 정보의 성격: 보호자의 질문·부탁·추측·직접 관찰·정정, 과거와 현재, 동행 미확인과 혼자 확인, 휴식 종료와 회복 확인.
5. 표현: 대화체·부정형·우회 표현·주어 생략·오타·여러 대화 턴. 의미와 출처가 보존된 것만 같은 정답을 사용한다. 표현 변경으로 의미가 달라지면 증강이 아니라 새 사례로 검토한다.
6. 연속 상황: 오전→피로 증가→휴식→재개, 동행 관측 변경, 환경 관측 만료. 독립 스냅샷과 실제 연속 경로 실험은 구분한다.

심리·행동 가설의 배경에는 기존 논문/RAG의 실제 출처를 연결한다. 집단 연구의 경향을 특정 개인의 확정 정답으로 만들지 않는다. 논문에서 개인 반응을 확정할 수 없으면 ‘연구 배경’과 ‘합성 보호자 설정’을 분리한다. 인용은 실제 확인한 자료만 사용한다.

## 데이터 생성과 정답 검토

먼저 합성 인물의 원문·현재 관측·원문으로 확정 가능한 행동 범위를 작성하고 그후 표현을 다양화한다. 모델의 응답을 곧바로 정답으로 삼지 않는다. 정답의 행동·목표 처리·회피 대상·이유·출처가 서로 맞는지 검사한다. 양·음성 대비와 미확인 사례를 함께 작성한다.

프로그램은 데이터 제작 시 구조화한 시나리오의 일관성과 상태 조합을 검사할 수 있다. 실제 서비스에서 보호자 단어를 찾아 행동을 고정하는 규칙은 만들지 않는다. 모델에게는 보호자 원문·저장 해석·현재 상태를 전달하고 작성용 정답/규칙은 숨긴다.

원자료→표현 증강→정답은 lineage_id로 연결한다. 원문이 같거나 단순 치환 관계인 자료를 다른 독립 계열로 세지 않는다. 모델 자기 검토와 Codex 검토를 사람·임상 평가라고 쓰지 않는다. 자동 검사 통과와 의미 검토 완료도 구분한다.

## 누수 방지

행 단위 무작위 분할을 하지 않는다. 인물/서사 원형과 모든 표현·시간·상태 변형을 같은 분할에 둔다. 학습·개발·평가 사이에 원문, 원형, 출처 사례, 표현 변형이 섞이지 않도록 그룹 분리한다. 실제 앞단K 출력 평가 자료와 최종 평가 자료는 학습에 넣지 않는다. 최종 평가로 후보를 수정했다면 그 자료는 이후 회귀 자료로 바꾸고 새 평가 세트를 만든다.

학습은 쉬운 continue 응답에 치우치지 않도록 행동별·조건별 분포를 공개한다. 증강 전 원자료 성능과 표현 증강 성능을 따로 본다. 증강 수만 늘려 같은 패턴을 외운 성과로 끝내지 않는다.

## 확대 평가에서 볼 것

- 사례별 행동·근거·관측 보존, 근거 없는 목적지와 불필요한 유보.
- 인물 계열별 성공률과 최저 성능 계열; 명령 종류별·복합 조건별 성능.
- 같은 상황의 개인 특성 대비, 같은 의미의 표현 변화, 시간/환경/피로 변화.
- 중대 오류(관측 반전·조건 예외 누락·행동/설명 충돌)의 수와 종류.
- 기존 기준선과 같은 자료·조건·호출 설정의 짝 비교. 반복 응답은 안정성 표로 분리.
- 불확실성 구간은 반복 행을 독립 표본처럼 계산하지 않고 인물/서사 계열 단위로 재표집하는 방법을 사용. 실제 환자 성능 구간이라고 부르지 않음.

확대 최종 평가 전에 허용 오차와 중대 오류 기준을 다시 사전 고정한다. 점수를 본 뒤 유리하게 기준을 정하지 않는다. 원래 개발 게이트의 중대 오류0 원칙은 유지한다. 합성 평가 후에도 현장 검토와 실제/비식별 종료 사례 검증이 있어야 임상적·운영상 주장을 강화할 수 있다.

## 진행 순서

진행 중인 작은비교를 완료 → 구조적 오류 수정 → 확대 원자료/정답/분할 구축·검사 → 선택된 계약으로 EXAONE LoRA 재학습 필요성 비교 → 개발/확대 평가 → 통과한 실제 응답의 KINTEX 반영·시간·예산 검사.

GPU학습을 시작하기 전에 데이터 파일·해시·행동 분포·분할·토큰 길이·서버 가용성과 실제 실행 상한을 기록한다. 현재K API128회 묶음에 이 대규모 학습/평가를 몰래 포함하지 않는다. 사용자의 반복 개선·증강·실행 승인 불필요 지시에 따라 각 묶음의 범위를 기록하며 진행한다.
