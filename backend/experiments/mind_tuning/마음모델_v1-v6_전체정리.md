## 0. 배경 — 무엇을, 왜 만들었나

「돌아오길」은 치매 실종자의 이동을 시뮬레이션해 수색 범위를 좁히는
앱이다. 시뮬레이션 속 디지털 트윈의 게이지(귀소 충동·불안)가 임계를 넘으면
**마음 재해석**이 발동한다 — LLM(EXAONE-3.5-7.8B, 자가호스팅)이 실종자
1인칭이 되어 JSON 으로 답한다:

- `inner` 속마음(서사) · `status` 몸 상태
- `behavior` 행동 의도 — 닫힌 4종: 끌림점 접근/귀소 시도/은신·멈춤/계속 배회
- `goal_label` 목적지(등록 후보 중에서만, 없으면 null)
- `confusion_level` 혼란도(하/중/상) — 수색 전략 가중치로 들어가는 제어 신호

이 출력을 좋게 만들기 위해 LoRA 튜닝을 6판 시도했고, 채택은 전부 사전에
정한 시험(게이트)으로만 판정했다.

## 0-1. 채점 방법 (전 버전 공통)

- **골드셋**: 보호자 인터뷰 대본 시나리오 20종. 판정자 3인 2/3 합의로 정답
  범위(허용/금지 목적지, 허용 행동, 혼란도 범위) 작성.
  dev 8종(개발용) / test 12종(봉인 — 최종 1회만).
- **측정**: 시나리오 × 상황 2종(귀소/불안 발동) × 4회 표집. dev=64콜.
- **게이트(사전 등록)**: 행동 적중 94% 수준 + 혼란도 적합 90%+ +
  형식 무결(JSON 깨짐·어휘 밖 0) + 치명 0(금지 목적지 확신 지목).
- **기준선(튜닝 없는 base 모델)**: 행동 80% · 혼란도 83% · 치명 0.

## 0-2. 학습 데이터 공통 파이프라인

실데이터가 없으므로 문헌 지식을 시나리오로 합성했다. 모든 버전이 이 뼈대를
공유하고, 버전 간 차이는 주로 **혼란도 정답을 만드는 규칙**이다.

1. **원천**: 실종 행동 논문 34편 → 원문 인용 대조로 검증된 행동 진술(claim)
   **63개** (`claims/claims.jsonl`). ※ 아래 스코프 고지 참고 — 현재 파일은 치매 33건.
2. **시나리오 변형(이것이 기본 증강)**: 각 claim 을 근거 유형(archetype)
   6종으로 변형 — 발견이력 확정 / 보호자 반복관찰 / 집단경향만 / 개인부정
   충돌 / 후보밖 의도 / 균형 2후보. 뒤 4종은 "논문 일반론이 보호자의 개인
   진술을 이기면 안 된다"(개인 근거 우선)를 가르치는 음성 사례다.
   여기에 변형 인덱스(목적지형 claim 16개·비목적지형 5개)마다 이름·나이
   풀 8종, 장소 풀 7버킷×8종, 게이지 상황(경과시간 9종×수준 조합, 골드셋
   표준 조합은 누수 차단 위해 제외), 장면 24종, 행동별 문장 풀(배회 12·
   은신 10·귀소 6·목표 16)을 결정론 시드로 조합한다.
3. **입력 생성**: 자체 템플릿이 아니라 **운영 코드의 실제 프롬프트 빌더**
   호출 — 학습 형식 = 서빙 형식.
4. **정답 생성**: 행동을 먼저 확정하고 문장을 행동별 풀에서 유도(모순이
   구조적으로 불가능). goal 정답 16 : null 5 재균형(과수동 방지), 템플릿
   최빈 반복 5회 이하, 골드셋 장소명과 교집합 0 검증.
5. **규모·분할**: train 2,232 / val 446 (v6만 train 2,594 — 오버샘플).
   검증은 별도 논문 4종(DEM-32·33, DEV-04·17)만으로 구성해 논문 단위 누수
   차단. 문장 표면형 패러프레이즈는 의도적으로 미사용(효과 분리를 위해
   결정론 원본으로 베이스라인).

## 0-3. 학습 설정 공통 (전 버전 동일한 부분)

- base: `LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct`, 서빙 vLLM 과 동일 체크포인트
  + code-revision 고정 (다르면 어댑터가 안 맞는다)
- LoRA r16, alpha 32, dropout 0.05, 대상 7모듈(q/k/v/o/gate/up/down)
  — 학습 파라미터 9.4M (전체의 0.12%)
- loss 는 assistant 답변 토큰에만(프롬프트 구간 -100 마스킹), 공식 chat
  template, bf16 + gradient checkpointing, cosine 스케줄 + warmup 3%,
  배치 2 × 누적 8 = 유효 16, max_len 1536, 2 epoch
- 환경: 공유 A100 80G. 학습 중 vLLM 을 0.5로 내려 공존(0.85면 OOM 실측),
  1판 약 20분. 어댑터는 `~/sar-ft/exaone-mind-lora-v{n}` 로 전부 보존.

# 버전별 상세

## v1 — 게이지 반향 라벨 (행동은 성공, 혼란도는 무정보)

**데이터** (생성기 v4.2): 위 공통 파이프라인 그대로. 혼란도 정답 =
**입력 게이지 보고에 적힌 혼란도를 그대로 복사**. train 2,232 / val 446.

**학습**: 공통 설정 + lr 1e-4. (NEFTune 없음)

**결과 (dev 64콜)**:

| 행동 | 혼란도 | goal | 치명 | 형식 |
|---|---|---|---|---|
| **94%** (기준선 80%) | 88% — 단 "중" 63/64 | 97% | 0 | 무결 |

행동 학습은 대성공 — 특히 불안 상황의 귀소 편향 미스가 13→3건. 그러나
혼란도 88%의 정체는 dev 게이지가 항상 "중간"이라 배운 대로 되돌려준 것.

**배운 것**: 게이지 값을 메아리치는 LLM 은 정보를 추가하지 않는다. 점수가
높아도 무의미 — 정답 라벨 설계 자체를 바꿔야 한다.

## v2 — 혼란 라벨 재설계 + 같은 레시피 (형식 붕괴)

**데이터** (혼란 규칙만 교체): 혼란도 정답을 행동류·근거 상황 기반 **확률
표집**으로 — 길잃음류 60% 상 / 강근거 익숙행동 60% 하 / 근거빈약 60% 중,
게이지는 극단값 모순 차단(높음→하 금지, 낮음→상 금지)으로 강등.
결과 분포 하 12% / 중 63% / 상 25%. 나머지 데이터·규모 v1과 동일.

**학습**: v1과 동일 (lr 1e-4).

**결과 (dev 64콜)**:

| 행동 | 혼란도 | goal | 치명 | 형식 |
|---|---|---|---|---|
| 84% | **70%** | 94% | 0 | **파싱 실패 9/64 + 어휘 밖 1** |

따옴표 없는 유사 JSON, 필드 뒤섞임, 학습 템플릿 문장을 그대로 재생하는
암기 흔적(final loss 0.082 — 과하게 낮음).

**배운 것**: 새 라벨 분포가 학습을 불안정화했고 학습률이 과했다. LoRA 는
내용만이 아니라 형식 안정성도 깨뜨릴 수 있다(외부 리뷰의 경고가 실측됨).

## v3 — 같은 데이터 + 안정화 레시피 (형식 회복, 원인 특정)

**데이터**: v2와 완전 동일 (변인 통제 — 레시피 효과만 분리).

**학습**: lr **5e-5**(절반) + **NEFTune 5**(임베딩 노이즈 주입 — 암기 억제).
final loss 0.148 (v2 0.082 대비 높음 = 비암기의 증거). 이후 모든 판이
이 레시피를 유지한다.

**결과 (dev 64콜)**:

| 행동 | 혼란도 | goal | 치명 | 형식 |
|---|---|---|---|---|
| 92% | 81% (하1/중51/상12) | 97% | 0 | 회복 (유효 64/64) |

혼란 미스 12건 중 11건이 A_귀소 상황의 세 시나리오(초기 치매 G03 4건,
경증 발달 G07 4건, 정보빈약 G08 3건)에 집중.

**배운 것**: 안정 학습법 확보. 그리고 결정적 발견 — 미스 지점의 입력엔
"작년 진단·대화 원활·혼자 다님" 같은 경증 신호가 가득한데, **학습 데이터
생성기에 경증/중증 어휘가 0회**. 모델이 배운 적 없는 구분은 못 한다.

### (v3 직후 병행) 8셀 전수 비교 — RAG 유무 × 모델 4종

같은 dev 로 base/sar/mind-v1/mind-v3 × RAG on/off 전 조합 측정. 확정 3:
(1) RAG 의 혼란도 개선(88%)은 전 콜 "중" 퇴화가 만든 가짜, (2) 어댑터+RAG
= 형식 파괴(behavior 누락 최대 30/64 — RAG 없는 입력으로 학습된 분포 이탈),
(3) 어떤 조합도 LLM 혼란도는 무정보. → **마음 경로 RAG 제외 확정.**

## v4 — 기능 수준 축 추가 (표적은 맞았으나 과잉 일반화)

**데이터** (생성기 v5): v3 진단의 처방.

- **입력 증강**: 시나리오마다 기능 수준을 경증/미상/중증 = 3:4:3 로 표집,
  경증·중증이면 보호자 진술 문장을 노트 맨 앞에 삽입. 문장은 암기 방지를
  위해 조각 조합식(진단 시기 3종 × 의사소통 3종 × 이동능력 3종, 대상군별
  별도 풀 = 셀당 27조합). 미상은 문장 없음 — 신호 부재도 학습 대상.
- **라벨 규칙**: v2 확률 표집에 기능 수준 보정 추가 — 경증이면 한 단계
  명료 쪽(단 정보빈약 archetype 에서는 차단), 중증이면 한 단계 혼란 쪽.
  "빈약→상 40%"는 25%로 완화(G08 과잉 실측 반영).
- 분포: 하 16% / 중 56% / 상 28%. 경증 행 = 하 40%, 중증 행 = 상 56%.

**학습**: v3 레시피 그대로.

**결과 (dev 64콜)**:

| 행동 | 혼란도 | goal | 치명 | 형식 |
|---|---|---|---|---|
| 94% | **73%** (하6/중21/상37) | 95% | 0 | **behavior 누락 12/64** |

표적이던 G03 은 미스 4→2로 절반 회복, "하" 출력도 살아남. 그러나 "중증→
상향"이 과잉 일반화돼 멀쩡하던 G06(중등도, 기대 ≤0.8)이 0→4/4 붕괴(전부
0.85), G08 은 반대로 0.35 언더슈트. 새 문장 축 탓에 형식도 재퇴행.

**배운 것**: 확률 표집 라벨에서는 규칙을 고칠 때마다 미스가 사라지지 않고
자리를 옮긴다. 판정자의 혼란 기대는 시나리오별 미묘한 추론이다.

### (전환점) 규칙만으로 혼란도 산정 — dev 16/16

발상 전환: 판정자 3인이 범위에 합의했다 = 그 판단은 말로 설명되는 소수
요인으로 움직인다. LLM 없이 **파라미터 5개 결정론 규칙**(`rule_confusion.py`
— 손상·명료 신호 어휘 차이, 정보빈약 분기, 불안 상황 +0.15, 기준값 3단)을
보호자 진술에 적용 → **dev 16상황 전부 적합(100%)**. LLM 12개 구성 최고치
88%(무정보)를 상회.

## v5 — 규칙 증류 (행동·goal 역대 최고 → 최종 채택 어댑터)

**데이터** (생성기 v6): 마지막 진단 — v1~v4 라벨은 확률 표집이라 **같은
조건에 다른 정답**이 붙어 있었다(라벨 노이즈). 모델이 안전한 "중"으로
도망친 건 합리적 학습이었다. 처방:

- 혼란도 정답을 검증된 규칙의 **결정론 교사**로 교체 — 입력에서 보이는
  신호의 순수 함수: 경증×비빈약×귀소 = 하 / 중증×불안 = 상 / 그 외 = 중
  (+게이지 극단 모순 차단). 같은 입력이면 항상 같은 정답 = 노이즈 0.
- 기능 수준 문장 증강(v4의 입력 축)은 유지. 분포: 하 8% / 중 80% / 상 12%.

**학습**: v3 레시피 그대로.

**결과 (dev 64콜)**:

| 행동 | 혼란도 | goal | 치명 | 형식 |
|---|---|---|---|---|
| **95% (역대 최고)** | 86% (하0/중59/상3) | **100%** | 0 | 누락 2 |

행동·goal·형식·상 과열까지 전부 역대 최선. 남은 실패는 단 하나 — 전체의
8%뿐인 "하" 라벨을 "중"으로 흡수해 한 번도 출력하지 않았다(미스 9건 중
8건이 정확히 그 지점).

**배운 것**: 라벨 노이즈 제거는 유효했다. 남은 건 소수 클래스 흡수 —
유일하게 교과서 처방(오버샘플링)이 존재하는 실패.

## v6 — "하" 3배 오버샘플 (최종판 — 결과 무관 튜닝 종료 선언 후 실행)

**데이터** (생성기 v7): v5 데이터에서 **"하" 라벨 train 행만 3배 복제**
(181→543행, 8%→21%; 복제본은 id 접미사 -O1/-O2, val 은 무증량 — 감시 지표
왜곡 방지). train 2,594 / val 446.

**학습**: v3 레시피 그대로.

**결과 (dev 64콜)**:

| 행동 | 혼란도 | goal | 치명 | 형식 |
|---|---|---|---|---|
| 91% | **73%** (하16/중31/상17) | 94% | 0 | 누락 0 |

"하"가 나오기 시작했고 표적 하나(G07)는 4/4 완벽 회복. 그러나 중증(G01·
G06)·정보빈약(G08)에 "하"를 오발(9건)했고, 같은 경증인 G03 은 여전히 "중".

**배운 것 (6판의 최종 결론)**: 7.8B 는 소수 라벨을 "내는 것"은 배워도
"언제 내는가"의 판별 정밀도가 없다. 궤적 88→70→81→73→86→73 — LLM 단일
혼란도는 이 규모에서 불가. 규칙은 같은 판별을 16/16 으로 한다.

## 후처리 — 형식 결함의 근본 수정 (v5 재검증)

v5의 누락 2건 원인 판독: 능력이 아니라 디코딩 사고 — inner 중간 개행 후
유사 JSON 붕괴 1건(내용은 정답이었음), "집에 가고 싶다" 반복 루프 1건.
처방: vLLM guided decoding 으로 **JSON 구조·필수 필드만** 강제 + 반복
페널티 1.05. 재검증 결과 **누락 0·어휘 밖 0, 혼란도 86% 유지, goal 100%,
행동 적중 동급** — 성능 무손실로 형식 항목 완전 충족.

함정 실측 하나: 한글 어휘(enum)까지 문법으로 강제하면 문법 엔진(xgrammar)이
한글을 UTF-8 바이트 단위로 컴파일해 모델이 학습한 토큰을 못 쓰게 되고 출력
분포가 붕괴한다(은신·멈춤 2→57 왜곡). **"구조는 강제, 어휘는 모델"**이 정답.

# 최종 선정

## 확정 구성

**mind-v5 어댑터 × RAG 제외 × 구조 강제 guided decoding + 혼란도 수치 = 규칙 산정**

## 선정 이유 (전부 실측 근거)

1. **어댑터는 왜 v5인가** — 행동 95%·goal 100% 로 전 판 최고이고, 라벨
   노이즈가 없는 유일한 판. 경쟁 후보 v1(행동 94·형식 무결)의 유일한 우위
   (형식)는 guided 처방으로 소멸했다. v6는 혼란도를 개선하지 못한 채
   행동·goal 을 깎았다.
2. **혼란도는 왜 규칙인가** — 6판 전패가 결론: LLM 최고 88%조차 "전부 중"
   전략의 산물(무정보)이고, 규칙은 dev 100%. 게다가 혼란도는 수색 전략에
   들어가는 제어 신호라 결정론(감사·재현 가능)이 성질에 맞는다. LLM 의
   confusion_level 출력은 서사 정합용으로만 두고 하류는 규칙값을 쓴다.
3. **RAG 는 왜 빼는가** — 8셀 전수에서 이득 0, 해 2종(가짜 점수 개선·형식
   파괴) 실측.
4. **guided 는 왜 켜는가** — 형식 실패를 확률이 아니라 문법 차원에서 0으로.

## 봉인 test 최종 성적 (G09~G20, 96콜, 1회 실행·사후 수정 없음 — 대외 인용 기준)

| 항목 | 결과 | 의미 |
|---|---|---|
| 치명(금지 목적지) | **0/96** | 수색을 엉뚱한 곳으로 보내는 실패 없음 |
| 서사 오염 | **0** | 발달 시나리오에 치매 서사 지어냄 없음 |
| 형식 결함 | **0** | guided 처방 일반화 확인 |
| goal 적중 | 96% | 견고 |
| 행동 적중 | 83% | dev(95%) 대비 하락이 정상 — dev 는 보며 개선한 값이라 거품이 있었고 이것이 진짜 일반화 수치. 미스 대부분은 "틀림"이 아닌 "중립" |
| 혼란도 | 규칙 88% / LLM 92% | 오차 수준 차이, 둘 다 중 우세. 규칙 이탈 3건은 어휘 매칭 한계 — 운영(등록 챗봇 구조화 필드)에서는 사라지는 부분 |

읽는 법: 이 시스템의 핵심 주장은 높은 적중률이 아니라 **"위험한 실수를
하지 않으면서 개인 근거를 우선한다"**이고, 그것이 봉인셋에서 무결점으로
증명됐다.

## 한계 (정직 고지)

- 홀드아웃은 생성 관여자가 작성한 **제한적** 홀드아웃(실행만 봉인).
  진짜 봉인은 비관여자 작성 신규 시나리오 — 후속 옵션.
- 입력·정답 모두 합성 데이터 — **실제 실종자 행동 확률분포의 재현을
  주장하지 않는다** (제안서 표기 원칙).
- 봉인 test 는 소진됨(재실행 금지, `results/test_usage.log` 기록).
- 남은 실행: 팀 공유 → 운영 통합 PR(1인칭 v2 전환·v5 라우팅·guided 활성·
  규칙을 등록 챗봇 구조화 필드에 연결) → 제안서 test 수치 반영.
