# 마음모델 계약 후보 A/B 비교 계획 (2026-10-07, 실행 전 고정)

## 왜 하나

2026-10-06 확대 비교(후보 `condition-program-v4-research`)는 두 설정 모두 기준에 미달했습니다. 저장 응답 128개를 오프라인으로 다시 분류한 결과([saved_failure_taxonomy.json](results/saved_failure_taxonomy.json))는 다음과 같습니다.

| 실패 종류 | Thinking 켬 (응답 64개 중) | Thinking 끔 (응답 64개 중) |
|---|---:|---:|
| 출력 미완료 (`finish_reason=length`) | 15 | 0 |
| 출력 경계 (완전한 JSON 하나가 아님) | 6 | 2 |
| 규칙 누락 (근거 문답에 실행 규칙 없음) | 1 | 31 |
| 목적지 결합 (목표 장소를 적용 범위로 씀) | 2 | 1 |
| 해석 오류 (조건·행동 오류, 계약 거절) | 6 | 3 |
| 엔진 소비 (정책은 맞는데 보행 검사 실패) | 0 | 0 |

한 응답에 여러 종류가 겹칠 수 있습니다. 분류는 수기 참조 정책과의 형식 비교이며 임상적 정답이 아닙니다.

목적지 결합은 두 형태였습니다. P14는 `walk`에 `place_labels=[느티공원]`을 넣었습니다(공원 근처에서 걷기). P15·P32는 `seek`의 목표를 `place_labels`에도 넣었습니다(이미 그 장소에 있을 때만 출발). 보행 엔진은 `seek`의 `goal_label`만 목표로 쓰고, `place_labels`는 반응 적용 범위로만 씁니다.

## 비교할 후보

두 후보 모두 사람당 K-EXAONE 1회 호출, 전체 문답 입력, 기존 화이트리스트 조건식 컴파일러(`condition_program.expression`), 기존 `mind_policy.Policy`를 씁니다. 보호자 문장에서 단어로 행동을 뽑지 않고, 엔진이 받지 않는 필드를 만들지 않습니다.

| 후보 | 출력 | 코드가 거절하는 것 |
|---|---|---|
| A 최소 계약 수정 | v4와 같은 `rules` + `non_action_note_ids`. 명령을 `action` / `goal_place` / `applies_only_at`로 분리하고 행동 의미를 명시 | seek인데 목표 없음, seek가 아닌데 목표 있음, 목표를 범위에도 씀 |
| B 근거 단위 해석 | 문답의 의미 단위마다 `subject`·`kind`·`action`·`start_condition`·`end_condition`·인용 | A의 거절 + 본인 반응으로 판정했는데 행동 없음(누락), 타인·미관찰·능력에 행동 부여, 원문에 없는 인용 |

공통 변경: 과거 사건을 현재 의도로 쓰지 말라는 기존 문장을 "과거에 관찰된 조건부 반응은 같은 조건이 다시 성립할 때의 규칙으로 보존한다. 과거 사건을 지금 조건이 성립한다는 증거나 현재 목적지 의도로 쓰지 않는다"로 바꿨습니다. 이 문장이 누락의 원인이라는 것은 **가설**이며 이번 비교로 단독 효과를 분리하지 않습니다.

B의 `(start) and not (end)` 변환은 종료 조건을 상태로 다룹니다. 보행 엔진이 매 분 조건을 다시 평가하므로 종료 조건이 참이 되는 즉시 대기가 끝납니다.

- 대상: P05·P14·P21·P25·P29(인계 문서의 대표 실패) + P06(능력만)·P13(발언만)·P24(부정·타인) 과잉 생성 반례. 모두 10/06에 결과를 본 개발 자료입니다.

- 채점: 10/06 고정 채점 기준(상태·명령·가능 명령 집합 일치). 출력 실패는 그 응답의 4장면 모두 실패. 후보당 64판정.
- 같은 8명에 대한 v4 기준선(저장 결과): 켬 39/64, 끔 48/64.
- **선택 규칙:** 판정 통과 수가 많은 후보 → 동률이면 치명 오류 수가 적은 쪽 → 완성 JSON 수가 많은 쪽 → A.
