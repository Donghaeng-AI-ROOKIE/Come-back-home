# D9: 원문 해석과 실행 규칙 변환 분리

D6의 48/64, D7의42/64, D8 스키마 조건의35/64 장면 일치로는 채택할 수 없다. 이전에 맞았던 응답의 재검토도 퇴행했고, 형식을 단순화해도 의미 오류가 남았다. D8의 제약 없는 출력 비교는 별도로 끝까지 보존한다.

새 가설은 원문에서 사람의 반응을 이해하는 작업과 실행 가능한 사실 이름·조건으로 옮기는 작업을 분리하면 조건 누락이 줄어드는가이다. 첫 단계는 관찰 행동·시작·종료·장소·수량·불명확함을 한국어 카드로 정리한다. 두 번째는 원문 전체와 그 카드를 함께 받아 기존 D8 계약으로 변환한다. 첫 해석은 형식 제약 없는 JSON, 실행 변환은 D8과 같은 API 스키마 제약을 사용한다. 제약 없는 D8plain 중간 결과에서 다중 객체·잘못된 타입도 관찰되어, 의미 분리 효과와 형식 검증을 분리한다. 카드는 모델 산출물로 표시하며 새로운 사실이나 전문가 검토로 취급하지 않는다. 두 단계 모두 정답·검사장면·참조 정책은 받지 않는다.

- 동일 개발 실패 입력8개×2반복,16응답. 환자16명이나 독립 평가가 아니다.
- 해석16회, 변환16회, 형식 검증 실패 수정 최대16회, 합계48회.
- 해석 출력8192토큰, 변환·수정16384토큰. 합계 출력 상한655360토큰. 각 입력40000바이트, 동시2개 작업.
- 통신 오류의 자동 재시도 없음. 원문이나 응답이 한도를 넘으면 자르거나 성공 처리하지 않는다.
- 해석 누락이나 인용 불일치도 실패로 분모에 남긴다. 보행에서 실행 못한 특성도 분모에서 빼지 않는다.
- 기존64장면·조건 반례·KINTEX 도로150명×3장면의 참조 비교. P08 참조 이견을 별도 유지한다.
- 사용자10월8일 지속 개선 승인으로 실행. 비용·단가·지원 차수는 미확인으로 기록.
- 운영·배포 수정, 신규 지도, 재학습 없음. 개발 결과 뒤 별도 반복·실제 앱 입력 검증을 해야 한다.

핵심 판정은 개선 여부다. 형식 통과만으로 채택하지 않으며 원문과 모순되는 행동, 누락, 보행에서 효과가 사라짐을 따로 판정한다. 이 소규모 개발 검사에서 좋은 점수가 나와도 임상적 정확도나 실제 실종 위치 정확도로 주장하지 않는다.
