# D10/D11: 비추론 출력 계약 비교

짧은 문답 진단에서 Thinking 끔+자유 출력은3/8, Thinking 끔+동일 영어 JSON 스키마는7/8이었다. 서로 다른 시간의 작은 개발 비교로 확정 개선율이 아니다. 구조화한 출력이 조건 오탈자를 줄이는지, 장문 Thinking 없이 조건 의미를 보존할 수 있는지 복합 입력에서 확인한다.

- D10: D4의 기존 계약·컴파일러. D11: D8의 간결한 계약·시간대 필드·컴파일러. 둘 다 Thinking 끔, JSON 스키마 켬.
- 두 후보 모두 temperature1.0/top_p0.95/presence_penalty0/repetition_penalty1, 출력16,384토큰·입력40,000바이트 이하.
- 같은 고정 개발 실패8입력×2반복×2후보=첫 호출32회. 출력 검증 실패 시에만1회 수정, 총 최대64회. 실패 포함, 자동 전송 재시도 없음, 동시2회. 전체 출력 상한1,048,576토큰.
- 단가·실청구액·지원 차수 미확인. 공용 원장에 시작/종료·토큰·실패 기록. 10/8 사용자의 같은 목표 반복 개선 지속 승인에 근거한다.
- 새로운 RAG·지도·임베딩·Mi:dm·GPU 학습 호출 없음. 개발 원문·정답·평가기·엔진은 그대로 유지한다. 이전 결과를 덮어쓰지 않는다.
- 실패 응답도 분모에 남긴다. 조건 반례 및 동일 KINTEX 보행 비교까지 수행한다. OSM 도로만 실제이며 시설·환경 관측은 합성이다.
- P08의 계속 걷기와 기존 정답의 불일치는 별도 원문 보존 쟁점으로 유지한다. 작은 개발 결과를 임상·실종 위치 정확도로 부르지 않는다.
- 통과 기준은 기존 단계 기준을 유지한다. 충분한 결과가 나오기 전에는 새 평가 세트·운영 적용으로 자동 승격하지 않는다.
