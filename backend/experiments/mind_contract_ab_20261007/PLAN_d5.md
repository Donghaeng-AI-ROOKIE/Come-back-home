# 후보 D5 계획 (2026-10-07, 실행 전 고정)

## 최종 기준

형식 통과율(장면 점수, 유효 출력)과 함께 **온보딩된 사람의 특성이 실제 행동에 보존되는가**를 봅니다. 기존 시험 점수에 맞추려고 개인 특성을 표현 대상에서 빼지 않습니다. 근거: `results/d3_dev128_analysis/D5_설계_수정결정.md`(사용자 리뷰). 이 문서가 `D5_설계.md`보다 우선합니다.

## 정정

- D4 dev8 58/64는 "검사가 엄격해져 낮아졌다"고 설명할 근거가 없습니다. 저장된 D4 최종 응답은 D3·D4 검증기 모두에서 58/64입니다. 실패 원인은 "가족이 없을 때 대기"를 "있을 때"로 읽은 해석 오류(장면 2개)와 근거 문장 누락으로 인한 무효(장면 4개)입니다.
- "D5 예상 약 905/1024"와 "여러 번 물어야 한다"는 가설입니다. 측정 전에는 근거로 쓰지 않습니다.

## D5가 D4에서 바꾼 것 (`contract_d5.py`)

**거절하지 않는 것(수정 결정):** 걷는 중이 아닐 때 시작되는 rest, 상황만으로 시작하는 rest, 부재 조건(거짓 사실)만으로 시작하는 행동, 피로·통증·보행 한계에서 계속 걷는 walk. 행동 종류를 일괄 금지하는 검사는 없습니다. 거절은 D4 검사(퇴화·충족 불가능 분기, 걷는 중에만 성립하는 대기 등)와 모델 자신의 선언끼리의 모순(역할·정정·우선 근거), 논리적으로 실행되지 않는 우선 관계뿐입니다. 설계안의 `rest_without_is_walking`, `walk_without_event`, `situational_only_rest`, `rule_always_conflicts`는 진단으로만 셉니다.

**설계와 다른 점:** 정정 관계를 문장 역할 값 안이 아니라 별도 `corrections` 목록에 둡니다. 요청 크기를 줄이려는 선택입니다. 재개 점검에서 실제 요청 직렬화 방식으로 측정한 최대 첫 요청은 dev8 33,730바이트, dev128 39,591바이트였습니다. 수정 요청에는 이전 응답이 추가되므로 더 커집니다. 전송 코드가 40,000바이트 상한을 강제하지는 않습니다. 바이트 수를 토큰 수로 해석하지 않으며, 입력 토큰과 비용은 미확인으로 기록합니다.

## 모델 호출 없는 사전 확인 (2026-10-07, D3 dev128 저장 응답 재생)

- D3 최종 유효 응답 247개 가운데 D5가 새로 거절하는 응답은 9개이고, 전부 D4도 같은 이유로 거절합니다(충족 불가능 분기 8, 퇴화 분기 1). **D5만의 새 거절은 0개**입니다.
- 그중 전 장면 통과 응답은 2개입니다: `DEV_P02_original/2`, `DEV_P26_hard/2`(둘 다 `unsatisfiable_branch`, D4와 같음).
- D4와 D5가 모두 받는 238개 응답에서 컴파일 결과 규칙은 D4와 같습니다.
- 한계: D3에는 역할·정정·우선 필드가 없어 `from_d3()` 고정 변환으로 재생했습니다. D5-06~08 검사는 재생으로 측정되지 않습니다. D3가 문장 누락으로 거절한 응답을 변환이 채워 받는 경우는 변환 산물이며 D5 수용으로 세지 않습니다.
- 수정 결정이 지킨 것: D3 유효 응답 19개에 걷는 중이 아닐 때 시작되는 rest가 있었고, 그중 5개는 전 장면 통과입니다. 설계안 D5-01이었다면 거절 대상이었습니다.

## 보고 항목

1. 장면 점수(전체, 상태별, 계열별, 형태별), 첫 응답·최종 유효, 수정 수, 치명.
2. 오류 코드 집계: run_v2는 오류 문장과 첫 코드만 저장하므로, 저장 응답에 `contract_d5.errors()`를 다시 돌려 전체 코드 목록을 집계합니다.
3. 진단: 걷는 중이 아닐 때의 rest, 상황만의 rest, 부재 조건 분기, 신체 walk, 근거 없는 겹침(`rule_always_conflicts`), 중복 규칙, 효과 없는 우선, 정정 미인용, 조용한 붕괴, `correction_drift`(오류 위치 안/밖), 엔진 입력 동일 반복 수. `engine_input_key`는 규칙 순서를 보존합니다. 엔진이 목록 위치로 선택하므로 규칙 순서를 정렬해서 같다고 판정하면 동일 시드의 행동 차이를 놓칩니다.
4. 엔진 지원 3구분: (1) 원문 근거가 있고 계약·엔진이 표현, (2) 원문 근거가 있으나 엔진 의미가 불완전(정지 중 rest의 반복, 대기 시간 미실행), (3) 표현 불가(not_representable, 특성 손실).

## 기존 시험과 논쟁 사례

- dev128 정답(참조 정책·장면)은 바꾸지 않습니다. 진행 조건은 기존 점수만으로 판정하고, 보정 점수는 만들지 않습니다.
- 논쟁 사례는 따로 보고합니다. 목록(`DISPUTED_DEV128`, dev128 원문을 대조해 AI가 고정한 검토 후보; 사람 검토 완료 아님): `DEV_P08_original`, `DEV_P08_preserve`, `DEV_P08_counterfactual`, `DEV_P08_hard`, `DEV_P19_counterfactual`. 검토용 별도 1건: `DEV_P06_preserve`(관찰된 지속인지 능력 진술인지).
- 보고 형식: 입력, 원문 문장, D5 규칙, 기존 정답과 어긋난 장면과 그 판정. `disputed()`와 진단 `disputed_physical_walk`는 후보 표시일 뿐입니다. 예: D3 재생에서 `DEV_P08_hard/2`는 "통증일 때 걷기"를 만들었는데, 이는 논쟁이 아니라 오해석입니다. 사람이 원문과 대조해 가릅니다.
- 별도 자료 `dataset/disputed_v1`(이번 재개 작업에서 빌드)은 다음을 다룹니다: 피로 상황의 이동 지속과 정보 부족의 대비, 정지·대기 중 휴식, 부재 조건으로 시작되는 행동, 질문 전제 승계. 원문·기대 행동·엔진 지원 여부를 함께 적고, **사람 검토 전에는 근거로 쓰지 않습니다.**

## 다중 호출 결정

D5 단일 호출 dev128 결과를 본 뒤에 정합니다. 비교 항목은 같은 입력 2회 사이의 엔진 입력 동일 비율, 규칙 단위 불일치의 유형, 논쟁·감시 입력의 행동 보존입니다. 여러 응답이 같은 오해를 반복하면 다중 호출은 효과가 없으므로, 반복 간 불일치가 실제 특성 손실로 이어지는 경우에만 별도 예산 승인을 요청합니다. 수정문 A/B(D4 문구와 D5 국소 수정 문구)는 별도 실행기가 필요하며 아직 만들지 않았습니다.

## 중단 기준 (실행 전 등록)

- 치명이 1건이라도 있으면 진행하지 않습니다.
- **개인 특성을 지우는 거절**이 관찰되면(예: 피로 상황 walk, 정지 중 rest, 부재 조건 행동이 오류로 거절됨) 그 자리에서 멈추고 계약을 고칩니다. 수정 결정 위반입니다.
- 첫 응답 유효율이 D4보다 3%p 넘게 떨어지거나 조용한 붕괴가 3건을 넘으면, `sentence_roles` 대신 D4 두 목록 + 서로소 검사로 되돌리는 안을 검토합니다.
- 우선 관계가 없는 겹침 입력에서 지어낸 overrides로 잃은 장면이 우선 명시 입력에서 얻은 장면 이상이면 overrides를 빼고 실행 불가 검사만 남깁니다.
- 질문 맥락·조건절·출처 문구(D5-09·11·12): 감시 입력 중 D3·D4에서 2/2 통과하던 입력이 떨어지면 해당 문구를 다시 검토합니다.
- API·전송 오류가 나면 실행기가 멈춥니다(재시도 없음).

## 실행 방법 (별도 작업 트리·D5 전용 진입점)

D4 실행 중인 작업 트리는 수정하지 않습니다. D5 초안을 통합 연구 브랜치의 별도 작업 트리로 옮겼으며, `run_d5.py`가 실행 시 D5만 등록하고 기존 `run_v2`의 승인 검사·단계 진행 조건·중복 제출 방지·원장 기록을 그대로 사용합니다. D5 진입점도 소스 해시에 포함합니다. 기존 `run_v2.py`는 수정하지 않았습니다.

```sh
python -m experiments.mind_contract_ab_20261007.run_d5 --stage d5_dev8 --run-dir "$D5_RUN_DIR" --ledger "$USAGE_LEDGER" --execute
```

위 명령은 D4 완료 확인 및 D5 승인 기록 후에만 실행합니다. dev8 통과는 문법·기존 장면의 회귀 점검이며 D5가 새 개인 특성을 해석하는지 증명하지 않습니다. dev128은 32개 원형 사례의 표현·의미 변형 128입력이고, 128명의 독립적인 실환자 자료가 아닙니다. 두 번씩 256개 첫 응답을 생성하며 검증 실패 응답에만 최대 한 번 수정 요청합니다. dev8을 포함한 호출 상한은 544회입니다.

`dataset/disputed_v1`은 32개 합성 개발 사례·128장면입니다. 빈 개인 규칙으로도 57장면이 통과하므로, 전체 점수와 함께 빈 규칙이 틀리는 71장면을 별도로 보고합니다. 기존 dev128과의 구조·문장 중복 표시 7개, 거친 구조만 겹치는 검토 대상 2개가 있습니다. 독립 최종 평가로 사용하지 않습니다. 원본 dev128 정답은 변경하지 않았습니다.

사전 점검 재현:

```sh
python -m experiments.mind_contract_ab_20261007.audit_d5_preflight --run-dir "$PREVIOUS_RUN_DIR" --output experiments/mind_contract_ab_20261007/results/d5_preflight/audit.json
```
