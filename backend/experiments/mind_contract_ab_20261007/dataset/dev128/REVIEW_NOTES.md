# 확대 개발 128입력 검토 메모 (2026-10-07)

## 상태

| 구분 | 수 | 상태 |
|---|---:|---|
| 원본(10/06 원형) | 32 | 기존 자료, 결과를 이미 본 개발 자료 |
| 파생(preserve·counterfactual·hard) | 96 | **AI 작성 초안, 사람 검토 전** (`draft_unreviewed`) |
| 장면 | 512 | 입력당 4장면(발동·비발동·경계/해제·미관찰/충돌) |

파생 96개는 Claude 하위 에이전트 4개가 원형 8개씩 나눠 작성했습니다. 빌더(`build_dev128.py`)는 각 입력의 수기 참조 정책이 4장면의 기대 결과를 모두 재현하는지 확인합니다. 이는 **내부 일관성 확인**일 뿐이며, 한국어 문장이 참조 정책의 뜻을 담고 있다는 증거는 아닙니다. 128개는 독립된 128명이 아니라 원형 32개의 계보입니다.

자동 확인: 문답 원문 중복 0, 보호자 답변의 영문·"정답"·"규칙"·"조건식" 0, 모델 호출 0.

## Claude의 의미 검토 (작성 에이전트가 불확실하다고 표시한 항목)

작성 에이전트가 표시한 항목 중 12개를 원문과 참조 정책을 대조해 읽었습니다. 사람 검토를 대신하지 않습니다.

| 입력 | 판단 | 메모 |
|---|---|---|
| DEV_P05_counterfactual | 유지 | AND 휴식. "시간만·거리만은 못 봤다"는 규칙 없음(기본 이동)으로 처리. 미관찰을 행동으로 만들지 않는 계약과 맞음 |
| DEV_P08_counterfactual | 유지 | 통증 OR 12분 휴식. "숨참만으로는 안 멈춤" 보존 |
| DEV_P21_counterfactual | 유지, 주의 | 정정 방향을 뒤집어 본인 대기. 해제 조건이 원문에 없어 무해제 대기로 둠 |
| DEV_P24_counterfactual | 유지 | 질문 맥락에 기댄 "네" + 본인 확인 |
| DEV_P09_counterfactual | 유지 | 가족이 곁에 있을 때의 대기만 관찰, 혼자일 때 미관찰 |
| DEV_P10_counterfactual | 유지 | 질문의 "불안해하실 때"가 조건에 포함됨. 짧은 답의 질문 의존 |
| DEV_P13_counterfactual | **수정 후보** | 발언→실제 출발과 시간 창(9~10시)이 함께 바뀜. 반사실의 "한 요인만 변경" 원칙에 어긋남. 결과 해석 시 두 요인을 분리하지 못함 |
| DEV_P16_hard | 유지, 주의 | 출발 조건에 "아직 도착 전"을 `not physical_arrival`로 넣음. 문장 근거는 있으나 모델이 같은 결합을 쓰지 않으면 도착 장면이 unknown이 될 수 있음 |
| DEV_P29_counterfactual | 유지, 주의 | "무릎이 먼저"라는 우선순위를 대기 조건의 부정 결합으로 표현. 계약에 `supersedes`가 없어 생긴 표현이며 동치인 다른 식도 정답 |
| DEV_P26_counterfactual | 유지 | 23시~자정 대기, 0시 해제 |
| DEV_P27_counterfactual | 유지 | 자정을 넘는 18~6시 창. "전까지"를 6시 해제로 읽음 |
| DEV_P18_counterfactual | 유지 | 어둠 OR 가족 부재. 문장에 명시됨 |

나머지 작성자 메모(P01_hard·P02_hard의 장소 범위가 앞 질문 문맥에 기대는 점, P03의 "해 지고"가 시각으로 읽힐 여지, P08의 "숨차 보임"을 높은 피로로 본 점, P20_hard의 대명사 해석, P28_hard의 근거 ID 선택 등)는 사람 검토 때 함께 봐야 합니다.

## 채점 시 주의

- `scoring.WITHHELD`는 원형 ID 기준입니다. 파생 입력에는 적용되지 않습니다. 파생 입력의 금지 행동 검사가 필요하면 입력별로 따로 지정해야 합니다(P21·P24 counterfactual은 본인 대기가 정답).
- 파생 P02는 원형과 달리 준비 정보(prepared_initial)가 없습니다.
- 휴식·대기 지속시간(`hold_minutes`)은 장면 명령으로 드러나지 않아 장면 채점에서 검사되지 않습니다.
