# 별도 평가 64원형 설계 (작성 전)

**아직 만들지 않았습니다.** 인계 문서 원칙에 따라 별도 평가 자료는 개발 자료를 작성·열람한 사람(이번에는 Claude)과 다른 사람이 작성하거나, 최소한 사람이 검토·확정해야 합니다. 이 문서는 그 작업을 위한 형식과 검사 방법입니다.

## 구성

8개 행동군 × 8개 새 원형 = 64명, 원형당 4장면(발동·비발동·경계/해제·미관찰/충돌), 모델 2응답. 후보 1개 기준 K-EXAONE 128회, 행동 판정 512건입니다.

| 행동군 | 새 원형이 다뤄야 할 다양성 (개발 32원형에 없는 조합 우선) |
|---|---|
| environment | 숲·물가 회피, 특정 장소와 유형 전체의 범위 차이, 소음/혼잡 외 어둠·비와의 결합 |
| physical_rest | 시간만·거리만·둘 다(AND) 한계, 휴식 지속시간 명시, 통증 발언 조건, 능력만 있는 반례 |
| waiting | 길 잃음 외 계기(비·어둠·불안), 가족 대신 다른 동행자, 해제 조건이 없는 대기 |
| destination | 솔빛쉼터·해든상가로의 출발, 발언과 출발의 구분, 도착과 인지의 구분 |
| external_state | 비·어둠·피로·불안의 OR/AND, 해제 조건, 시각으로 어둠을 추정하지 않는 반례 |
| source_fidelity | 여러 턴에 걸친 정정, 다른 가족 사례, "네"만 있는 짧은 답, 철회 후 재진술 |
| time_context | 자정을 넘는 시간대, 시작/종료 경계, 시각과 연속 보행 시간의 혼동 반례 |
| multiple_behaviors | 세 행동 공존, 우선순위 명시/미명시, 한 행동만 관찰된 경우 |

## 레코드 형식

개발 자료와 같은 파일 구성을 씁니다. 모델 입력 파일에는 정답·행동군·원형 정보를 넣지 않고, 실행기는 `personal`만 모델에 보냅니다.

- `eval64_inputs.jsonl`: `id`, `root_id`(새 원형 자체), `family`, `split="evaluation"`, `synthetic=true`, `review_status`, `author`, `personal`
- `eval64_scenes.NOT_MODEL_INPUT.json`: 원형당 4장면, `role`·기대 상태·명령·가능 명령
- `eval64_reference.NOT_MODEL_INPUT.json`: 수기 참조 정책(채점 일관성 확인용)
- `eval64_review.NOT_MODEL_INPUT.jsonl`: 작성자, 검토자, 검토 날짜, 불일치와 합의 결과

`build_dev128.py`의 DSL과 같은 방식으로 작성하면, 참조 정책이 장면 기대를 재현하지 못할 때 빌더가 멈춥니다. 이는 내부 일관성 확인이며 문장의 의미가 맞다는 증거는 아닙니다.

## 확정 절차

1. 작성자가 원형 64개와 장면을 작성합니다. 작성자가 개발 자료를 읽었다면 그 사실을 `author`에 적습니다.
2. `leakage_check.py`로 개발 자료와의 문장 유사도(문자 3-gram Jaccard 0.5 이상)와 같은 행동군·같은 규칙 구조를 표시합니다. 표시된 원형은 다시 쓰거나 개발 자료로 옮깁니다.
3. 별도 검토자가 원문 의미·참조 정책·장면을 대조합니다. 애매하면 `unknown`으로 두거나 보류합니다.
4. 검토가 끝난 파일의 SHA-256을 실행 매니페스트에 고정한 뒤에만 호출합니다. 결과를 보고 후보를 바꾸면 이 세트는 개발 자료가 되며, 다음 버전에는 새 세트가 필요합니다.

## 통과 기준 (인계 계획 제안, 실행 전 PLAN에 고정)

512판정 중 461 이상, 행동군별 64판정 중 52 이상, 실제 반응 장면·미관찰 장면 각 90% 이상, 유효 완성 응답 128개 중 122 이상, 치명 오류(목적지/범위 혼동, 명시 휴식 삭제, 미관찰→관찰 조작, 정정된 타인 행동 주입) 0건.
