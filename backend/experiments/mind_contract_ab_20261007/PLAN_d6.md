# D6 조건 보존 수정 후보 — 실행 전

목표는 온보딩에서 드러난 개인의 행동 조건을 보행까지 보존하는 것이다. 센터 시연 자료 제작은 중단하고 실제 연결의 실패를 고친다. 기존 데이터와 정답·점수는 고정한다.

## 확인한 문제

- D3에서 기존 네 상황을 통과하고 보행에는 실패한 8응답 모두 추가 조건 검사에서 차이가 발견됐다. 행동 이름만 맞아도 보행에 필요한 시작·종료·도착 조건이 빠질 수 있다.
- D5 dev8 최종 결과는 51/64, 유효 출력 13/16으로 기존 기준 58/64·15/16 미달. 한 응답은 휴식 행동을 만들면서 그 근거의 주인을 다른 사람으로 표시했다. 다른 응답은 행동을 관찰하지 못했다는 문장을 ‘행동을 한정하는 문장’으로 표시하고 어느 행동에도 인용하지 않아 거절됐다. 또 다른 유효 출력은 원문 280미터를 880미터로 바꿨다. 이 결과를 강제 수정하거나 유효 처리하지 않는다.

## 변경과 유지

D6은 D3/D4의 두 목록 출력과 D4 컴파일러를 그대로 사용한다. D5의 문장별 역할 행렬과 정정 관계 출력 과제를 추가하지 않는다. 질문과 답을 묶어 제시하고, 행동 조건·부정·목적지 도착·장소 한정·수치를 원문과 대조하는 지침을 준다. 단어 매핑으로 조건을 보충하지 않는다. 실제 출력이 개선되는지는 아직 확인하지 않았다.

이 후보에는 D5의 새 우선순위·정정 관계 표현 능력이 없다. 그런 원문까지 지원한다고 주장하지 않는다. 이 범위의 개선만으로 최종 아키텍처나 배포판을 확정하지 않는다.

## 첫 수정 실험

입력 ID는 `run_repair8.IDS`에 고정한 8개. 보행 한계(P05), 걷던 중 통증(P08), 발언과 실제 출발의 구분(P13), 도착과 인지(P16), 자정 넘는 시간 조건(P26), 수치와 여러 행동(P29), 장소 회피와 휴식(P30), 불안과 가족 부재의 공통 조건(P31)을 확인한다. 기존 실패 유형을 고치는 개발 자료이며 독립 최종 평가가 아니다. 8입력 × 2반복 = 첫 호출 16회, 검증 실패 응답에만 수정 요청 최대 1회 = 총 최대 32회. 자동 전송 재시도 없음, 동시 2회. 모델 `depmkuykpfon9lg`(K-EXAONE), temperature 1.0, top_p 0.95, 출력 호출당 16,384토큰, 전체 출력 최대 524,288토큰. 입력 토큰·단가·실청구액·지원 차수는 미확인. 기존 공용 원장 기록을 연결한 실행기 사용. 신규 GPU·RAG·지도 호출과 배포 없음.

실행 전 이 새 후보·선정 입력 범위의 승인을 기록한다. 기존 D5 승인 파일을 D6 승인으로 복사하지 않는다.

## 판정 순서

1. 기존 네 상황 점수와 원문/응답을 보존한다. 실패·무효 응답을 분모에 포함한다.
2. `condition_probe`로 기준과 다른 실행 조건의 반례를 찾아 원문과 대조한다. 기존 기준은 팀 작성 가설이므로 차이는 자동 임상 오답 판정이 아니다. 임의로 정답을 바꾸지 않고 논쟁 사례로 분리한다.
3. 실제 새 출력과 기존 D3의 같은 입력을 기존 KINTEX 도로·합성 관측·동일 난수에서 비교한다. 저장 출력이 아닌 사람이 수정한 출력으로 성공을 만들지 않는다.
4. 잘못된 인물·없는 관찰·조건 반전이 남거나 기존 정답을 훼손하면 확대하지 않는다. 통과해도 새로운 문답·시간 연속성·실제 앱 연결 검증은 별도로 필요하다.

센터장에게 보여 줄 준비가 됐다는 판정, 독립 전문가 평가, 실제 실종 위치 정확도는 이 개발 실험의 결과가 아니다.
