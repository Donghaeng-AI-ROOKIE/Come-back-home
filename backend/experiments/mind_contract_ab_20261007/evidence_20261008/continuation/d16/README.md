# D16 조건 요약 개선과 길이 실패 복구 — 완료

짧은 답변의 시작·종료 조건, 도착과 공간 범위의 구분, 근거 문답 누락을 개선하려 했다. D15에 간단한 근거 요약 지시와 누락 문답 ID 피드백을 추가했다. 같은 합성 개발 입력8개×2반복이며 최초16회와 검증 실패 수정 최대16회를 동결했다.

| 같은 입력 비교 | D12 | D15 | D16 |
|---|---:|---:|---:|
| 작성자 참조 장면 일치 | 57/64 | 58/64 | 55/64 |
| 최종 실행 가능한 출력 | 16/16 | 15/16 | 15/16 |
| 추가 조건 조합 일치 | 8/16 | 12/16 | 9/16 |
| 판별 가능한 KINTEX 보행 | 8/12 | 9/12 | 7/12 |

D16은 채택하지 않는다. D12 대비 장면3개를 고쳤지만5개가 악화됐다. D15 대비5개를 고치고8개가 악화됐다. 프롬프트에 조건 보존 지시를 더한다고 일관된 개선이 나오지는 않았다.

실제로 계속 걷는 행동은 별도 머무름 기준선 검사에서 두 반복 모두 보존됐다. 그러나 질문의 가족 귀환 조건, 아침 시각 구간의 가족 부재 조건, 장소 도착 해석에서 실패가 남았다. 이 표는 개발 자료와 작성자 참조 기준이며 임상 정확도·실제 실종 경로 정확도가 아니다.

## 별도로 고친 실행 문제

출력1개는16,384토큰 한도에서 끊겼다. 미완성 모델 응답을 수정 요청에 다시 넣으면서 요청이43,257바이트가 되어40,000바이트 상한을 넘었다. 보호자 원문을 지키기 위해 기존 실행기는 수정 요청을 보내지 않고 실패로 남겼다.

수정한 실행기는 **원래 보호자 문답·모델 설정·출력 스키마는 전부 보존**한다. 길이 한도로 끊겼고 수정 요청이 상한을 넘는 경우에만, 미완성 이전 모델 응답 본문을 요청에서 생략한다. 이전 원응답은 파일로 보존하고 생략 사실도 기록한다. 다른 형식 오류를 무조건 잘라 통과시키지 않는다.

같은 합성 사례에 별도1회 재생성을 실행했다. 요청은14,459바이트였고 완전한 규칙이 반환됐다. 기존에 빠뜨렸던 보조 문답 N3도 근거로 포함했으며, 자정을 넘는 기다림과 가족 부재 조건은 작성자 참조의24개 조건 조합에 모두 일치했다. 이1건은 실행 복구 가능성을 확인한 것이며 D16 전체 개선이나 일반적인 복구 성공률을 입증하지 않는다. 원래 표의55/64·15/16·7/12를 사후 수정하지 않았다. 보충 응답 자체의 신규 보행은 실행하지 않았다.

## 사용량 및 검증

- 본 실험: K17회, 입력41,476·출력85,002·합계126,478토큰. 통신 오류0. 출력 길이 실패1건은 별도로 존재한다.
- 보충 재생성: K1회, 입력2,670·출력5,889·합계8,559토큰. 통신 오류0.
- 합계18회 모두 시작·종료 원장이 일치한다. 단가·실청구액·지원 차수는 미확인이다. 새 지도·RAG·임베딩·GPU 학습·운영 배포 없음.
- 수정 요청의 원문 보존·상한·오류 구분 테스트3개 통과. 관련 조건·실행 진단 테스트는 별도로32개 통과했다.

본 실험 증빙은 `d16_dev8/`, 보충 호출은 `length_correction_supplement/`에 분리했다. 코드 `bounded_correction.py`는 연구 실행기용이며 운영에 연결하지 않았다.

## 다음 판단

D12의24개 확대 개선 근거는 유지한다. D15·D16을 전면 교체 후보로 삼지 않는다. 남은 일은 (1) 질문 속 종료 조건의 반복 누락을 새 장문의 지시 추가와 다른 방식으로 해결하고, (2) 장소별 도착·인지 사실을 엔진에 정확히 연결하는 것이다. 후자는 앞선 구성 상태 진단으로 엔진 문제가 재현됐으며, K 해석 정답률과 섞어 처리하지 않는다.
