# D15 집중 수정 — 전체 교체 보류

D12 확대 비교에서 드러난 ‘실제로 계속 걸었다는 관찰 누락’, ‘질문에 담긴 종료 조건 누락’, ‘이미 고정된 규칙 중복’을 짧은 지시 세 단락으로 고치려 했다. 같은 K-EXAONE, 샘플링, 출력 스키마, 검증기, 작성자 참조를 유지했다. 기존 실패·통제 입력 8개를 두 번씩 실행했으며 독립 평가는 아니다.

| 같은 8개 입력 비교 | 저장된 D12 | D15 |
|---|---:|---:|
| 작성한 장면 일치 | 57/64 | 58/64 |
| 실행 가능한 출력 | 16/16 | 15/16 |
| 추가 조건 조합 일치 | 8/16 | 12/16 |
| 판별 가능한 KINTEX 보행 | 8/12 | 9/12 |

장면은 7개를 고치고 6개가 악화됐다. 보행은 3개를 고치고 2개가 악화됐다. 한 점 상승만으로 전체 교체하지 않는다. 원형 8개×2반복이며 16명의 환자가 아니다. 기본 보행 검사에서 구분하지 못하는 4개는 보행 분모에서 제외했다.

## 실제로 개선된 부분

보호자가 ‘기다린다는 설명은 아버지 이야기였고, 어머니는 길을 잃은 것을 알아차리면 계속 걸었다’고 정정한 사례다. D12는 첫 반복에서 어머니의 계속 걷기까지 빠뜨렸다. D15는 두 반복 모두 `lost_awareness → walk`를 보존했다.

기본 성향을 머무름으로 둔 구분용 KINTEX 검사에서도 두 반복 모두 참조와 같은 평균0.4797km 이동·19.9733분 대기를 기록했다. 규칙이 없는 경우는0km·30분이었다. 이 검사는 합성 조건에서 규칙이 이동에 영향을 주는지 확인하며 실제 이동거리 예측 성능을 뜻하지 않는다.

## 남은 오류와 별도 진단

1. 가족이 돌아오면 대기를 끝낸다는 조건이 한 반복에서 다시 빠졌다. 다른 반복은 올바르게 반영했다. 같은 문답의 반복 안정성 문제가 남아 있다.
2. 특정 장소 주변에 있음과 그 장소에 실제 도착함을 구분하지 못한 출력이 남았다. 현재 엔진의 `physical_arrival`도 선택한 목표의 도착 상태여서, 임의 장소에 도착한 사건을 완전하게 표현하지 않는다. 모델 해석과 엔진 사실 연결을 별도로 봐야 한다.
3. 자정을 넘는 기다림 규칙 자체는 맞게 만들었지만, ‘가족이 옆에 있으면 기다리지 않았다’는 보조 문답 N3를 어느 출력 목록에도 넣지 않아 전체 출력이 거절됐다.

3번은 원래 실패를 유지한 채 규칙만 진단 보행했다. 조건24조합과 KINTEX3상황에서 참조와 일치했다. 그러나 코드가 N3를 비행동 정보라고 판정하거나 정답 근거로 채우지는 않았다. 누락한 문답은 **미분류**로 명시했고 배포 가능 판정을 하지 않았다. 원점수58/64와 형식15/16은 그대로다.

다음 D16은 짧은 근거 요약에 시작·종료·예외 조건을 먼저 정리하게 하고, 근거 누락 수정 요청에 빠진 문답 ID를 명시한다. 의미를 코드가 대신 해석하지 않는다.

## 사용량

K20회(최초16+수정4), 통신 오류0, 원장 시작·종료20쌍. 입력47,284·출력78,603·합계125,887토큰. 단가·청구액·지원 차수 미확인. 추가 보행·근거 진단은 모델/네트워크 호출0회다.

증빙: `d15_dev8/scored.json`, `condition_probes.json`, `paired_with_d12.json`, `walking_paired_with_d12.json`, `explicit_walk_stress.json`, `coverage_only_diagnostic.json`, `usage_summary.json`. 운영 배포·전문가 검토 없음.
