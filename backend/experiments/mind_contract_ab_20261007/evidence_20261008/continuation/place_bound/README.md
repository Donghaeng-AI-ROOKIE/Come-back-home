# 장소별 도착·인지 연결 수정 후보와 전체 보행 회귀 검사

이전 엔진은 `physical_arrival`을 선택 목적지의 과거 도착 상태에서 읽고, `target_recognized`에는 장소 구분이 없었다. 특정 장소의 행동이 다른 장소의 도착·인지 사실로 확정될 수 있어 별도 실행 후보를 구현했다.

## 구현한 것

- `PlaceRecognition`: 등록 장소 이름·인지 여부·유효 시각을 함께 보존하는 관측. 등록되지 않은 장소, 잘못된 필드, 다른 종류의 사실은 거절한다.
- `PlaceBoundPopulation`: 특정 장소 규칙의 도착·인지 조건을 그 장소에 연결한다. 이동 이력의 방문 완료와 현재 좌표 도달을 분리한다.
- 장소 이름 없는 인지 관측, 다른 장소에 대한 관측, 관측 만료·충돌은 해당 장소의 인지 확정으로 쓰지 않는다. 가능한 행동의 분기로 남긴다.
- 같은 장소의 미확인 사실은 여러 규칙에서 동일한 미확인 변수로 취급한다. 서로 모순되는 참·거짓이 동시에 성립하는 것으로 만들지 않는다.
- 인지 관측이 분 사이에 바뀌어도 그 시각에 대기를 재평가한다. 저장·복원 시에는 장소별 관측 구성이 같은지도 검사한다.

기존 `Population`에는 규칙 평가 메서드를 분리하는 변경만 했다. 새 실행기를 API에 자동 연결하거나 운영 모델을 교체하지 않았다. 기존 연구 기준선의 소스와 결과는 보존했다.

## 검증 결과

KINTEX 실도로 캐시에서 합성 등록 장소·관측으로 검사했다. 모델·지도·임베딩 신규 호출0회다.

| 검사 | 결과 |
|---|---|
| 장소별 동작·인지 만료·충돌·저장 복원 | 신규9개 통과 |
| 기존 휴식·대기·보행·상태 유지 | 기존37개 통과 |
| 실제 앱 합성 사례의 회귀 | 500명×3상황×6시간 동일 |
|1·2·4시간JSON 저장 후 복원 | 기존 보행자 상태와 동일 |
| 시간별 지도·집계·첫5명 원시 경로 | 기존 결과와 동일 |
|500명 전원 행동 검사 | 기존 검사 결과와 동일 |

기존 앱 합성 사례의 세 결과 JSON은 파일 해시까지 같았다. 이 사례의 휴식·가족 대기·장소 소음 회피에는 새 도착·인지 규칙이 없으므로 **기존 성공 사례의 회귀가 없다는 검사**다. 새 도착·인지 동작은 별도9개 검사에서 확인했다. 500명을500개의 독립 환자 사례로 세지 않는다.

새 규칙을 주입한 단위 장면에서는 선택 목적지가 아니더라도 해당 등록 도로 노드에 있고 그 장소를 알아보았다는 관측이 있으면 기다렸다. 다른 장소의 인지 관측만 있으면 해당 장소의 인지는 미확인으로 남았다. 인지를 참에서 거짓으로 바꾼 장면에서는0.25분 대기 후1.75분을 걸었고, 중간 저장·복원 후에도 동일했다.

## 적용 범위와 남은 일

‘도착’은 현재 등록 장소로 스냅한 도로 노드에 있다는 기하적 정의다. 실제 건물 출입이나 방문 의도를 확인한 것이 아니다. 같은 스냅 노드를 통과하는 경우와 건물에 방문한 경우까지 구별하지는 못한다. 장소 유형도 실제 소음·혼잡 관측으로 쓰지 않는다.

현재 후보는 도착·인지가 들어간 규칙을 장소 하나에 연결한다. 이런 규칙에 복수 장소를 한꺼번에 넣으면 명시적으로 거절한다. 자료에서 여러 장소의 행동이 필요하다면 장소별 규칙과 사실 연결을 함께 검증해야 한다.

운영API의 관측 입력·저장 경로는 아직 연결하지 않았다. K가 종료 조건이나 도착 조건 자체를 빠뜨리는 문제도 이 실행기 변경이 대신 고치지는 않는다. 후보는 배포 완료나 임상 행동 재현 완료로 판정하지 않는다.
