# 슬롯 랭킹 측정 도구

Phase 0 온보딩이 "다음에 뭘 물어볼지" 고르는 품질(`phase0/retrieval.py`)을 재는 도구.
**임베더를 바꾸거나 슬롯 `embed_text` 를 손볼 때** 쓴다.

## 왜 필요한가

`retrieval.py` 의 세 상수는 **코사인 유사도 절대값**이다.

| 상수 | 하는 일 |
| --- | --- |
| `COHERENCE_THRESHOLD` | 이 값 미만으로 유사한 과거 턴은 화제이탈로 보고 버림(디노이즈) |
| `PIVOT_SIM` | 최고 유사도가 이 값 이상이면 피벗 모드(꼬리질문), 미만이면 템플릿 순서 |
| `RISK_GATE` | 위험 슬롯 가점을 이 값 이상일 때만 적용 |

임베더를 바꾸면 유사도 분포가 통째로 이동해서 **값을 그대로 두면 가드가 조용히 꺼진다.**
실측 예 — ko-sroberta 기준 `COHERENCE_THRESHOLD=0.15` 를 KURE-v1 에 그대로 쓰면
과거 턴을 **0% 잘라내** 디노이즈가 사실상 없어진다(KURE 는 본론 턴끼리 코사인 최솟값이 0.322).

## 구성

```
corpus.py         ON(본론)/OFF(잡담) 코퍼스 — 골드 라벨은 chatbot_eval 시나리오에서 파생
slot_sim_dist.py  코퍼스 기준 분포·argmax 적중률·자석 진단   (빠름, 쿼터 0)
const_sweep.py    하네스를 굴리며 상수 갈아끼우기 + 라이브 분포 (느림, 실키는 쿼터 소모)
```

골드 라벨은 공짜다 — `scenarios.py` 의 `answers` 가 `{슬롯키: 그 슬롯 답변}` 구조라
"이 발화의 정답 슬롯"이 이미 라벨링돼 있다.

## 실행

backend 디렉토리에서. 콘솔이 cp949 면 `PYTHONUTF8=1` 필수.

```bash
# 임베더 품질 — 모델 비교, embed_text 수정 전후
PYTHONUTF8=1 PYTHONPATH=. python -m experiments.slot_ranking.slot_sim_dist
PYTHONUTF8=1 PYTHONPATH=. python -m experiments.slot_ranking.slot_sim_dist --model nlpai-lab/KURE-v1

# 상수 후보 좁히기 (스텁, 쿼터 0)
PYTHONUTF8=1 PYTHONPATH=. python -m experiments.slot_ranking.const_sweep \
    --config "PIVOT 0.45:0.45/0.30/0.15" --config "COH 0.45:0.32/0.30/0.45"

# 상수 확정 (실 Mi:dm — 설정당 시나리오수 × runs 회 대화)
PYTHONUTF8=1 PYTHONPATH=. python -m experiments.slot_ranking.const_sweep \
    --real --runs 3 --config "후보:0.45/0.30/0.45"
```

`--config` 형식은 `라벨:PIVOT/RISK/COH`. 값 자리를 비우면 현재값을 쓴다 —
`"RISK만:/0.45/"` 처럼 **1개 상수만 격리**할 수 있다. 두 개를 같이 바꾸면
어느 쪽이 효과를 냈는지 못 가리므로, 원인을 알아야 할 때는 반드시 격리할 것.

## 절차 — 임베더를 바꿀 때

1. **`slot_sim_dist.py --model 새모델`** — argmax 적중률로 모델 자체가 나은지 확인.
   현재 임계가 새 스케일에서 극단(전부 발동/전혀 미발동)으로 가는지도 여기서 보인다
2. **`const_sweep.py --config ...`** (스텁) — 후보를 3~4개로 좁힌다
3. **`const_sweep.py --real --runs 3`** — 좁힌 후보로 확정
4. **채택 직전 설정을 한 번 더 돌린다** — 재현 검증

## ⚠ 함정 (전부 P1-1 에서 실제로 밟은 것)

**① 스텁으로 상수를 확정하면 안 된다.** 스텁은 질문 문구가 고정 템플릿이라
대화 궤적·폴백 분포가 실 Mi:dm 과 근본적으로 다르다. P1-1 에서 **3전 3패**
— 스텁이 고른 값이 실키에서 세 번 모두 반대로 나왔다. 스텁은 후보 좁히기까지만.

**② 스텁의 중복질문 수치는 아티팩트다.** 스텁 18~28 이지만 실키는 0~0.7.
고정 문구가 반복돼 중복으로 집계될 뿐, 실 Mi:dm 은 매번 다른 문구를 생성해
`dedup` 가드가 정상 작동한다.

**③ 임계는 라이브 분포에서 고른다.** 실제 랭킹은 단일 발화가 아니라
`build_history_aware_query` 가 만든 융합 쿼리를 쓴다. 이어붙이면 벡터가 희석돼
코퍼스 유사도보다 낮게 나온다. `slot_sim_dist.py` 의 임계 후보는 참고용이고,
확정은 `const_sweep.py` 가 출력하는 라이브 분포에서.

**④ 수집률·축 커버리지로 판단하지 마라.** 반복 측정한 변동폭:

| 지표 | 변동폭 | 판정에 쓸 수 있나 |
| --- | --- | --- |
| 질문수 | SD ≈ 0.6 | ✅ |
| 축 커버리지 | 4pp | ❌ |
| 수집률 | 8pp | ❌ |

수집률은 시나리오 6개의 평균인데 셋은 분모가 **1** 이다(`COR_*`). 끌림점 하나를
놓치면 전체 평균이 16.7pp 움직인다. 축도 하나 놓치면 3.7pp.

**⑤ 유의성을 논하기 전에 노이즈부터 재라.** 판정할 설정을 배치에 **두 번** 넣어라.
몇 분이면 되고, 없으면 판정이 무의미하다. P1-1 에서 이걸 안 하고 시작해 판정을 두 번 뒤집었다.

**⑥ 무정보 답변은 OFF 다.** `"잘 모르겠어요"` 는 대본상 슬롯에 매달려 있지만 내용이 없다.
ON 으로 두면 분포가 오염된다(적중률 61.5% vs 75.9%). `corpus.is_noinfo` 가 처리한다.

**⑦ "1등 횟수 ≫ 정답 횟수" 가 곧 자석은 아니다.** 잡담 발화만 흡수하는 슬롯일 수 있다
(허브니스 — `embed_text` 가 짧고 일반적이라 코퍼스 중심에 가까운 경우). 자석 진단표만
보지 말고 **argmax 오답 목록**과 대조해서 "내용 있는 발화를 실제로 가로챘는지" 확인할 것.
