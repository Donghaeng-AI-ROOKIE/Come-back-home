# 정답표(골드셋) 생성 실험 설계 — 3계열 모델 라벨링

작성 목적: **EXAONE이 페르소나 특성에 맞게 축 점수를 잘 매기는지(축별 정확도·변별)** 를
측정할 골드셋 v1을 만든다. 정답 라벨은 Claude·GPT·Gemini 3계열 모델로 생성하고,
갈린 셀만 사람이 판정한다.

---

## 0. 한눈에 보는 역할 분리 (제일 중요)

| 구성 | 누구 | 절대 규칙 |
| --- | --- | --- |
| **채점 대상(시험 보는 쪽)** | EXAONE | 골드셋 만들 때 EXAONE 출력을 **아무도 보면 안 됨**(독립성) |
| **라벨러(정답표 만드는 쪽)** | Claude · GPT · Gemini | 서로 블라인드, EXAONE 블라인드, 계열이 달라야 함 |
| **판정자(갈린 셀만)** | 사람 | 라벨러 후보는 봐도 됨, EXAONE 결과는 못 봄 |

라벨러 ≠ 채점 대상이라 순환논리 없음. 단 **"gold"가 아니라 정확히는 "3계열 합의 +
사람 판정 기준셋"** — 라벨러도 AI라 애매 셀은 사람이 앵커한다.

---

## 1. 측정하려는 주장과 지표

주장 = **Claim B (축별 정확도)** 의 "변별(discrimination)" 버전. 전체 평균 하나로는
"어느 축이 약한가"가 안 보이므로 축을 쪼개서 본다.

### 지표

셀 = (시나리오, 축). 라벨은 A~E(0.1~0.9) 순서형 + F(판정불가, 순서형 밖).

- **축별 정확도** — 각 축마다 따로:
  - 정확 일치율 (choice 완전 동일)
  - 인접 일치율 (±1단계면 맞다고 봄 — 0.7 vs 0.9는 사소)
  - **이차 가중 Cohen's κ** (A~E를 1~5 순서로, 인접 오차엔 관대·먼 오차엔 엄격 + 우연 보정)
  - MAE (0.1~0.9 스케일 평균 절대오차)
- **변별** — 각 축 내에서 EXAONE 점수 ↔ 정답 점수의 **Spearman ρ**(특성 강도를 순위대로 따라가나)
- **축 분리** — 대조쌍(§2-B)에서 varied 축만 움직이고 나머지 축은 안 새는가 (Δ 비교)
- **F 처리** — 순서형에서 빼고 따로: EXAONE·정답이 둘 다 F인가(근거부족 인식 일치율)

한 축당 셀이 최소 15~20개는 있어야 위 지표가 노이즈를 벗어난다 → §2 규모.

## 2. 데이터셋 설계

축 목록 (기준표 `app/phase0/axis_rubric.md` 단일 소스):

- 공통 3축: `mobility_transport_capacity`, `hazard_awareness_vulnerability`, `communication_approach_vulnerability`
- 치매 특화 3축: `wayfinding_error_recovery_deficit`, `autobiographical_destination_pull`, `distress_induced_movement_reactivity`
- 발달 특화 4축: `preferred_target_seeking`, `aversive_context_escape`, `transition_routine_disruption`, `elopement_pattern_consistency`
- → 치매 페르소나 = 6축 채점, 발달 = 7축 채점

시나리오는 두 종류로 나눈다.

### A. 표준 다양 페르소나 (bulk — 정확도·커버리지용)

- **유형당 15명** (치매 15 + 발달 15 = 30명). 특화축당 15셀, 공통축당 30셀.
- 목표 = 각 축이 0.1~0.9 **전 구간**을 고루 덮게. 다 0.5쯤 몰리면 변별을 못 잰다.
- **프로파일 벡터로 커버리지 통제**: 각 페르소나에 미리 "축별 목표 레벨"을 배정해
  생성 → 커버리지 보장. **단, 목표 레벨은 생성 계획용일 뿐 정답이 아니다** — 실제
  정답은 §3 라벨링으로 독립 산출한다(목표와 다르게 나오면 그게 오히려 정보).

유형당 15명 프로파일 배분 (각 축이 저·중·고를 최소 4~5셀씩 보게):

| 프로파일 | 인원 | 성격 |
| --- | --- | --- |
| 전반 저위험 | 3 | 대부분 축 A~B |
| 전반 고위험 | 3 | 대부분 축 D~E |
| 혼합형 | 9 | 일부 축만 고·나머지 저 (축 간 상관을 깨는 게 핵심 — 축 분리 검증 재료) |

혼합형 9명은 서로 다른 축 조합을 고점으로: 예) #1 이동능력만 高·나머지 低, #2 위험인식만
高, #3 자전적목적지 高 + 이동능력 低 … 식으로 축마다 "이 축만 튀는" 케이스가 최소 1명씩
나오게 배치.

> **커버리지 수용 기준(라벨링 후 점검):** 각 (축 × 레벨밴드 저/중/고)에 정답 셀이
> **3개 미만**이면 그 밴드를 노리는 페르소나를 몇 명 추가 생성해 채운다. 이 top-up
> 반복이 "big ≠ meaningful"을 막는 장치다.

### B. 대조쌍 (contrast — 변별·축 분리 전용)

각 축마다 **다른 축 근거는 거의 동일**하게 두고 **그 축의 근거만 저(A/B) ↔ 고(D/E)** 로
바꾼 페르소나 2명(쌍). 여유되면 중(C) 추가해 3명(삼중)으로.

- 치매 6축 × 2명 = 12명, 발달 4축 × 2명 = 8명 → **대조쌍 20명**
- 검증:
  - **변별** = varied 축에서 EXAONE 점수가 저→고로 올바른 방향으로 움직이나 (부호 검정)
  - **분리** = 안 바꾼 축들의 EXAONE 점수는 그대로인가 (Δ 작아야 정상)

이게 "특성에 맞게 매긴다"의 직접 증거다. README #2의 D2(친숙성 高 + 길찾기취약 高
동시 성립)에서 두 축이 서로 안 끌려간다고 본 그 관찰을 축마다 체계화한 것.

### 규모 합계

- 시나리오: 30(표준) + 20(대조) = **50명**
- 셀: 표준 195 + 대조 128 ≈ **약 320셀**
- 사람 판정 부담은 규모와 무관 — §4의 60셀 핵심층 고정(약 1시간)

## 3. 라벨링 = 정답표 생성 (Claude·GPT·Gemini)

### 입력 형식 — B안(축별 근거 발화만), EXAONE 채점과 동일

라벨러와 EXAONE이 **똑같은 입력·똑같은 프롬프트**를 봐야 사과 대 사과 비교가 된다.
축 X의 입력 = 그 페르소나의 축 X로 태그된 보호자 발화(+추출 사실)만. 대화 통짜(A안)는
상향 오염이 실증돼(파일럿) 쓰지 않는다.

### 프롬프트 = P1 그대로 (`app/phase0/axis_scoring.py`의 `build_p1_messages`)

축 하나씩, 기준표 A~E 분류 + quote 강제 + F(판정불가) + temperature 0. **숫자 직접
출력 금지**(코드가 A~E→0.1~0.9 매핑). 라벨러가 여러 축을 한 번에 보면 halo(후광)로
축이 서로 번지므로 **반드시 축 단위 격리**.

시스템/유저 프롬프트 원문은 `axis_scoring.py:99` `P1_SYSTEM` / `P1_USER_TMPL`.
축별 앵커·방향은 `axis_rubric.md`에서 그대로 채운다.

### 실행 방식 — 스크립트 권장

`experiments/axis_goldset/score_axes.py`가 이미 (시나리오 × 축 × 조건 × runs) 잡을
돌린다. 여기에 **라벨러 클라이언트 3개만 추가**하면 된다:

- Claude / GPT / Gemini 모두 OpenAI 호환 `chat/completions` 어댑터로 감싸 `client.chat(msgs, temperature=0)` 시그니처를 맞춘다(EXAONE 클라이언트와 동일 인터페이스).
- 조건 = `B-P1` 고정, `--models claude,gpt,gemini`, `--runs 3`.
- 파싱·quote 검증·다수결은 `axis_scoring.parse_p1` / `_majority` 재사용 → 라벨러도
  운영 파서로 검증돼 실험이 곧 코드 검증이 됨.
- 320셀 × 3모델 × 3run ≈ 2,880콜. **실호출 전 총 콜 수·쿼터 고지**(기존 규칙).

수동(챗 UI)으로 일부만 돌리려면 페이지 맨 아래 붙여넣기용 프롬프트 사용.

### 라벨러별 산출 → 셀당 라벨

각 라벨러: 축당 3run → 자기 다수결(intra 안정성). 그 결과가 그 라벨러의 셀 라벨.

## 4. 정답표 확정 — 3중 필터 + 사람 핵심층

각 셀에서 3라벨러의 라벨을 모아:

1. **intra 안정** — 각 라벨러가 자기 3run 안에서 다수결 성립
2. **inter 합의** — 3라벨러 중 ≥2가 같은 choice
3. **quote 검증** — 다수 label의 근거 quote가 입력에 실재(`_quote_exists`)

→ 셋 다 통과 = **자동 정답 채택**. 하나라도 실패(3-way 분열, F vs 점수 충돌, quote
불통) = **사람 판정 대기**.

### 사람이 만지는 건 두 묶음뿐 (규모 무관, 약 60셀 / 1시간)

- **갈린 셀 전부** — 자동 채택 실패분 (보통 15~30%)
- **층화 검증 서브셋** — 자동 채택분에서 (축 × 레벨) 고루 뽑은 랜덤 표본
  - 용도: 사람 ↔ 3계열 합의 일치율 측정 → **합의가 믿을 만한지 입증**(높으면 나머지
    자동 채택분 신뢰 근거 확보). 이 서브셋이 "라벨러 검증"을 겸한다.

판정은 맨땅 라벨링이 아니라 **기준표 + quote + 라벨러 후보를 놓고 고르기**(셀당 1~2분).
갈린 셀은 대개 기준표 문구가 애매한 지점 → 그 사유를 모아 `axis_rubric.md` 개선에 환류.

정답 셀에는 **choice·점수·확정 근거 quote**를 함께 고정 → EXAONE이 "우연히 맞았나
근거까지 맞았나" 구분 가능.

산출: `07_정답표_v1.md` (셀 = 시나리오·축·정답 choice·quote·확정 사유·[사람판정 여부]).

## 5. EXAONE 평가

1. 각 페르소나를 `score_axes_for`(운영 경로, B-P1, runs=3, 다수결)로 채점 → EXAONE 축점수.
2. 골드셋 v1과 대조해 §1 지표 산출:
   - 축별 정확·인접 일치율, 이차가중 κ, MAE
   - 축별 Spearman ρ (변별)
   - 대조쌍 부호 검정(변별) + 비-varied 축 Δ(분리)
   - F 일치는 따로
3. **표기 원칙**: "EXAONE이 3계열 합의(+사람 앵커) 기준셋과 축별로 얼마나 일치하는가."
   "정답과 얼마나 맞는가"로 과장하지 말 것.
4. 통과 기준 예(팀 합의 필요): 축별 인접 일치율 ≥ 0.8, 이차가중 κ ≥ 0.6, 대조쌍 변별
   부호 정답률 ≥ 0.9. 미달 축은 프롬프트·기준표 개선 대상.
5. 확정 골드셋은 회귀 테스트로 편입(`test_axis_scoring.py`) — 이후 프롬프트·모델 변경 시
   자동 재측정.

> 붙여넣기 전 `{유형}`(치매/발달장애), `{나이}`, `{프로파일 벡터}`(축별 목표 레벨),
> 그리고 해당 유형 축 목록·기준표(axis_rubric.md 표)를 채운다.

```
너는 실종 위험 페르소나 시나리오 작가다. 아래 프로파일에 맞는 현실적인 보호자 상담
대화를 만든다.

[대상자] {유형}, {나이}세
[이 페르소나의 축별 목표 레벨] {프로파일 벡터}   ← 커버리지용, 겉으로 드러내지 말 것
[축 목록과 기준표] {axis_rubric 발췌}

규칙:
- 챗봇 질문 ↔ 보호자 답변 형식. 보호자 답변은 실제 사람이 말하듯 구체적·자연스럽게.
- 목표 레벨에 "딱 떨어지는 기준표 문장 복붙"은 금지. 정황으로 드러나되, 채점자가
  기준표를 대봐야 판정되게 쓴다(뻔한 답안지 만들지 말 것).
- 각 보호자 답변 끝에 " → axis_field" 로 그 발화가 근거가 되는 축을 태그(여러 개 가능).
- 근거 없는 축은 억지로 만들지 말고 비워둔다(그 축은 F가 정답이 될 수 있음).
- 개인정보(실명·전화·주소 실제값) 넣지 말 것.

출력: 아래 형식만.
# {ID}. {유형} ({나이}세, 한 줄 요약)
챗봇: ...
보호자: ... → axis_field
챗봇: ...
보호자: ... → axis_field
...
```

## 부록 B. 라벨링 프롬프트 (Claude·GPT·Gemini 각각, 축 하나씩)

> `build_p1_messages`와 동일. 수동 실행용. `{...}`는 axis_rubric.md에서 채운다.

시스템:
```
너는 실종 위험 프로파일 채점자다. 보호자 상담 내용에서 지정된 '평가 축' 하나만 보고,
기준표의 선택지 중 가장 부합하는 하나로 분류한다.

규칙:
- JSON 객체 하나만 출력한다. JSON 밖에 어떤 문장도 쓰지 않는다.
- choice: "A"~"E" 중 하나. 입력에 이 축을 판정할 근거가 부족하면 "F".
- quote: 판정의 핵심 근거인 보호자 발화를 입력에서 글자 그대로 옮겨 적는다. choice 가 "F" 면 빈 문자열.
- 입력에 없는 사실을 추측하거나 지어내지 않는다. 지정된 축과 무관한 정보는 판정에 쓰지 않는다.
- 여러 선택지의 근거가 공존하면 발견·구조를 더 어렵게 만드는 쪽(E에 가까운 쪽)을 고른다. 단, 축의 방향이 '능력·예측성'인 축은 실제 확인된 최고 수준으로 고른다.
- reason: 판단 근거 1~2문장 (한국어).
```
유저:
```
[대상자] {유형}, {나이}세
[평가 축] {축 한글명}
[축의 방향] 이 축의 상위 선택지(E쪽)가 뜻하는 것: {방향}
[기준표]
A. {0.1 앵커}
B. {0.3 앵커}
C. {0.5 앵커}
D. {0.7 앵커}
E. {0.9 앵커}
F. 판정 불가 — 입력에 이 축을 판정할 근거가 부족함
[보호자 상담 내용]
{그 축으로 태그된 보호자 발화만}

출력 형식: {"choice": "A~F 중 하나", "quote": "...", "reason": "..."}
```

## 부록 C. 왜 이 설계가 조작이 아닌가 (레드팀 대비)

- 프로파일 벡터의 "목표 레벨"은 **커버리지 계획용**이고 정답이 아니다. 정답은 3계열
  독립 라벨링 + 사람 판정으로 나온다. 목표와 정답이 달라도 그대로 둔다.
- 시나리오는 **현실적·풍부**해야 하고 기준표 문장 복붙("답안지 캐리커처")은 금지 —
  EXAONE은 남들과 똑같은 자연 시나리오로 시험 본다.
- 구성적 앵커(정답이 설계로 정해진 케이스)는 **골드셋에 넣지 않는다**. 쉬운 문제로
  점수를 부풀리는 패딩이기 때문. (라벨러 sanity가 필요하면 골드셋 밖 별도 파일에 두고
  EXAONE 채점엔 절대 쓰지 않는다.)
