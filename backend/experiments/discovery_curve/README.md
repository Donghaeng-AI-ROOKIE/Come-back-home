# 발견율 곡선 — 알림 전략 비교

x축 = 알림 셀 수(발송 비용), y축 = hit율. **"타겟 알림이 무차별 발송보다 얼마나
효율적인가"를 같은 조건에서 재는 실험.** LLM 호출 0회, GPU 불필요.

## 왜 만들었나

"그래서 얼마나 잘 맞느냐"에 답할 수치가 저장소에 하나도 없었다. 제안서의
핵심 주장(무차별 경보의 피로도를 줄인다)이 정성 서술만으로 남아 있었다.

## 실행

```bash
# backend/ 에서
python experiments/discovery_curve/run_curve.py --pilot   # 파일럿 60개 (약 15초)
python experiments/discovery_curve/run_curve.py           # 본 실험 800개 (약 4분)
python experiments/discovery_curve/analyze.py --pilot     # 집계 → 마크다운 표
python experiments/discovery_curve/analyze.py

# 도로망 켠 모드 — 타임라인당 약 2.5초(도로망 끔의 10배)
python experiments/discovery_curve/run_curve.py --pilot --roadnet --n=200
python experiments/discovery_curve/analyze.py --pilot --roadnet
```

`--roadnet` 은 `curve*_roadnet.jsonl` 로 따로 저장한다(끈 결과를 덮지 않는다).

### `--roadnet` 모드가 하는 일

1. `settings.use_roadnet` 을 켠다.
2. **도로망을 LKP 중심 그래프 하나로 고정한다**(`install_fixed_roadnet`). 제보로
   `case.lkp` 가 옮겨질 때마다 그 중심 그래프를 새로 받으면 중심당 약 114초가
   든다(실측: 5km 도보망 32,682노드 · 92,828엣지). 타임라인마다 layer2 제보가
   여러 번 나오므로 고정하지 않으면 실험이 성립하지 않는다.
3. **진짜 궤적도 도로망 위에서 만든다**(`_simulate_truth_net`). `gen_timelines`
   쪽은 `net=None` 고정이라 도로망을 켜도 궤적은 연속 공간 워커를 탄다 — 아래
   한계 3의 원인 경로를 그대로 타므로, 이 모드에서는 궤적 생성부를 바꿔야 한다.

고정의 대가: 반경 밖으로 나갈 워커가 그래프 경계에 갇힌다. 관측된 이탈거리
90분위가 2.9km 라 5km 로 대부분 덮이지만 먼 꼬리는 잘린다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `run_curve.py` | 타임라인 생성(진짜 궤적 + 제보열) → 네 전략 평가 → `curve.jsonl` |
| `strategies.py` | 비교군 4종의 셀 선정 |
| `analyze.py` | 집계 → 마크다운 표(곡선·비용 정합 비교) |
| `results/` | 실행 결과 문서 |

타임라인 생성 부품(제보 품질 혼합·궤적 표집·위치 노이즈)은
`../d3_threshold/gen_timelines.py` 를 그대로 재사용한다. 그 값들은 2026-07-25/26
파일럿으로 교정된 것이라 다시 만들면 교정이 사라진다. 다만 제보 처리 루프는
복제했다 — 그쪽 반환값에 `current_poa` 가 없고, 시그니처를 바꾸면 측정을 마친
D3 실험의 재현성이 흔들리기 때문. **로직을 고칠 일이 생기면 양쪽을 함께 고칠 것.**

## 비교군 4종

| 전략 | 확률 모델 | 제보 반영 | 커버리지 노브 |
|---|---|---|---|
| `none` | 없음 | — | 없음(항상 0셀) |
| `blanket` | 없음(물리 도달 반경 `v_max×t` 전체) | 없음 | 없음(항상 전체) |
| `stat_only` | Koester 로그정규 거리 × 균등 방향 | **없음** | 있음 |
| `ours` | Phase2 파이프라인 POA | **있음** | 있음 |

`stat_only` 는 거리 표집에 운영과 같은 `radius.sample_distance_km` 을 쓴다.
거리 분포를 공유시켜야 두 전략의 차이가 **동역학(6전략 보행·도로망)과 제보
반영이 있는가** 하나로 좁혀진다. 거리 분포까지 다르게 두면 이득의 원인이
분해되지 않는다.

POA 기반 두 전략의 셀 선정은 운영 함수(`alerts.select_alert_cells`)를 그대로
호출한다. 운영과 다른 규칙으로 잰 곡선은 제안서에 인용할 수 없다.

## 평가 규약

- 평가 시점은 타임라인 종료 시각 하나(`d3_threshold` 와 같은 규약).
- **hit** = 그 시점 진짜 위치 셀이 알림 셀 집합에 포함됨.
- 네 전략은 **같은 타임라인·같은 제보열·같은 시드** 위에서 평가된다. 바뀌는
  것은 셀 선정 방식 하나뿐이다.
- 정답 라벨 균형을 맞추지 않는다(`d3_threshold` 와 다른 점). 발견율은 자연
  발생 비율 그대로 재야 의미가 있다.

### 비용 정합 비교

전략마다 셀 수가 자유롭게 움직이므로 "커버리지 0.8 끼리" 견주면 비용이 다른
것을 비교하게 된다. 그래서 `ours` 가 각 커버리지에서 쓴 셀 수 k 를 다른
전략에 그대로 주고 비교한다.

- `stat_only_at_k` — 통계 POA 의 **상위 k 셀**(커버리지 격자로 근사하지 않는다.
  근사하면 격자 간격만큼 항상 stat_only 쪽이 과소평가된다).
- 무차별 — 확률 순위가 없어 상위 k 를 고를 수 없으므로, 도달 반경 안에서
  무작위 k 셀을 고른 것과 같다고 보고 기하적 기대값 `k / 반경 내 전체 셀` 로 계산.

## 한계 (인용 시 반드시 함께 적을 것)

1. **hit 는 발견율의 상한이다.** 알림을 받은 시민이 실제로 발견할 확률(POD)을
   1로 놓았다. 실제 발견율은 이보다 낮다.
2. **순환 논법이 부분적으로 남아 있다.** 진짜 궤적을 우리 시뮬레이터
   (`simulation.run_monte_carlo`)가 만든다. 따라서 `stat_only` 대비 `ours` 의
   우위는 구조적으로 과대평가된다. 이 곡선은 **예측 성능의 증거가 아니라 알림
   전략 효율의 비교**로만 쓴다.
   - 완화된 부분: 진짜 궤적은 실제 Koester 파라미터 + 전략 혼합으로 걷고,
     예측은 스텁 prior 로 따로 계산한다. 즉 "진짜 위치"와 "우리 믿음"은 같은
     엔진을 쓰되 같은 난수를 공유하지 않는다.
   - 남는 부분: 보행 동역학의 **가정 자체**는 공유한다. 실제 치매 실종자가
     6전략 ABM 과 다르게 움직인다면 그 오차는 이 실험에 잡히지 않는다.
3. **셀 수는 발송 인원의 대리값이다.** 실제 인구 분포·앱 보급률을 쓰지 않았다.
   셀당 인구가 균등하다는 가정이 들어 있다.
4. **정답 궤적이 통계 분포보다 짧다.** 연속 공간 워커(`simulation._walk`)가 Koester
   표본을 경로 길이로 소비해, 최종 변위가 통계 기대의 29~47% 에 그친다(2026-08-04
   실측). 도로망 워커에는 변위 기준 종료 교정이 있으나 연속 공간 워커에는 없다.
   `--roadnet` 으로 켜면 55~65% 로 줄지만 **완전히 사라지지는 않는다** — 남은
   원인은 미확인(고정 그래프 반경 경계 / 스텝 상한 300 / `staying_put`·
   `backtracking` 감쇠 계수가 후보).
   **인용은 도로망 켠 쪽(`curve_roadnet.jsonl`)을 쓴다.** 대조는
   `results/discovery_curve.md` 의 "두 모드의 차이".
