## 질문

같은 사건, 같은 시간에서 돌아오길 전체 제품(D)이, 보호자 답변 없이 같은 제품을 돌린 경우(B)보다 합성 정답 위치를 같은 알림 면적에서 더 자주 포함하는가? 또는 더 좁은 지도로 더 자주 포함하는가?

## 비교

| 구성 | 입력 | 실행 |

| B | 나이·유형·집·신고 위치/시각·신고 문장. 보호자 답변·등록 장소 없음 | main 제품 함수. 개인 정책이 없으므로 main이 기존 보행(dem5 포함)을 선택 |

## 평가 실행 전 변경 기록 (개발 실행 중 검토 결과, 평가 자료는 보지 않음)

1. 재시작 때 원장 재생이 `model` 대신 `model_requested`를 읽도록 수정. 같은 분할의 모든 샤드 원장을 사람 단위로 다시 센다(재시작 후 사람별 상한 유지).
2. 보행 시작 표식 추가: 표식만 있고 결과가 없으면 재호출하지 않고 `interrupted_walk` 실패로 저장.
3. 최초 샤드 수를 고정하고 다른 샤드 수로 다시 띄우면 멈춘다.
4. 준비 중단 시 D만 실패로 기록하고 B는 실행. 채점기는 기록된 실패를 대기 중이 아닌 실패로 센다(포함 실패, 면적 미확정).
5. 평가 분할은 별도 코드 폴더(`code_evaluation`)로 올린다. 개발 4명은 첫 묶음으로 실행됐다.
위 변경은 재시작·중단이 없으면 결과에 영향이 없다. 판정 규칙·지표·정답은 바꾸지 않았다.

(개정 3, 평가 1차 실행 5분 만에 중단) 신고 시각 입력을 운영과 같은 형식으로 바꿨다. 합성 자료의 시각은 한국 시각 의도의 naive 값인데, UTC 서버에서는 SAR 입력이 +9시간(10:00→19:00)으로 보였다. 이제 실행기는 `+09:00`을 붙여 앱처럼 절대 시각을 보내고, 스키마가 서버 로컬 naive로 바꾼다. 사전 검사에서 SAR·준비가 읽는 한국 시각이 작성 시각과 같은지 확인한다. 중단된 1차 실행(F05–F10 준비 일부, 외부 호출 54회 시도)은 `aborted_eval_r1/`에 보존하고 채점하지 않는다. 개발 4명은 이전 형식으로 실행됐다(실행 가능성 확인용).
