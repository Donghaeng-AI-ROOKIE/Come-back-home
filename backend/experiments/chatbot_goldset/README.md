# 챗봇 추출 골드셋 (Phase 0 온보딩)

챗봇이 보호자 자유 발화에서 **페르소나를 얼마나 정확히 추출하는가**를 사람 정답표로
평가한다. `axis_goldset`(축 점수 채점 골드)의 챗봇 추출 버전 — 독립성 원칙을 그대로 따른다.

## 무엇을 재나 — 추출(understanding)만

챗봇의 LLM(Mi:dm) 일은 둘: (1) 자유 발화 → 구조화 **추출**, (2) 질문 **작문**.
작문 품질은 주관적이라 골드로 못 매긴다. 이 골드셋은 **추출**만 채점한다:
- 기본필드(이름·나이·유형)
- 끌림점(라벨·지역·**evidence 등급**·place_type)
- 축 근거(어느 axis_field 에 근거가 있어야 하나)
- 정정 반영(있는 시나리오만)

## 독립성 원칙 (골드셋의 생명)

**판정자는 Mi:dm 출력을 보기 전에, `01_추출_기준표.md`와 `02_시나리오_대화.md`만
보고 `03_정답표_v0.md`를 채운다.** axis_goldset 03 문서의 교훈 그대로 —
"결과를 열람하면 독립성을 잃는다". 채운 사람·날짜를 반드시 기록한다.
설계자(작성 모델)는 정답을 채우지 않는다(작성자=평가자 문제 회피).

## 절차

1. 판정자가 **01 기준표**를 숙지한다.
2. **02 대화**만 읽고(챗봇 실제 질문·모델 출력 금지) **03 정답표**를 채운다.
   - 애매하면 "애매" 열에 대안과 이유를 적는다 → 회의 합의 안건.
   - 근거 부족은 **판정불가**로 명시(빈칸 금지).
3. 채운 03 을 하네스 기대치로 변환한다(기계적 전사, 판단 아님).
4. 하네스로 Mi:dm 을 N회 돌려 03 대비 채점 → 성능 수치(수집률·evidence 정확도·
   축 커버리지 ± 신뢰구간).

## 하네스 연동

`02` 의 보호자 발화 = 하네스 시나리오의 `answers`(챗봇이 질문을 생성하면 responder 가
이 발화들로 답한다). `03`(채워진 뒤) = 시나리오의 `expected`. 채점은
`experiments/chatbot_eval/scorer.py` 가 그대로 담당한다. 지오코딩 혼입을 피하려
**수집률**(좌표화 이전)로 성능을 읽고, 반영률은 인프라 지표로만 본다.
