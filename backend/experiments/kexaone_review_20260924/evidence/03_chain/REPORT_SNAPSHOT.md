# K → SAR + RAG 결합 및 시간별 OSMnx 실험 결과

2026-09-22 · 승인 범위 실행 완료 · 합성 사례 탐색 실험 · 운영 앱 변경 없음

## 판단

현재 만든 K 사실 정리 → SAR 판단 연결은 바로 도입하지 않는 편이 타당하다. K 정리의 구조 오류뿐 아니라 관찰 여부를 반대로 표시하는 의미 오류가 있었고, 정리된 입력을 받은 SAR도 개인 관찰을 최종 이동 파라미터에 일관되게 반영하지 못했다. 기존 K 단독에서 관찰했던 머무름/지속 이동 구분도 결합 후에는 약해졌다. 이것은 이 프롬프트·스키마·연결 방식의 결과이며, K와 SAR의 모든 결합이나 SAR의 학습 지식 전체를 부정하는 결과가 아니다.

시간별 변화는 확인됐다. 세 구성 모두 1→2시간과 2→4시간에서는 경로·분포가 달랐지만, **4→6시간에서는 324쌍 모두 경로와 확률 분포가 정확히 같았다.** 따라서 이번 조건에서는 모델 교체만으로 시간에 따른 갱신 문제를 해결할 수 없다.

## 실행한 범위

- 6개 가상 사건 원형 × A/B/C 관찰 조건 × 2회 생성. A와 C는 의미가 같은 재서술, B는 행동 정보를 바꾼 조건이다.
- 신규 K 사실 정리 36회 + SAR 초기 성향 판단 36회 = 72회. HTTP 응답 모두 수신, 재시도 0회. K에는 원문 정리만 맡기고 RAG를 주입하지 않았으며, SAR에는 원문·통과한 K 정리·기존 동결 RAG를 함께 제공했다.
- 기존 SAR+RAG, K+RAG 단독 응답 72개와 단독 1시간 OSM 결과 216회를 재사용했다. 신규 임베딩·지오코딩·지도 다운로드 0회.
- 정릉의 동일 5km OSMnx 캐시, 같은 출발지·가상 장소·시드 41/73/109, 각 500워커. 새 보행 1,080회·540,000워커 실행. 기존 포함 분석 1,296회·648,000워커 실행.
- 모든 시간에서 초기 prior 고정. 마음 재해석 OFF인 statistical MC에도 개인 prior는 반영된다. 실제 서비스의 agent/statistical 최종 결합 지도나 운영 자동갱신 스레드 전체를 시험한 것은 아니다.
- K 최대 출력 900토큰, SAR 700토큰, temperature 0.2, thinking OFF, timeout 30초. 기존 보행 규칙·Koester·반경 후처리는 변경하지 않았다.

## 1. K 사실 정리 단계가 먼저 보완되어야 함

36건 중 23건이 구조·인용 검증을 통과했고 13건은 정리를 버리고 원래 SAR 입력으로 돌아갔다. 실패는 최상위 JSON 객체 대신 배열 등 지정하지 않은 형태를 반환한 10건, 인용문과 노트 위치가 맞지 않은 3건이다. 후자의 한 건은 노트 번호 범위 오류도 함께 있었다. 13건 모두 보행·성공률 분모에 포함했다.

더 중요한 문제는 구조를 통과한 출력에도 있었다. 저장된 출력의 AI 수동 검토에서 **23건 중 16건에 명시적 긍정 관찰을 `not_observed`로 분류한 사례**를 확인했다. 이 숫자는 독립 전문가 평가 점수나 일반 모델 정확도가 아니다.

> F01_A_chain_0: “최근 두 달 동안 혼자 나서면 시장 쪽으로 걷는 모습을 여러 번 봤다.”를 정확히 인용했지만 `evidence_status: not_observed`로 분류했다.

동일한 문제가 최근 이동 방향, 공장 출근 행동, 같은 길 반복, 머무름·지속 이동 등에서 나타났다. 원문 문자열이 일치하는지만 검사하면 의미 반전은 통과한다. 이번에 작성한 분류 프롬프트의 필드 정의·예시와 의미 검증도 충분하지 않았다는 의미다. 특히 하나의 인용문에 관찰된 행동과 말하지 않은 의도가 함께 있을 때 무엇에 대한 부정인지 분리하는 설계가 필요하다. 이 상태의 보조 정보를 그대로 전달했으므로 이상적인 K→SAR 조합의 성능을 공정하게 측정했다고 볼 수 없다.

구조가 통과한 23건만 따로 유리하게 골라 최종 성능으로 보고하지 않았다. F03은 6건 전부 K 정리가 탈락했으므로, 해당 결과를 성공적인 결합의 효과라고 읽으면 안 된다.

## 2. 최종 성향과 움직임에서 나타난 결과

SAR의 최종 성향은 36건 모두 운영 파서·후처리를 거쳐 생성되어 기본 prior 폴백은 없었다. 다만 36건 모두 코드펜스를 포함했고, 전략 합계 오류 10건과 장소 라벨 계약 오류 7건이 있었다(중복 가능). 코드펜스는 기존 운영 파서로 처리했으므로 모든 응답이 unusable했다는 뜻은 아니다.

아래는 “길을 헤맬 때 근처에 멈춰 머무는 사람(A)”과 “멈추지 않고 계속 걷는 사람(B)”의 1시간 결과다. 각 값은 2회 생성 × 3시드, 3,000워커의 평균이다.

| 구성 | A: 근처 종료 | B: 근처 종료 | A−B |
|---|---:|---:|---:|
| SAR + RAG | 17.43% | 17.77% | -0.33%p |
| K + RAG | 33.07% | 17.73% | +15.33%p |
| K 정리 → SAR + RAG | 17.50% | 16.50% | +1.00%p |

근처 종료는 출발지 200m 이내의 최종 위치다. 실제 정지·휴식 시간을 측정한 것이 아니다. K 단독은 이 두 관찰 조건을 크게 구분했지만, 결합은 SAR 단독과 비슷한 수준으로 차이가 작았다. K가 정리를 통과한 F05_A_chain_0에서도 SAR의 최종 staying_put은 약 5.6%였으며, 설명은 머무름을 일반적인 배회·익숙 장소 방문으로 해석했다. 따라서 단순히 정보를 한 번 더 정리하는 것으로 개인 행동과 이동 전략의 연결이 해결되지는 않았다.

다른 사례도 함께 확인했다. 최근 시장 지향을 공원 지향으로 바꾼 F01에서 결합의 공원 구역 진입률은 2.43→2.50%로 변화가 작았다. 과거 회상에서 최근 출근 의도가 생기는 F02는 공장 구역 진입률이 13.60→16.40%로 증가했지만, 이 한 사례만으로 결합이 더 낫다고 일반화할 수 없다. 반복 경로 F04의 노드 재방문율은 결합 A 24.47%, B 25.30%로, 동일 구간 반복 관찰을 더 높은 재방문으로 뚜렷하게 구현하지 못했다. 이러한 경로 지표는 임상 정답이 아니다.

설명에서도 근거 추가가 남았다. F04_B_chain_1과 F06_B_chain_1의 SAR 출력은 보호자가 여러 번 향하는 것을 관찰했다는 입력을 “과거 실종 때 실제 발견된 곳”이라고 바꾸었다. F02_A_chain_1은 최근 출근 행동의 미관찰을 현재 의도가 없다는 뜻으로 해석했다. 따라서 K가 앞단에 있다는 사실만으로 SAR의 근거 충실성이 보장되지는 않았다.

## 3. 시간별 경로·확률지도

| 시간 비교 | 경로가 다른 쌍 | 확률 분포가 다른 쌍 |
|---|---:|---:|
| 1→2시간 | 324 / 324 | 324 / 324 |
| 2→4시간 | 324 / 324 | 324 / 324 |
| 4→6시간 | 0 / 324 | 0 / 324 |

쌍 하나는 같은 출력·같은 시드·같은 도로망의 두 시점이다. 경로의 전략·노드 시퀀스 내용 해시와 확률 셀 값을 비교했으며, 파일의 생성 시각이나 화면 모양만 보고 판단하지 않았다.

전체 사건·관찰·반복·시드의 평균 출발지 이탈 거리:

| 구성 | 1시간 | 2시간 | 4시간 | 6시간 |
|---|---:|---:|---:|---:|
| SAR + RAG | 0.558km | 0.592km | 0.602km | 0.602km |
| K + RAG | 0.524km | 0.560km | 0.574km | 0.574km |
| K 정리 → SAR + RAG | 0.555km | 0.592km | 0.603km | 0.603km |

현재 표집 상한은 `min(통계 p95, max(0.5km, 4.32km/h × 경과시간))`이다. 이번 108개 성향 출력은 후처리 후 모두 같은 μ=0.095, σ=1.48이므로 통계 p95≈12.548km, 포화 시점≈2.905시간이다. 1시간 상한은 4.32km, 2시간은 8.64km, 4·6시간은 모두 12.548km다. 마음 OFF·성향 고정 조건에서 시간이 더 들어갈 다른 경로가 없으므로, 같은 시드의 4·6시간은 같아진다. 세 모델 모두에서 동일한 현상이 확인되어 모델 고유 문제와 구분된다. **상한은 실제 평균 이동 거리나 모든 워커가 도달해야 할 거리가 아니다.**

초기 시간의 지도 변화도 크기만으로 유효성을 주장할 수 없다. 1→2시간 평균 JS 거리는 구성별 약 0.235~0.244, 2→4시간은 0.213~0.227이었다. 같은 시점에서 시드만 바꾼 평균 JS 거리도 약 0.235~0.275다. 시간 설정이 계산 결과를 바꾼다는 사실은 확인했지만, 그 변화가 표본 변동보다 충분히 크거나 실제 실종자의 시간별 분포에 맞는다는 검증은 아니다. 같은 시드는 난수 소비 순서 변화까지 없애지 않으며, 같은 walker_idx를 시점 사이의 동일 인물로 읽으면 안 된다.

## 4. 기존 보행 근거를 유지하면서 판단할 부분

4·6시간이 같다는 이유만으로 통계 반경을 무한히 키우거나 매번 시드를 바꿔 지도를 다르게 만드는 것은 해결책이 아니다. 기존 Koester 변위 종료·도보 상한·개인 축 우선 후처리에는 기록된 설계 근거가 있다. 이번에는 이를 그대로 유지했다.

사용자가 원하는 “시간이 지남에 따라 현재 예상 위치를 갱신”하는 요구에는, 반경 포화 후에도 상태·이동·머무름과 새로운 관찰이 분포에 어떻게 반영되어야 하는지를 별도로 정의할 필요가 있다. 이동·휴식 시간의 실제 경과와 표본 경로 진행을 구분하고, 기존 종국 변위 통계와 충돌하지 않는 시간 조건부 분포를 검토하는 순서가 타당하다. 이번 실험은 실제 agent 마음 재해석과 새 제보가 있는 경우의 갱신까지 부정하지 않는다.

OSM 그래프는 5km로 고정되어 시간 상한보다 작다. 신규 재생의 bounding-box 경계 150m 이내 접근 비율은 회당 최대 1.6%, 300스텝 도달은 최대 2.6%였다. 이 수치가 낮다고 지도 내부의 모든 누락·단절이나 먼 거리 꼬리 분포가 안전하다고 증명되는 것은 아니다. 전체 1,296회에서 검증한 도로 노드 전이 33,173,560건은 모두 그래프상의 연결이었다.

## 5. 도입 판단과 다음 설계

1. **이번 결합안은 도입 보류.** 13건 폴백, 통과 결과의 의미 오류, 약한 개인 행동 반영 때문에 현재 결과로 성능 개선을 주장할 수 없다.
2. **K 정리 계약부터 오프라인 보완.** 관찰된 행동·의도 없음·관찰하지 못함을 별도 명제로 나누고, 태그 정의와 긍정/부정 예시 및 노트 ID를 명확히 한다. 원문 인용 검증과 별개로 의미 충돌 검토를 설계한다. 기존 실패 자료를 써서 보완하되 다음 평가는 새 holdout을 두어야 한다.
3. **SAR가 개인 정보를 받아들이는 단계는 별도 평가.** 사람이 확인한 사실 정리를 넣는 대조군이 있으면 K 정리 실패와 SAR 적용 한계를 분리할 수 있다. 이번에는 이 대조군이 없었고, SAR 학습에 사용하지 않은 도메인 지식 평가도 수행하지 않았다.
4. **시간별 갱신은 별도 시뮬레이터 과제.** 기존 통계 근거를 유지하면서 시간 조건부 분포·내부 시간·종료 사유·이전 상태 연결의 요구사항과 계측부터 설계한다. 이번에 운영 코드를 바꾸거나 추가 실험을 실행하지 않았다.

이 권고는 이번 저장 출력에 대한 기술적 판단이다. 독립 사람/도메인 검토는 아직 수행하지 않았으며 실제 실종 경로 데이터도 없다. 익숙한 6개 합성 원형을 재사용한 탐색 결과이므로 실제 발견율·정확도 개선으로 쓰지 않는다.

## 6. 사용량과 비용

| 역할 | 호출 | 입력 토큰 | 출력 토큰 | 총 토큰 |
|---|---:|---:|---:|---:|
| K 사실 정리 | 36 | 11,398 | 8,052 | 19,450 |
| SAR 최종 판단 | 36 | 71,671 | 9,503 | 81,174 |

두 단계 합산 평균 응답 시간은 7.62초다. 기존 단독 측정은 SAR 약 4.24초, K 약 3.08초였으나 측정 시점·서버 부하가 달라 동시 성능 비교는 아니다. 신규 보행 재생 프로세스 CPU는 321.93초, 원격 준비·생성 클라이언트·좌표 내보내기를 포함한 계측 CPU 합은 322.86초다. CPU 시간은 서버 총 청구시간 또는 GPU 사용시간이 아니다.

단가·실청구액·지원 차수·GPU 청구시간은 미확인(null)으로 유지했다. 자가호스팅 SAR 토큰은 사용량이며 유료 API 비용으로 중복 환산하지 않았다. K의 정확한 endpoint 내부 모델 revision은 확인되지 않았다. API 144개 시작/종료 이벤트와 자원 이벤트 8개를 공용 원장에 event_id 기준 중복 없이 동기화했다. 이전 실험 토큰은 이번 사용량에 합산하지 않았다.
