# K 프롬프트 v3 실행 결과

2026-09-23 · 승인한 소규모 생성 완료 · 사전 중단 조건에 따라 보행 미실행

## 결론

**v3 프롬프트는 채택 보류.** K 12회 호출은 모두 HTTP 성공했고, 12개 응답 모두 JSON·6전략 합계·허용 장소·등급의 기본 검사를 통과했다. 그러나 저장 응답에 대한 AI 검토에서 명백한 개인 행동 추가가 2개 응답에서 확인되어 사전에 합의한 보행 진입 조건을 통과하지 못했다. 따라서 OSMnx 재생은 0회다. 실패 응답을 제외한 일부 사례만 골라 보행 성과로 보고하지 않았다.

이번 결과는 “명령을 더 자세히 쓰면 문제가 해결된다”는 가설을 지지하지 않는다. 문장을 읽기 좋게 만들거나 JSON을 맞추는 것과 원문의 개인 관찰을 보존하는 것은 다른 문제다. 실험은 알려진 6개 개발 입력이므로 일반화 평가·임상 정확도 평가가 아니다.

## 실행 범위

- F01 A/B: 최근 시장 지향과 공원 지향.
- F05 A/B: 근처 머무름과 지속 이동.
- F06 A/B: 최근 관찰과 최근 정보 부족.
- 각 2반복, K 단독+기존 동결 RAG, 12회. 기존 단일 few-shot 제외, 원문 노트 번호 추가, system 교체.
- temperature 0.2, max_tokens 700, thinking OFF, timeout 30초. 자동 재시도 0회.
- SAR·임베딩·지도·지오코딩·별도 연결 점검 호출 0회. 검색기·RAG 코퍼스·보행 코드는 수정하지 않았다.
- 원문·장소·초기 후처리·개인 축은 기존과 같고 번호만 붙였다. 요청 내용과 응답을 `outputs/`에 저장했다.

## 보행을 중단한 근거

| 출력 | 원문에 있는 정보 | 추가된 개인 행동 |
|---|---|---|
| F01_B_k_v3_1 | 최근 공원 쪽으로 걷는 모습 관찰 | “최근 직진 경향”, “공원 중심의 반복 이동과 직진 경향” |
| F05_B_k_v3_1 | 길을 헤맬 때 멈추지 않고 계속 걷는 모습 관찰 | “방향 전환이나 주변 탐색 없이 직진하는 양상이 반복되었으므로” |

특정 장소 쪽으로 향한다는 것과 경로가 계속 직선이라는 것은 다르다. 계속 걸었다는 원문에도 방향 전환·주변 탐색 여부는 없다. 특히 F05_B_k_v3_1은 이 내용을 가설로 구별하지 않고 관찰된 반복 행동처럼 판단의 근거로 사용했다. v3에는 이 추론을 금지하는 문장이 있었지만 막지 못했다.

2/12는 독립 전문가가 측정한 일반 환각률이 아니다. 이번 저장 출력의 AI 수동 검토에서 명백하게 확인한 중단 근거의 수다. 나머지 10개가 의미적으로 완벽하다는 뜻도 아니다. 예를 들어 최근 정보가 모두 부족한 두 장소에 서로 다른 등급을 부여하는 근거가 약하거나, 높은 비중을 주었다는 설명과 실제 확률 순서가 일치하지 않는 사례가 남았다. reasoning 길이와 정확한 직접 인용 요구도 모든 응답이 지킨 것은 아니다. “기본 계약 12/12”를 “모든 프롬프트 요구 12/12”로 해석하면 안 된다.

## 기존 K 출력과의 파라미터 비교

F05의 최종 staying_put 값은 다음과 같다. **아래 수치는 보행 종료 비율이 아니라 모델이 출력한 전략 가중치**다.

| 구성 | 머무름 A: 2회 평균 | 지속 이동 B: 2회 평균 | A−B |
|---|---:|---:|---:|
| 기존 K+RAG | 30.0% | 5.0% | 25.0%p |
| 새 K v3+RAG | 15.0% | 12.5% | 2.5%p |

두 번째 반복에서는 A와 B의 6개 전략 확률, 장소 가중치, 반경 파라미터가 모두 같았다. 즉 설명은 관찰 내용을 언급했지만, 최종 성향 설정에서는 두 사람의 차이가 사라진 사례가 있었다. 이 값의 차이가 큰 것이 항상 정답은 아니지만, v3가 개인 차이를 더 잘 반영한다는 증거는 되지 않는다. 보행을 수행하지 않았으므로 새 경로·진입률·실제 위치 예측 성능이 개선됐거나 악화됐다고 수치화하지 않는다.

F01과 F06에서는 최근 지향이 명시된 장소를 높은 등급으로 두고 정보 부족을 설명하는 경향은 유지됐다. 반면 과거 관찰이 공통으로 있는 나머지 장소를 중/하로 나누는 충분한 근거는 약했다. 일부 direction_keeping 가중치와 설명도 명시적 직진 관찰 없이 설정되었다. 가능한 시뮬레이션 가설을 남기는 것과 그 행동이 실제 관찰되었다고 쓰는 것을 구분해야 한다.

## RAG를 확인해 찾은 원인 후보

동결 F05 RAG 블록에는 논문 발췌의 “앞만 보고 걸어감”, “주변을 둘러보지 못하고 정면만 보면서 직진”이라는 다른 참여자의 사례가 있었다. 또 별도의 QA에는 “목적 상실형 익숙 거점 순회”라는 해석 문구가 있었다.

새 F05_B_k_v3_0은 이 문헌 사례와의 유사성을 언급했고, F05_B_k_v3_1은 현재 사람에게 직진·주변 탐색 없음이 관찰되었다는 식으로 확장했다. F05_A_k_v3_1의 “목적 상실형 익숙 거점 순회”도 RAG QA 문구와 일치한다. 이는 **문헌의 다른 사람 사례 또는 QA 해석이 현재 사람의 개별 관찰로 섞이는 현상**과 부합한다.

하지만 RAG 유무를 통제한 비교는 이번에 하지 않았다. 그러므로 RAG가 원인이라고 확정하거나, 기존 RAG 전체를 버려야 한다고 결론내리지 않는다. 기존 few-shot을 제외해도 비슷한 문구가 나왔으므로, 이전에 의심했던 few-shot만을 원인으로 설명할 수도 없다. system 변경과 예시 제거를 함께 했다는 한계도 있다.

## 다음에 할 일

현재 v3를 운영에 적용하거나, 같은 실패를 둔 채 36회 보행을 돌리는 것은 권하지 않는다. 먼저 문헌에서 허용할 추론과 개인의 관찰 사실을 분리하는 입력·출력 계약을 정리해야 한다.

다음 유료 실험은 금지 문구를 더 붙인 대규모 재시도보다 **같은 입력·같은 프롬프트에서 기존 RAG 유무를 최소 조건으로 대조하는 설계**가 원인 파악에 도움이 된다. 이 대조는 RAG를 폐기하거나 다시 구축하는 작업이 아니다. RAG가 있을 때만 개인 사실 추가가 늘어나는지, 없어도 같은 오류가 나는지를 확인하려는 것이다. 검색기 변경·코퍼스 삭제·재정렬은 이번 범위에 없고 실행하지 않았다.

자료 구조 측면에서는 보호자 원문 노트와 문헌 발췌에 다른 출처 ID를 붙이고, “개인 관찰 / 문헌상 가능한 가설 / 확인되지 않은 정보”를 구분해 검토하는 후보가 있다. 앞선 영어 태그 분류도 실패했으므로 태그를 다시 추가하면 자동으로 해결된다고 가정하지 않는다. 저장된 실패 사례로 검증을 준비하고, 후속 일반화 평가는 새 사례와 사람 검토를 포함해야 한다. 위 후속 제안은 설계 의견이며 추가 호출을 실행한 것이 아니다.

## 사용량·비용

- K 호출 12회, 입력 20,596토큰 + 출력 3,320토큰 = **23,916토큰**.
- 평균 요청 경과 시간 약 **3.98초**. 단독 과거 실험과 동시 측정이 아니므로 지연 개선을 주장하지 않는다.
- 생성 실행 프로세스 경과 47.99초, Mac mini 프로세스 CPU 약 0.262초. 이는 GPU 시간이나 서버 총 청구시간이 아니다.
- 신규 보행 0회, 재시도 0회. 단가·실청구액·지원 차수는 미확인(null).
- 공용 원장에 API 시작/종료 24개와 자원 세션 2개, 총 26개 이벤트를 중복 없이 동기화했다. 원격 원장도 보존했다.
- endpoint 내부 모델 revision은 미확인. 키·Authorization·원문을 비용 원장에 저장하지 않았다.

## 증빙

`approval.json`은 실행 승인 범위와 소스 해시, `execution_manifest.json`은 실행 환경 확인, `outputs/`는 12개 요청·응답, `review_gate.json`은 전체 출력 검토 및 보행 중단 근거, `analysis.json`은 집계, `verification.json`은 호출량·동기화 검증이다. 모델명 비공개 비교 카드는 `blind_review.md`, 대응표는 `review_key.json`에 별도 저장한다.
