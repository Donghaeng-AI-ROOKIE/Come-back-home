# K-EXAONE 피처별 개인 해석 실험 결과

작성: 2026-09-23. 실행 ID: `KEXAONE_featurewise_v1_20260923`.

## 판단

피처 분리는 계속 발전시킬 가치가 있지만, 이번 출력 그대로 운영에 도입할 근거는 부족하다. 목적지·이동 지속성·경로 형태를 나눠 설명하는 것과, 그 구분이 최종 확률 및 보행까지 유지되는 것은 달랐다. 머무름 조건에서는 유리한 변화가 관찰됐지만, 목적지만 바꿔도 직진·무작위 보행 확률이 함께 변했고, 방향 전환 조건의 반영은 반복마다 달랐다.

따라서 다음 구현 후보는 **SAR·RAG의 일반 행동 가설을 유지하면서 K는 피처별 관찰·가설·미확인을 정리하고, 코드가 검증 가능한 규칙으로 보행 파라미터에 연결하는 구조**다. 이 제안의 성능은 아직 검증하지 않았다. 일반 행동 가설은 개인에게 직접 관찰되지 않았다는 이유만으로 제거하면 안 된다. 다만 일반 가설이 이번 개인에게 관찰된 사실로 바뀌어서는 안 된다.

## 실행 범위와 비교 조건

- 승인: 6개 합성 사례 × 통합/피처별 2조건 × K 반복 2회, 최대 24 API 호출·72 보행.
- 실제: K 24회, 원래 검증 절차로 수치 prior 사용 가능 21개, 보행 63회 × 500명 = 31,500 walker-runs.
- SAR 신규 호출·임베딩·지도 다운로드·자동 재시도 0회. 운영 코드 및 배포 변경 없음.
- 모든 요청에 동일한 기존 SAR 참조 `F06_B_sar_0`와 동일한 기존 RAG 발췌를 사용했다. 이 SAR는 최근 행동 미확인인 관련 기준 사례의 저장 결과이며, 각 새 입력을 SAR에 새로 넣은 결과가 아니다.
- CONTROL: 관찰·가설·미확인·결정·최종 prior의 통합 출력. FEATURES: destination_pull / movement_persistence / route_shape / mobility_range를 나눈 후 통합·prior 출력. 피처마다 별도 호출하지 않았다.
- 두 조건은 프롬프트 및 출력 구조를 함께 바꾼 처리 묶음이다. 순수한 JSON 모양 효과나 특정 문구의 효과를 따로 분리한 실험은 아니다.
- 저장된 OSM 도로망, 가상의 세 장소, 동일 신체 축·반경 정책·시드 41/73/109, 1시간·마음 재해석 OFF. 시드 3개는 동일 K 출력에 대한 보행 반복이다.

| 사례 | 최근 방향 | 길을 잃었을 때 | 갈림길 행동 |
|---|---|---|---|
| C01 | 시장 | 가까이 머무름 | 미확인 |
| C02 | 공원 | 가까이 머무름 | 미확인 |
| C03 | 시장 | 계속 걷기 | 미확인 |
| C04 | 공원 | 계속 걷기 | 미확인 |
| C05 | 시장 | 계속 걷기 | 방향을 거의 바꾸지 않음 |
| C06 | 시장 | 계속 걷기 | 좌우로 자주 방향 전환 |

모든 사례에 과거 세 장소로 반복 지향한 이력이 같다. 실제 신체 능력 차이를 조작하지 않았으므로 mobility_range의 효과는 평가할 수 없다.

## 비교 가능한 결과

실패 응답은 삭제하지 않았다. 아래 조건 간 비교는 양쪽 구성에 같은 사례 쌍·K 반복 번호·보행 시드가 모두 있는 부분만 사용했다. C01을 포함하는 두 비교에는 공통 K 반복이 없어 우열을 판단하지 않았다. 전체 출력과 조건별 나머지 진단은 `analysis.json`, `contrasts.json`에 남아 있다.

### 1. 머무름과 계속 걷기: 피처별 출력의 반응이 더 컸지만, 하나의 비교만 가능

공원으로 향하는 C02와 C04, K 두 번째 반복, 보행 시드 3개 평균이다.

| 지표 | 통합 출력 | 피처별 출력 |
|---|---:|---:|
| 머무름 입력의 staying_put | 0.10 | 0.20 |
| 계속 걷기 입력의 staying_put | 0.05 | 0.05 |
| 머무름 입력: 출발지 200m 내 종료 | 19.47% | 26.07% |
| 계속 걷기 입력: 출발지 200m 내 종료 | 16.07% | 17.27% |
| 두 입력 간 차이 | 3.40%p | 8.80%p |

피처별 출력에서 입력 차이가 위치 분포에 더 크게 전달된 사례다. 그러나 출발지 주변 종료는 실제 정지 시간이나 휴식 확률이 아니다. 머무름만 바꿨는데 피처별 출력의 공원 상대 가중치도 0.429→0.333, direction_keeping도 0.10→0.30으로 달라졌다. 다른 다섯 전략끼리 재정규화한 분포의 TV 차이는 통합 0.143, 피처별 0.191이었다. 이는 단순히 staying_put을 바꾼 정규화 효과만으로 설명되는 변화가 아님을 보여주지만, 숫자 차이 자체가 전부 오류라는 뜻은 아니다. 변화 근거를 따로 검토해야 한다.

### 2. 목적지만 시장→공원으로 변경: 피처별 방식의 장점 확인 안 됨

계속 걷기·경로 미확인인 C03과 C04, K 반복 2개 × 보행 시드 3개 평균이다.

| 지표: 시장 조건 → 공원 조건 | 통합 출력 | 피처별 출력 |
|---|---:|---:|
| 공원 상대 가중치 | 0.333 → 0.429 | 0.310 → 0.333 |
| 공원 구역 진입 비율 | 2.17% → 3.30% | 2.20% → 2.37% |
| direction_keeping | 0.347 → 0.375 | 0.350 → 0.250 |
| random_walk | 0.099 → 0.100 | 0.075 → 0.175 |

피처별 출력은 공원 조건에서 두 반복 모두 세 장소를 모두 '상'으로 출력했다. 공원에 더 끌린다는 설명을 썼어도 정규화 후 장소 가중치는 동일해졌다. 반면 목적지 외 경로 전략은 크게 바뀌었다. '특정 장소로 간다'와 '한 방향으로 직진한다'가 다른 특성이라는 구분이 최종 통합에 안정적으로 유지되지 않았다.

구역 진입은 가상 장소 중심 120m 안으로 저장 경로 노드가 한 번 이상 들어간 비율이다. 발견 정확도·목적지 도달 확률은 아니다. 도로 접근성·경로 구성의 영향도 포함된다.

### 3. 직진과 잦은 방향 전환: 피처별 방식에서 작은 차이, 반복 간 불안정

C05와 C06, K 반복 2개 × 보행 시드 3개 평균이다.

| 지표: 직진 관찰 → 잦은 전환 관찰 | 통합 출력 | 피처별 출력 |
|---|---:|---:|
| 최종 direction_keeping | 0.325 → 0.325 | 0.297 → 0.225 |
| 최종 random_walk | 0.075 → 0.200 | 0.074 → 0.300 |
| 갈림길 좌우 전환 보조 비율 | 49.11% → 48.62% | 49.48% → 50.76% |

피처별 출력은 평균에서 기대 방향으로 움직였지만, 첫 K 반복은 C05와 C06의 direction_keeping이 모두 0.30이었다. 두 번째 반복에서만 원출력 0.30→0.15로 줄었다. 따라서 '방향 전환 특성을 안정적으로 구현했다'고 말하기 어렵다.

좌우 전환 지표는 원래 코드의 turn_fraction과 별개다. 원 지표는 이동 벡터의 길이 변화도 전환으로 셀 수 있어, 현재 결과를 읽기 전에 보조 정의를 별도 기록했다. 저장 도로의 진입·진출 접선 각도를 사용해, 되돌아가는 노드를 제외한 선택지가 2개 이상인 갈림길에서 45도 이상 150도 미만으로 꺾인 비율을 계산했다. 방문하는 갈림길 자체가 조건별로 달라지므로 동일 갈림길 선택 실험도, 임상적인 전환 기준도 아니다. 자세한 정의와 분모는 `방향전환_보조지표_정의.md`, `replay_diagnostics.json`에 있다.

## 해석과 수치 통합에서 발견한 문제

1. **지속 보행을 직진 관찰로 바꾸는 오류.** `C03_FEATURES_1`은 입력에서 방향 전환 여부를 관찰하지 못했다고 했는데, route_shape 결론에 '직진하는 경향이 관찰'됐다고 적었다. 일반 가설 제시는 허용되지만, 이 표현은 개인 관찰로 승격한 것이다.
2. **설명과 숫자 방향 불일치.** 사용 가능한 FEATURES 10개 중 7개에 한 건 이상 있었다. 비교 가능한 전략 변경 선언 33건 중 9건이 고정 SAR 참조 대비 원출력 숫자와 불일치했다. 예: `C05_FEATURES_1`은 landmark_seeking을 높인다고 쓰고 0.10→0.00으로 낮췄다. 이 지표는 CONTROL에 같은 action 필드가 없으므로 두 구성의 오류율 비교로 쓰지 않는다.
3. **과거 이력 근거의 누락.** 사용 가능한 FEATURES 10개 모두 N0가 personal_evidence에 포함되지 않았다. 일부 다른 문장에서는 과거 이력을 언급하므로 '과거 정보를 완전히 잊었다'는 뜻은 아니다. 지정한 근거 추적 규칙을 충족하지 못했다는 뜻이다.
4. **같은 입력에서도 변동.** FEATURES C03·C04는 두 K 응답의 전략 TV 차이가 각각 0.20이었다. 두 번만으로 안정성 우열이나 유의성을 주장할 수 없다.
5. **RAG 출처와 적용의 구분.** R0는 일부 보호자의 직진·배회 관찰, R1/R3는 기존 코퍼스의 QA다. 이들을 모든 개인에게 적용되는 법칙이나 이번 개인의 관찰로 취급하면 안 된다. 이번 실험은 RAG를 고정했으므로 RAG 사용 유무의 효과를 판단하지 않았다.

수치 감사는 원출력과 시뮬레이터 최종 입력을 구분했다. 기존 코드가 전략 확률 0을 0.02로 올린 뒤 정규화하는 경우가 2개였다(C03_CONTROL_1, C05_FEATURES_1). 이 차이는 K의 해석 변화가 아니다. 초기 replay 검토에는 최종 입력 기준 8/33으로 기록되었고, 원출력 기준 감사 결과는 **9/33**이다. 수정 근거는 `semantic_review_postcheck.json`에 보존했다. 원래 검토·응답·보행 결과는 변경하지 않았다.

## 형식 오류와 해결

원래 검증 절차에서 prior를 사용할 수 없던 3개:

| 응답 | 원인 | 로컬 복구 |
|---|---|---|
| C01_CONTROL_0 | JSON 뒤 닫는 중괄호 1개 과다 | 유일한 완결 객체 뒤의 중괄호 제거 |
| C02_FEATURES_0 | 코드블록 + 닫는 중괄호 1개 과다 | 바깥 코드블록과 과다 괄호 제거 |
| C01_FEATURES_1 | integration·prior가 features 내부에 들어감 | 충돌 없이 유일한 두 필드의 위치 이동 |

세 응답 모두 finish_reason은 stop이었다. 토큰 제한에 의해 응답이 잘렸다는 증거는 없었다. 프롬프트의 JSON 지시만으로 응답 구조를 보장하지 못했고, 원래 파서는 뒤의 과다 괄호와 잘못된 중첩을 처리하지 않았다.

사용자의 추가 질문에 따라 **새 API 없이** `format_guard.py`와 `check_format_guard.py`를 만들었다. 저장된 24개 원문을 그대로 보존하면서 필요한 표면 형식만 정리하면, 24개 모두 동일 prior 검증기의 수치 입력 검사를 통과했다. 누락된 숫자나 근거를 만들어 넣지 않았다. 중복 키·이어 붙인 복수 객체·비정상 숫자·누락된 전략·잘못된 장소 등 11개 부정 검증도 통과했다.

그러나 전체 규약을 통과한 것은 5개다. 나머지에는 근거 커버리지 부족, 설명 개수 초과 등의 문제가 남는다. 수치 입력 사용 가능과 해석 타당성은 별도 상태다. 복구된 3개를 추가 보행하지 않았고, 위 비교표는 원래 절차의 63회 결과다. 복구 코드는 운영에 연결하지 않았다.

권장 처리 순서: 원문 및 usage 저장 → 보수적인 형식 정리 → 스키마/라벨/수치 검증 → 근거·설명과 숫자 일치 검사 → 사용 가능 여부 판정. 다음 API 변경에서는 공급자와 해당 endpoint가 지원하는 경우 schema-constrained output을 검토할 수 있으나, 이번에는 지원 여부 검증 호출이나 적용을 하지 않았다. 형식 지시를 반복하는 것만으로 해결됐다고 판단하지 않는다.

## 다음 구현 후보 — 미실행

- K의 출력은 피처별 관찰·일반 가설·불확실성·근거 참조에 집중하고, 최종 전략 숫자와 증감 설명을 동시에 자유 생성하는 부분을 줄인다.
- SAR 기준과 도메인 가설을 바탕으로 코드가 개인 정보에 따른 변경을 제한적으로 적용한다. 목적지는 상대 장소 가중치, 지속성은 머무름/이동 구성, 갈림길 관찰은 방향 선택에 우선 연결한다. 피처 간 상호작용은 이유와 규칙이 있을 때만 허용한다.
- 물리적 능력 정보가 없으면 기존 신체 축·반경 근거를 유지한다. 모든 미관찰 행동을 0으로 만드는 방식은 피한다.
- 변경 선언은 모델이 별도로 쓰는 대신 실제 변환 전후 값에서 코드가 생성한다. 미확인을 관찰 사실로 승격하는 것은 별도 차단한다.
- 장소의 과거 친숙함과 최근 상대 선호를 구분할 필요가 있다. 모두 '상'이어도 최근 한 장소로 향한다는 차이를 표현할 수 있어야 한다. 그 표현/변환 방식의 효과는 새 비교 설계로 검증해야 한다.
- 다음 비교에서는 형식 처리 규칙을 먼저 고정하고 두 조건에 동일하게 적용한다. 새 모델 호출·보행은 범위와 비용을 제시한 별도 승인 후 실행한다.
