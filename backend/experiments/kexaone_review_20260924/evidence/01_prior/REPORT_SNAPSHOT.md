## 1. 실행 범위

| 항목 | 수행 내용 |
|---|---|
| 독립 사례 | 6개 원형 |
| 입력 변형 | A 원래 관찰 / B 핵심 관찰 변경 / C A와 같은 의미의 재서술 |
| 모델 생성 | 각 입력을 SAR·K 각각 2회, 총 72회 |

108,000개 워커 실행은 독립 환자 표본 수가 아니다. 사람/사건 수준 독립 원형은 6개뿐이다. 각 조건의 본문 수치는 생성 2회 × 시드 3개, 총 3,000워커의 평균이다. 동일 시드라도 전략에 따라 난수 소비가 달라져 개별 워커를 일대일 대응한 실험은 아니다.

SAR는 배포 모델 ID `exaone-sar`, K는 기존 KEXAONE 환경변수가 가리키는 FriendliAI endpoint ID를 사용했다. K endpoint ID만으로 정확한 모델 revision을 증명할 수 없어 미확인으로 기록했다. 배포 앱 코드·인덱스 SHA-256은 `manifest.json`에 저장했다.

## 2. 관찰이 실제 움직임으로 이어졌는가

### F05 — 근처에 머무름 ↔ 계속 걷기

입력 A: 길을 몰라 헤맬 때 가까운 곳에 멈춰 머무는 모습을 여러 번 관찰.
입력 B: 같은 상황에서 멈추지 않고 계속 걷는 모습을 여러 번 관찰.

| 지표 | SAR A | SAR B | K A | K B |
|---|---:|---:|---:|---:|
| 최종 staying_put 비중 | 5.2% | 4.0% | 30.0% | 5.0% |
| 목격지 200m 이내 종료 | 11.9% | 10.9% | 23.8% | 11.6% |
| 평균 직선 변위 | 0.505km | 0.520km | 0.418km | 0.554km |
| 평균 누적 경로 길이 | 2.266km | 2.307km | 1.799km | 2.689km |

K에서는 명시된 관찰의 차이가 보행 집계에 더 크게 나타났다. 다만 staying_put 구현은 실제 정지 시간을 측정하는 모델이 아니라 목표 변위를 줄이는 규칙이다. 따라서 ‘23.8%가 쉬었다’고 해석하면 안 된다.

또한 K B의 첫 응답은 입력의 ‘계속 걷기’를 ‘직진’, ‘주변 인식 없이 한 방향’으로 확장했다. 방향 유지 비중 35%의 적절성까지 입증된 것은 아니다. 좋은 방향의 변화와 근거 없는 상세 해석을 함께 평가해야 한다.

K는 최근 관찰의 대상이 바뀌면 상대적 끌림의 순서도 뒤집혔다. SAR는 B에서 두 장소를 같은 비중으로 처리했다. 구역 진입에는 우연한 통과도 포함되므로 ‘그곳을 목표로 선택한 비율’과 같지 않다.

## 3. 모델을 바꿔도 해결되지 않는 연결 지점

1. **초기 이동 반경이 후처리에서 사라진다.** 이번 고정된 `mobility_transport_capacity=0.5`가 모든 조건의 radius를 같은 기준값으로 설정했다. K 응답 8개, SAR 응답 1개에서 모델의 상/하 판단이 최종값에서 바뀌었다. F05의 K ‘하→상’ 해석도 최종 radius는 동일했다. 따라서 F05 경로 차이를 반경 해석 개선의 효과라고 말할 수 없다.
2. **backtracking의 이름과 실제 동작에 간극이 있다.** 변위를 0.3배로 줄이고 진행 방위를 유지하는 구현이며, 이전 노드 즉시 회귀에는 낮은 가중치를 준다. 짧은 구간을 되풀이하는 관찰이 전략 비중에 반영돼도 실제 왕복 궤적이 보장되지 않는다.
3. **목적지를 알아보지 못하고 지나치는 행동은 P 단독으로 평가할 수 없다.** 해당 동작은 마음 재해석에서 나온 혼란 상태를 소비하는 경로에 있다. 이번 결과의 전체 경로 길이 차이를 인식 실패 재현으로 대체해 읽지 않는다.

참조 코드: 배포본 해시는 `manifest.json`의 `llm/exaone.py`, `phase2/guardrail.py`, `phase2/simulation.py`. 로컬 대응 파일은 `본선/Come-back-home/backend/app/` 아래에 있다. 실험에서 보행·후처리 코드는 변경하지 않았다.

## 4. 안정성·형식·근거 충실성

| 항목 | SAR | K |
|---|---:|---:|
| HTTP 성공 | 36/36 | 36/36 |
| 운영 파서·후처리로 사용 가능한 prior | 36/36 | 36/36 |
| JSON 객체만 출력하는 엄격한 계약 충족 | 0/36 | 33/36 |
| 코드블록 사용 | 36 | 0 |
| 전략 확률 합 오류 | 8 | 3 |
| 미등록 장소 라벨 등 불일치 | 3 | 0 |
| 평균 요청→후처리 시간 | 4.24초 | 3.08초 |
| 최대 요청→후처리 시간 | 5.74초 | 4.21초 |

오류 종류는 중복된다. SAR의 0/36은 생성 실패율이 아니다. 기존 앱은 코드블록 속 JSON을 추출하며, 확률 합을 정규화하고 미등록 장소를 정리한다. **두 모델 모두 36개 전체를 재생했다.** 처음 실행기에 있던 엄격 계약 기준 제외 조건은 첫 보행 전에 운영 파서 기준으로 수정했으며, `implementation_notes.json`에 이유를 남겼다. 원시 응답·오류 표시는 유지했다. 추가 생성은 없었다.

전략 분포의 A↔C 거리(TV=확률 차이 절댓값 합의 절반)는 6원형 평균 SAR 0.116, K 0.069였다. 같은 입력 생성 2회 간 거리는 각각 0.142, 0.055였다. 탐색에서는 K가 덜 흔들렸지만, F02·F04는 K의 A↔C 전략 거리가 각각 0.150으로 작지 않았다. F04 K의 같은 뜻 A/C에서 평균 경로 길이도 2.442km와 1.703km로 달랐다. 작은 표본에서 안정성을 확정하거나 유의성을 주장하지 않는다.

응답을 직접 읽어 확인한 **비독립 AI 점검 사례**:

- `F05_B_k_0`: ‘계속 걷기’를 ‘직진·주변 인식 없이 한 방향’으로 확장.
- `F06_A_k_0`: 최근 한 달 관찰을 ‘실종 직전에도 확인’으로 바꿈.
- `F02_B_k_0`: 과거 반복 지향 관찰이 있는 도서관을 ‘언급만’으로 설명하고 ‘과거 이탈 패턴’을 추가.
- `F03_B_k_0`: 직접 관찰로 제시한 약국을 ‘언급 수준’으로 축소.
- `F03_A_sar_0`, `F03_B_sar_0`: 직접 관찰이 있는 약국을 ‘직접 관찰 근거가 없다’고 설명.
- `F04_B_sar_0`: 입력에 없는 공원·병원·편의점 라벨 추가. 최종 가중치에는 제거됨.

이 목록은 전수 인간 채점이나 오류율이 아니다. RAG가 두 모델에 공통 제공됐으므로 RAG 때문에 생긴 오류인지 모델/프롬프트의 일반화 때문인지는 이번 실험으로 분리할 수 없다. 기본 RAG의 QA에는 등급·성향 해석을 담은 문장이 포함돼 있었고, 모델 응답이 이를 개인 사실처럼 확장하는지 후속으로 살펴볼 필요가 있다.

## 5. 다음 작업 제안 — 이번 실행에 포함하지 않음

**추천 순서: 사람 검토 → 표현 가능한 행동·연결 구조 명세 → 필요한 범위의 후속 비교.** K를 바로 운영에 교체하기보다, 현재 결과를 개선 후보와 병목 확인 자료로 쓴다.

1. `blind_review.md` 72카드를 두 사람이 모델명을 보지 않고 판정한다. 입력 사실 보존·부정/시점·허구 사실·허용 가능한 행동 해석을 보고 불일치를 조정한다. `blind_review_key.json`은 평가자에게 별도로 숨긴다. 응답 스타일만으로 모델이 추측될 수 있어 완전한 맹검은 아니다.
2. 입력에서 ‘직진’을 직접 관찰했을 때와 ‘계속 걷기만’ 관찰했을 때를 구분하는 출력 근거 규칙을 설계한다. 모델이 출력한 사실·추론·문헌 일반론을 구분하고 각 행동의 입력 근거를 검토 가능하게 한다.
3. 실제 왕복·머무름·목적지 지나침을 어떤 상태/전이로 구현할지 먼저 정의한다. 왕복 패턴과 정지 시간을 기존 전략 이름만으로 구현됐다고 간주하지 않는다. radius는 신체 이동 능력 상한과 해당 상황의 이동 의도를 어떻게 함께 쓸지 명세한다.
4. P의 근거 충실성 문제가 정리되면 M(이동 중 마음 재해석) 비교 범위를 별도로 제안한다. 이번에 쓰지 않은 120회 M 또는 통합 720회 계획을 자동 실행하지 않는다.

위 표는 이번 실행분의 보조 근거다. 지원 차수와 지원 기간 전체 규모, API 지원/사용 기간은 사무국·공급자 증빙으로 확정해야 한다. 하루의 호출 확인을 지원 기간 1일이라고 단정하거나 양식 예시를 실적에 옮기지 않는다. 이 실험의 ‘성과’에는 개인 관찰의 행동 반영 비교와 시뮬레이터 연결 병목 도출을 쓰며, 발견율·예측 정확도 향상을 쓰지 않는다.

## 7. 산출물 읽는 순서

- `movement_comparison.html`: 파일 하나로 열 수 있는 보행 비교. 사례·A/B/C 선택, 30/100/500개 경로 표시, 스텝 진행 재생. 첫 생성 반복·시드 41로 고정해 결과 선택 편향을 피함. 화면의 500명 수치와 본 보고서의 반복·시드 합산 수치는 다름.
- `analysis.json`: 모든 원형·모델·변형의 6회 재생 집계, 형식·지연·토큰 통계.
- `outputs/`: 원시 요청/응답, 형식 오류, 후처리 전후 prior 72개.
- `replays/`: 216개 집계와 각 500명 전체 경로 gzip. 추가 모델 호출 없이 분석 가능.
- `rag/`: 실제 사용 발췌·출처·해시 6개. 검색 결과를 새로 고르지 않음.
- `inputs.json`, `rubric.json`, `preregistration.json`: 입력·임시 판정 기준·사전 설정. 사람 검토 미완료 상태 보존.
- `blind_review.md`, `blind_review_key.json`: 독립 사람 검토용 자료와 분리된 모델 대응표.
- `manifest.json`, `offline_checks.json`, `implementation_notes.json`, `usage_events.jsonl`: 재현성과 실행 근거.
