# 현재 판단과 다음 검증 방향

2026-09-24 사용자 논의 반영. **아래는 미실행 후보 설계이며 운영 도입 결정이나 추가 API 실행 승인이 아니다.**

## 검증 목표

**보호자 원문 + 기존 SAR 해석 + RAG → K 최종 초기 이동 성향 → 기존 수치 변환·제약 → OSMnx 보행**

SAR의 도메인 지식과 K의 개인 해석을 함께 활용할 수 있는지 판단한다. K를 앞단 추출기로 두고 SAR를 최종 판단자로 바꾸는 방향은 이번 최종 검증 목표가 아니다. 과거 보고서의 해당 권고는 당시의 탐색 기록으로 보존한다.

## K가 해야 하는 일

목적지·머무름·방향·거리의 네 항목에 대해 개인 관찰, 도메인 기반 가설, 미확인·충돌을 구분한다. SAR 제안을 유지하거나 수정할 때 근거와 변경 이유를 남긴다. ‘계속 걷기’를 ‘직진 관찰’로 바꾼 SAR 설명은 바로잡되, 개인 정보가 없다는 이유만으로 도메인 기본값 전체를 없애지는 않는다. 기본값과 관찰된 개인 특성을 표시상 구분한다.

네 피처에 대한 수정 권한을 주는 방향이 제안됐다. 구체적인 출력 골격, 등급·숫자 연결 규칙, 수정 허용 범위 및 판정 임계값은 후속 명세에서 확정해야 한다. 임의 반경·새 계수를 지금 확정하지 않는다.

## 비교 순서

1. **형식 안정성:** 실제 JSON 골격과 현재 제공 환경을 소규모로 확인. 토큰 상한 증량이 해결책이라고 가정하지 않음.
2. **해석 비교:** 동일 원문·SAR·RAG에서 기존 SAR 최종 출력과 K 최종 검토를 더한 출력을 비교. 관찰 누락/추가·부정/시점·피처 배치·충돌 보존·근거 없는 수정·SAR 오류 수정 여부를 사전에 정의.
3. **보행 비교:** 해석 조건을 통과하면 동일 OSM 도로·시드·제약·마음 OFF로 비교. 정보 하나를 바꿨을 때 관련 축에 반응하고 무관한 축은 불필요하게 바뀌지 않는지 확인.
4. **일반화와 사람 검토:** 프롬프트 개발에 쓰지 않은 사례를 잠그고, 두 명 이상의 독립 검토 및 불일치 조정 절차를 준비. 실제 경로가 없으면 사실 충실성과 시뮬레이션 일관성 범위로 결론 제한.

K가 기존 오류를 줄이고 개인 정보를 보행에 더 충실하게 반영하면서 새 오류·지연·비용을 감당할 수 있을 때 도입을 검토한다. 설명만 좋아지거나 SAR 오류를 복제하면 보류한다. SAR를 버린다는 결정도, K가 쓸모없다는 결론도 내리지 않았다.

실행 전 대상·조건·최대 호출량·예상 비용 또는 미확인 비용을 제시하고 사용자 승인 범위를 기록해야 한다. 이번 PR은 기존 결과의 정리만 수행한다.
