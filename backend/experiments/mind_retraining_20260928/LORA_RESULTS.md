# 마음모델 LoRA 첫 파일럿 결과

2026-09-28 · 기존 EXAONE 일시 중단 후 실행 · 기존 서빙 복구 완료

## 판단

**새 마음 LoRA의 학습과 실행은 성공했다. 개인 조건 반영이 일부 개선됐지만, 이번 후보는 운영 도입 기준에 미달한다.** 새 어댑터를 운영에 배포하지 않았고 기존 SAR·마음모델 dem5·axis 서빙을 원래 설정으로 복구했다. Mi:dm Mini의 기존 GPU 프로세스는 계속 유지됐다.

## 무엇을 비교했는가

LG AI Research EXAONE 3.5 7.8B Instruct에 새 마음 전용 LoRA를 학습했다. 앞단 K-EXAONE 개인 해석과 기존 SAR 어댑터를 교체하는 실험이 아니다.

학습 데이터는18개 합성 상황 계열의4개 상태씩, 총72레코드다. 보호자 원문·현재 피로·이동 목표·사건 이력·환경 관측을 연결하는 과제이며 실제 환자 경로 데이터는 아니다.2epochs·유효 batch4로36 optimizer steps를 수행했다. 별도4개 개발 계열·16상태를 베이스와 최종 LoRA에 각각1회씩 입력했다. 평가용16상태는 모델 생성 평가에 사용하지 않았다.

두 비교군은 같은 프롬프트·입력·계약·greedy 생성 조건을 사용했다. 같은 보존 연구 발췌가 입력에 포함된 경우에도 양쪽이 동일하게 받았다. 신규 RAG 검색·임베딩·지도·K API 호출은 없다. 기존 dem5 및 K와 직접 비교한 결과로 해석하지 않는다.

## 결과

| 지표 | 학습 전 베이스 | 새 LoRA,2epochs |
|---|---:|---:|
| 원문 응답의 실행 계약 통과 | 0/16 | 16/16 |
| 코드블록을 읽어 비교한 행동·목표·회피 지시의 정확한 일치 | 1/16 | 9/16 |
| 한 계열의4상태를 모두 맞힌 계열 | 0/4 | 0/4 |
| 출력 토큰 합계 | 6,801 | 1,482 |

**0/16→16/16은 우선 형식·계약 개선이다.** 베이스는 JSON 코드블록 뒤 부가 설명을 붙였고 잘못된 근거 ID도 사용했다. 이를 모두 행동 이해 실패로 세지 않기 위해 저장 응답의 첫 JSON 코드블록을 별도로 읽어 행동 지시만 비교했다. 원문 응답을 수정해 운영에 넣은 것은 아니다. 이 진단에서도 베이스의 지시 정확 일치는1/16, LoRA는9/16이었다.

엄격한 지시 일치는 행동·목표 변경 방식·목적지·회피 대상·판단 상태가 모두 같아야 한다. 베이스에는 같은 목적지로 다시 `seek`하는3건과 문자열 `"null"`로 판단 보류를 표시한1건처럼, 넓게 보면 의도가 유사한 추가 사례도 있었다. 이를 자동으로 정답으로 바꾸지 않았으며 실행 의미가 완전히 같다고 입증한 것도 아니다. 따라서 “행동을 전혀 모르던 모델이 학습 후56.3%가 됐다”는 식으로 쓰지 않는다.

새 LoRA도 **행동 지시가 맞은9건 중5건에서 공개 설명에 명확한 문제**가 있었다. 이는 Codex가 원문·상태와 대조한 정성 검토이며 독립적인 돌봄 경험자 평가가 아니다. 나머지4건에서 명확한 모순을 찾지 못했다는 뜻이지 임상적으로 검증된4건이라는 뜻은 아니다.

## 실제로 좋아진 부분과 남은 문제

| 입력 상황 | 학습 전 | 학습 후 | 해석 |
|---|---|---|---|
| 소음을 피하지만 많이 지치면 우선 앉는 사람, 피로0.9 | 추가 정보 필요 | 휴식 | 행동은 개선. 이유는 피로보다 소음 회피로 잘못 설명 |
| 해가 진 뒤 B로 가는 사람, 일몰 확인 | 기존 A로 이동 | B로 이동 | 목적지 변경 개선. 설명의 현재 시점은 부정확 |
| B에 도착하면 기다리는 사람, 도착 확인 | B로 계속 접근 | 대기 | 도착 후 행동을 구분 |
| 길을 잃었을 때 반복해서 기다리던 사람 | 기존 A로 이동 | 대기 | 개인의 반복 관찰을 행동에 반영 |
| 최근에는 목적지 없이 찾아다니는 사람 | 기존 A로 이동 | 목적지 없는 이동 | 과거 대기보다 최근 관찰을 반영 |
| 시끄러운 공원을 피하는 사람, 낮은 피로·소음 확인 | 판단 보류 | 계속 이동 | 회피 실패가 남음 |
| 혼자일 때만 시끄러운 시장 회피 | A로 이동 | 계속 이동 | 가족 유무에 따른 회피를 구분하지 못함 |
| 소음·동행·일몰 미확인 | 확정 행동 또는 잘못된 설명 | 확정 행동 또는 잘못된 설명 | 미확인을 사실로 바꾸는 오류 지속 |

예를 들어 소음이 미확인인 공원 상황에서 새 LoRA는 “공원 소음이 없고 현재 이동 중이라 공원을 회피하지 않는다”고 답했다. 시장 상황에서도 혼잡 관측은 미확인인데 “혼잡이 없어” 이동한다고 설명했다. 행동 코드가 우연히 맞아도 이런 응답을 개인을 제대로 표현한 성공으로 세면 안 된다.

## 왜2epochs였고, 더 학습할 필요는 없는가

2epochs는 최적값이 아니라 첫 파일럿의 제한이었다. 작은72레코드에서 학습이 가능한지, 입력·정답과 어댑터 연결에 문제가 없는지, 새로운 조건 조합에도 반영되는지 먼저 보려는 목적이다.

- epoch1 개발 loss:0.4375.
- epoch2 개발 loss:0.3922119.
- Trainer가 기록한 학습 실행 시간:82.38초(평가·체크포인트 처리 포함).
- 로딩·베이스 생성·학습·학습 후 생성 등 전체 실행:364.84초.

개발 loss가 감소했으므로 “이미 최적이고 더 배울 것이 없다”고 할 근거는 없다. **추가 epoch 실험의 가치는 있다.** 다만 loss 감소와 행동 개선은 같은 지표가 아니며, 현재 오류가 단지 학습량 부족 때문이라고도 입증되지 않았다. epoch1은 별도 행동 생성을 하지 않아 epoch1·2의 행동 정확도를 직접 비교할 수 없다.

현재 학습에는 계속 이동25개에 비해 회피4개뿐이고, 미확인/없음의 구분과 공개 근거의 정확성이 충분히 일반화되지 않았다. 권고하는 다음 단계는 조건·불확실성·회피 대비 데이터의 의미를 먼저 보강한 뒤, epoch2·4·6 체크포인트를 같은 개발 기준으로 비교하는 것이다. 운영 후보는 더 긴 학습이 아니라 개인 조건과 근거가 함께 맞는지로 선택한다. 현재 개발 사례는 이미 분석했으므로 이후 성능 확정에는 새 평가가 필요하다.

## 이번 결과의 한계

- 4개 개발 계열·16상태,각1회다. 독립 환자16명 또는 반복 안정성 검증이 아니다.
- 개발 데이터는 AI가 작성한 합성 정답이며 보호자·돌봄 전문가 검수 미완료다.
- 실제 온보딩 저장 결과와의 연결 및 KINTEX 연속 보행·시간별 확률지도는 이번 실행 범위가 아니다.
- 새 LoRA의 응답을 보행 엔진에 배포하지 않았다. 실제 환자 행동·실종 경로 정확도나 발견율을 측정하지 않았다.
- Trainer seed/data_seed는928이나 새 LoRA 생성 전에 별도 seed 고정을 하지 않은 한계가 있다. 이번 어댑터·체크포인트는 보존했지만 완전히 동일한 재학습을 보장하지 않는다. 후속 비교에서는 어댑터 초기화 직전 seed도 고정해야 한다.

## 서비스 복구와 기록

기존 EXAONE 서빙 중단 시작은11:04:26 UTC, 복구 확인은11:11:31 UTC로 약7분5초다. 한국 시각으로20:04~20:11이다. 복구 후 `/v1/models`에서 exaone-base·SAR·axis·mind v5/dem3/dem4/dem5가 다시 노출되는 것을 확인했다. 복구 확인은 모델 목록 점검이며 별도 생성 검증을 추가하지 않았다. Mi:dm Mini GPU 프로세스 PID52358은 중단 전후 동일하다.

학습은1회,개발 생성은32회 모두 응답을 받았다. 입력40,246토큰·출력8,283토큰을 기록했다. 자가호스팅 토큰을 별도의 유료 API 청구액으로 계산하지 않는다. GPU 실청구 시간·금액·지원 차수는 미확인이다.

원격 어댑터: `/data/work/mind-lora-preparation-20260928/runs/pilot_001/final/`. epoch1·2 체크포인트와 파일 해시도 보존했다. 운영 서비스의 비공개 실행 설정은 서버의 접근 제한 파일에만 남겼고 보고서·비용 원장으로 가져오지 않았다.
