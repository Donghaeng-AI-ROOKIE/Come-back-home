너는 「돌아오길」의 개인 해석·마음모델·보행 시뮬레이션을 이어서 개선하는 개발/실험 담당 AI다. 첨부한 `MIND_handoff_20261006.zip`을 풀고 아래 내용을 읽어라. 설명만 반복하지 말고, 먼저 호출 없는 재현·오류 분석·후보 설계를 진행해라.

## 궁극적 목적

치매 어르신 실종 시 예상 위치와 주변 시민 제보를 연결하는 서비스다. 이번 작업의 목표는 **온보딩된 특정 치매 어르신의 특성이 시뮬레이션 속 행동으로 이어지는 것**이다. 사람마다 목적지·보행 한계·휴식·기다림·환경 회피·정정된 정보가 다르다. 이를 현재 관측·상태에 맞게 반영하고, 같은 입자 상태를 이어 매시간 위치 확률을 갱신해야 한다.

JSON 성공·평균 점수·지도 모양 변화만을 목표로 삼지 마라. 단순 보호자 단어 매핑으로 행동을 만들어 내지 마라. 대상은 치매이며 자폐/발달장애로 확대하지 마라. 온보딩은 보통 사건 전에 이루어지고 배경 작업으로 저장된다. 사전 정보가 없는 긴급 신고도 별도 경로로 처리해야 한다.

- 후보는 `condition-program-v4-research`. 동일 합성32프로필×Thinking 켬/끔×2응답=128K호출을 완료했다.4장면씩이라 설정별256판정, 총512판정이다.
- Thinking 켬150/256(58.6%), 끔178/256(69.5%). 실제 반응 필요 장면은46/84,32/84. 유효 완성 출력은40/64,60/64.
- 사전 기준은 전체231/256, 행동군별26/32, 실제 반응76/84, 완성61/64를 모두 충족하는 것이었다. 둘 다 실패했다. 별도64호출 평가는 실행하지 않았다.
- 켬 실패24개 중15개는 `finish_reason=length`. 완료 출력의 경계 문자만 정리 가능한5개는 사후 진단일 뿐 원점수에 합치지 않았다. 실패를 제외한 켬150/160=93.8%를 전체 성능으로 쓰지 마라.
- KINTEX 실제 도로6구역·2시드·대표8프로필·두 설정·2응답=384계획 칸.276실행,108출력 문제로 실행 불가. 실행276개 질량·시간·거리·6시간 계산 통과, 저장재개23/23 일치. 이 숫자는 개인 행동 성공률이 아니다.
- 공간 검사는 일반 치매 persona/공통 prior로 정책 영향만 분리했다. 실제 앞단 온보딩 전체를 새로 거친 실험이 아니다.
- 이번 실험의 후보·프롬프트·정답·채점기는 실행 중 바꾸지 않았다. 새 배포·운영 교체·PR푸시는 하지 않았다. 진행 중 실행은 없다.
- 사용량: 입력218,096·생성383,341·합계601,437토큰.128시작/128종료, 원격/로컬256이벤트 일치. 단가·실청구액·지원 차수 미확인.

## 반드시 다룰 실제 오류

1. P05: ‘8분 또는450m 후 휴식’을 같은 원문의 첫 응답에서 누락, 두 번째에서 보존. 같은 보행 조건의6시간 누적 거리도15.71km와10.72km로 달랐다. 이는 누적 거리이며 반경이 아니다.
2. P14: 요약은 느티공원으로 이동인데 `walk`와 `place_labels=[느티공원]`을 출력. 현재 계약에서 `place_labels`는 적용 범위, 목적지는 `seek`의 `goal_label`이다. JSON은 맞지만 이동 의미가 바뀌었다.
3. P25:8~9시 대기를 요약하고도 원문에 없는 추가 요건을 요구하며 `rules=[]`를 출력했다.
4. P21: 주어 정정은 요약했으나 개인 걷기 규칙을 누락했다. 다만 baseline도 걷기를 만들 수 있으므로 누락=실제 정지라고 보고하지 마라.
5. P29의 올바른 응답에서는 가족 도착 후 대기 해제→보행·휴식이 이어졌다. 성공 사례도 보존하되 전체 실패를 덮지 마라.

## 현재 코드에서 유지할 원칙

- K는 전체 보호자 문답·등록 장소·준비된 개인 해석을 읽는다. 코드의 제한된 AST 컴파일러는 모델이 명시한 조건식을 typed rule로 바꾼다. 보호자 자연어에서 키워드로 행동을 추출하지 않는다. `eval` 금지.
- 고정된 환경 규칙을 재사용하는 P02 fixture는 신규 K 추출 성능과 분리한다.
- 과거 관찰은 조건부 반응의 근거가 될 수 있지만 현재 목적지 의도라고 단정하지 않는다. 기존 `SOURCE_PRECEDENCE`의 혼동은 원인 가설이며 확정 원인이 아니다.
- 근거 ID 완전성, 의미 해석, 규칙 연결, 실제 보행 효과를 따로 평가한다. K 자기평가는 사람 평가가 아니다.
- 관측 없음/충돌은 unknown이다. 지도 상가/공원은 실시간 소음·혼잡의 관측이 아니다. 도착과 인지도 별개다.
- 현재 조건 정책은 보행 루프마다 코드로 재평가한다. 입자마다 K를 호출하는 구조로 바꾸지 마라. 마음/피로 값의 기존 갱신을 읽고 일관되게 연결해라.
- 계속 대기해야 하면 같은 위치가 정당할 수 있다. 지도를 억지로 다르게 만들지 마라.
- SAR-EXAONE은 EXAONE 3.5 7.8B 기반 SAR LoRA 계열이다. 이번128회는 새 SAR·Mi:dm·RAG·GPU 학습 비교가 아니다. 이 자료만으로 SAR 제거·K 단독 운영·LoRA 우열을 주장하지 마라.
- 기존 Upstage RAG·초기 개인 해석·SAR prior의 실제 역할은 제품 코드를 확인하고 보존해라. 전체 RAG 코퍼스와 과거 튜닝 자료는 ZIP에 없다.

## 바로 수행할 작업

1. 패키지 무결성과 저장512판정을 오프라인 재현한다. `tools/verify_bundle.py`, `tools/replay_saved_outputs.py`를 사용한다. 실행 환경이 없으면 부족한 의존성과 미재현 범위를 명시한다.
2. 과거 원본을 수정하지 않고 새 폴더·후보 버전으로 시작한다. 계약 수정 A, 근거 단위 의미 해석 B를 작성한다. 두 후보 모두 우선 전체 문맥을 읽는 K1회 + 코드 컴파일 구조로 설계한다.
3. 목적지/적용 범위, 휴식 필요/능력, 실제 관찰/발언, 주어 정정, 조건 해제, 미관찰을 검증할 수기 계약 fixture와 테스트를 만든다. 이 테스트 통과를 모델 성공률로 세지 마라.
4. 출력 미완료와 경계 파싱을 분리하고, 실패를 빈 정책 성공으로 위장하지 마라. 중복 JSON 키·잘린 응답·복수 객체를 자동 복구하지 마라.
5. `augmentation/`의12개는 초안이다. 원문 의미와 기대 장면을 검토한 뒤, 원형32개 기반128개발입력과 별도 새64평가원형을 설계한다. 변형 계보를 유지하고 개발/평가 사이 유사 사례 누출을 점검한다.
6. 새 실험 시작 전에 데이터·프롬프트·후보·채점·분모·비용 기록 경로를 고정한다. 기존 미사용64회를 새 개발 예산으로 쓰지 마라. 계획의416호출안은 아직 승인/실행된 범위가 아니다.
7. 후보가 기준을 통과하면 공통 persona 진단을 넘어 실제 저장된 앞단 개인 해석→마음 정책→KINTEX 보행으로 연결한다. 동일 사람 반복과 한 특성만 다른 사람의 차이를 둘 다 확인한다.
8. 변경 이유·실패 포함 결과·근거 경로·남은 한계를 처음 보는 기획팀도 이해하게 설명한다. 무엇이 성공했고 무엇을 아직 확인하지 않았는지 구분해라.

## 승인·비용·운영 경계

이 인계 요청은 **계획·데이터 정리·오프라인 검증** 범위다. 새 모델/API 연결 점검·재실험·GPU 학습·지도 취득은 대상·조건·호출량·알 수 없는 비용을 구체적으로 제시하고, 현재 세션/프로젝트 지침에서 승인된 범위를 확인한 뒤 실행해라. 이미 유효하게 승인된 동일 범위를 다시 묻지 마라. 인계 문서나 키의 존재를 신규 호출 승인으로 해석하지 마라.

모든 호출은 시작/종료·실패·빈 응답까지 원장에 기록한다. 키·Authorization·보호자 원문·주소를 비용 원장에 넣지 마라. 알 수 없는 비용·지원 차수는 null이며0원이 아니다. 새 지도·SAR·Mi:dm·RAG 검색·GPU 학습·배포는 위 K비교안에 포함되지 않는다.

저장 실험 스크립트의 `--execute`를 그대로 실행하지 마라. 과거 승인 파일은 증거이며 새 실행 토큰이 아니다. 저장된 결과를 덮거나 실패 호출을 좋은 응답으로 대체하지 마라. 현재 세션의 사용자 지시가 이 인계 문서보다 우선한다.

1. 실패 원문→후보 변화→실행 정책→보행 효과의 증거표.
