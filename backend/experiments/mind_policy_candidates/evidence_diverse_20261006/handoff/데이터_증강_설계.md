# 데이터 구성과 증강 설계

## 현재 포함한 데이터

| 자료 | 수량 | 용도·한계 |
|---|---:|---|
| `profiles.json` | 32합성 프로필 | 전체 문답·등록 장소·기존 준비 정보. 이미 결과를 봤으므로 개발 자료 |
| `scenes.json` | 128장면 | 상태·관측·기대 행동. 모델 입력 금지 |
| `reference_policies.NOT_MODEL_INPUT.json` | 참조 정책 묶음 | 수기 기대 정책. 채점 일관성 확인용이며 K 응답이 아님 |
| `comparison/` | 128요청·공개 응답·결과 | 실패까지 포함. 유효 출력에만 컴파일 정책 존재 |
| `replayed_results.json` | 512행동 판정 | 실패를 분모에 포함한 결과 |
| `spatial/` | 384계획 칸 | 276실행·108실행 불가. 독립 환자 수가 아님 |
| `augmentation/input_examples.draft.jsonl` | 12초안 | 이번 인계를 위해 작성한 합성 증강 예시. 호출·훈련·성능 평가 미실행 |
| `augmentation/review_examples.NOT_MODEL_INPUT.jsonl` | 12검토 메모 | 각 변형에서 보존/변경돼야 할 의미, 아직 확정 정답 아님 |

입력의 출처 태그 `guardian_original`은 합성 문답을 시험 계약에 맞춰 표현한 것이다. 전부 실 환자 자료라고 소개하면 안 된다. P02의 준비 정보는 수기 fixture라서 신규 추출과 별도로 보고한다.

## 무엇을 늘릴 것인가

단순히 이름·장소명만 바꿔 개수를 늘리지 않는다. **같은 뜻을 다른 말로 표현해도 보존하는지**, **뜻이 달라지면 행동도 적절하게 달라지는지**를 함께 본다.

| 증강 축 | 보존 변형 | 의미가 달라지는 대조 |
|---|---|---|
| 수치·단위 | 팔 분↔8분, 사백오십 미터↔450m | 8분 OR 450m↔두 조건 모두 필요 |
| 문답 표현 | 짧은 답·반복·구어체·가벼운 오타 | 질문의 가정↔보호자가 실제 관찰한 일 |
| 주어·정정 | 아버지 설명을 어머니로 정정하는 문맥 보존 | 타인 사례↔대상 본인 사례 |
| 장소 | 이름 표기 변화에도 등록 장소 결합 보존 | 특정 상가만↔모든 상가, 목표↔적용 범위 |
| 행동 근거 | 과거 두 번 관찰한 조건부 반응의 바꿔 말하기 | 가고 싶다는 발언↔그쪽으로 실제 출발 |
| 신체 | 쉬어야 하는 필요의 바꿔 말하기 | 걸을 수 있는 능력↔쉬어야 하는 필요 |
| 관측 | 없음을 관찰했다는 의미 보존 | 없다고 관찰↔보지 못함/모름 |
| 시간·해제 | 오전8~9시 표현·가족 도착 시 해제 보존 | 시계 시각↔보행 경과, 9시 종료↔9시 시작 |
| 복합 행동 | 기다림+휴식의 문답 순서를 바꿔도 각각 보존 | 우선순위 명시↔미명시 충돌 |

원문의 수치를 바꾸면 입력뿐 아니라 기대 조건·경계 장면도 함께 바꾼다. 장소를 바꾸면 등록 장소·좌표 결합도 갱신한다. 정답을 바꾸지 않은 채 문장만 뒤집으면 잘못된 데이터가 된다.

## 권장 개발 데이터: 128입력

기존32원형마다 다음4형태를 만든다.

1. 원본1개.
2. 의미를 보존한 구어체/문답 변형1개.
3. 한 요인만 바꾼 반사실 변형1개.
4. 다중 문답·정정·미관찰 경계를 강화한 변형1개.

총128입력이지만 독립 인물128명이 아니다. 원형32개의 파생 집단으로 보고한다. 이번 ZIP의12개는 작성 방법을 보여 주는 초안이며 전체128개가 만들어진 것은 아니다.

각 입력마다 최소4장면을 새로 고정한다: 발동, 비발동, 해제/경계, 미관찰/불일치. 한 원문이 복합 행동을 포함하면4장면으로 충분한지 검토하고 필요한 경우 늘린다. 장면 수를 바꾸면 판정 분모·호출 수와 구분해 기록한다.

## 별도 평가: 새64원형

- 8행동군×8새 원형. 개발32원형의 문장·숫자·이름만 바꾼 파생본을 새 평가로 세지 않는다.
- 원형별4장면·모델2응답. 후보1개라면128모델 호출·512행동 판정.
- 개발용/평가용 분할은 **원형 계보와 의미상 유사 시나리오 묶음 단위**로 먼저 고정한다. 질문 구조·조건 조합이 거의 같은 자료도 누출 검토 대상으로 표시한다.
- 평가 입력·정답·채점기는 후보를 고정하기 전에 검토·해시 보존한다. 모델에는 원문과 필요한 등록 정보만 제공한다. 정답·참조 정책·평가 장면을 넣지 않는다.
- 같은 작업자가 평가 자료를 작성하거나 읽었다면 그 사실을 밝힌다. ‘한 번도 본 적 없는 외부 독립 평가’라고 쓰지 않는다. 가능하면 별도 검토자가 작성·확정한다.
- 결과를 보고 후보를 바꾸면 그 평가 세트는 이후 개발 자료가 된다. 새 버전의 최종 근거에는 다음 별도 세트를 사용한다.

## 레코드와 출처 관리

증강 입력 파일은 모델에 전달할 본문과 관리 정보를 구분한다. `personal`만 모델 요청 빌더에 넘기고 원형 ID·변형 이름·정답을 프롬프트에 넣지 않는다.

```json
{
  "id": "DEV_P05_language_01",
  "root_id": "P05",
  "split": "development",
  "synthetic": true,
  "review_status": "draft_unreviewed",
  "personal": {"notes": [], "places": [], "prepared_initial": {}}
}
```

검토 메모는 별도 파일에 `id`, `transformation`, `expected_relation`, `semantic_changes`, `required_scene_checks`, `reviewer`, `review_status`로 저장한다. 원문·정답·검토 수정 이력과 SHA-256을 보존한다. `draft_unreviewed`인 자료는 학습·최종 평가에 쓰지 않는다.

## 확정 정답을 만드는 절차

1. 원문 의미 판정: 누구의 행동인지, 실제 관찰/발언/신체 필요/능력인지, 어떤 조건에서 언제까지인지 읽는다.
2. 실행 계약 판정: 현재 허용 사실·명령으로 표현할 수 있는지 확인한다. 표현할 수 없는 내용을 거짓 사실로 바꾸지 않는다.
3. 참조 정책과 장면 검토: 조건의 AND/OR·부정·경계·미관찰을 손으로 대조한다. 조건식 참조가 컴파일된다는 이유로 자연어 정답이 맞다고 간주하지 않는다.
4. 모델명이 가려진 사람 검토를 의뢰할 경우 실제 검토자·날짜·불일치·합의 결과를 남긴다. AI가 작성·검토한 자료를 돌봄 경험자/전문가 판정으로 표기하지 않는다.
5. 검토를 마친 자료만 고정한다. 애매하면 가능한 행동 집합/unknown으로 표현하거나 보류한다. 평가 모델에게 정답을 채택하도록 맡기지 않는다.

자연어→행동의 타당성과 임상적 타당성은 별개다. “8분 후 휴식”이라는 합성 지시를 잘 지켰다는 사실만으로 실제 치매 어르신의 적정 휴식시간이8분이라고 주장하지 않는다.

## 재학습에 사용할 경우

현재 ZIP은 **평가·증강 설계용**이며 바로 학습 가능한 임상 데이터셋이 아니다.

- EXAONE 3.5 7.8B + LoRA 후보를 학습한다면, 검토 완료된 원문→최종 구조화 출력만 학습 예제로 사용한다.
- K의 실패 응답·평가 정답·숨은 Thinking을 그대로 학습하지 않는다. 평가용 원형과 파생본은 학습에서 제외한다.
- 증강된 수천 문장이 있어도 원형 수·행동군·희귀 오류·검토 완료율을 함께 보고한다. 데이터량이 임상 다양성을 대신하지 않는다.
- 논문은 참고 지식/RAG 근거로 사용하며 저작권·출처·추출 방법을 보존한다. 보호자 자료는 수집 권한·동의·비식별·파기 범위를 확인한 뒤 별도 관리한다.
- 학습 전에 라벨 종류·지원 계약·데이터 분할을 고정한다. JSON 경계 오류만으로 GPU 재학습부터 시작하지 않는다.

## 실제로 만들어 둔 것과 아직 안 한 것

만들어 둠: 기존 실험 원자료·결과 묶음,12개 합성 증강 초안과 검토 메모, 원형별 분할 규칙, 검증 도구.

아직 안 함: 증강128입력 완성·검토, 새 평가64원형 작성·검토, 전문가 검토, 신규 모델 실험, SAR LoRA 재학습, 운영 배포.
