# 초기 이동 성향 전체 안정화 — 구현 전 명세

2026-09-23. 사용자 확인 범위: 목적지·머무름·방향·거리. 마음 재해석은 이후 단계로 분리한다.

현재 상태: 설계 문서 작성. v2 모델 호출·보행 재실험·운영 변경 없음. 기존 실험 실행 승인을 새 조건의 호출 승인으로 재사용하지 않는다.

## 1. 완료 목표

보호자 정보와 SAR·RAG의 도메인 가설을 구분하여 초기 이동 성향을 만들고, 그 구분을 실제 보행 입력까지 보존한다. 실제 실종 경로의 예측 정확도 입증과는 별도 목표다. 실제 경로 데이터가 없는 상태에서 임상적 정확성·완벽한 개인 재현을 주장하지 않는다.

입력 → 피처별 근거·해석 → 검증 → 명시적 수치 변환 → 기존 물리·통계 제약 → 마음 OFF 보행의 순서로 검토한다.

## 2. 역할과 변경 범위

- SAR: 도메인 관점의 기준 해석 제공. 정답이나 순수 통계로 취급하지 않는다. 이전 실험의 고정 SAR 참조 한 개로 모든 사람을 설명할 수 있다고 가정하지 않는다.
- 기존 RAG: 일반 행동 가설과 적용 조건 제공. 검색기·인덱스 재구축은 이번 설계의 기본 범위 밖이다. QA의 서술과 논문 원문에서 직접 확인된 사실을 구분한다.
- K-EXAONE: 개인 관찰을 보존하고, 도메인 가설의 적용·불확실성·충돌을 피처별로 해석한다.
- 코드: 검증, 근거 추적, 피처와 보행 파라미터의 연결, 정규화, 기존 제약 적용, 실제 변경값에서 설명 생성.

K가 최종 확률과 증감 설명을 각각 자유 생성하는 구조를 줄이는 것이 후보 변경이다. 숫자로 옮기는 강도·계수는 아직 확정하지 않는다. 임의의 계수를 만들어 모델의 오류를 가리는 방식으로 구현하지 않는다.

## 3. 피처별 출력 계약

모든 피처는 개인 근거 ID·정확한 인용, 일반 가설과 출처 ID·적용 한계, 해석, 미확인 정보, 충돌 정보를 별도로 보존한다. 한 문장에 여러 특성이 있으면 관련 부분을 각각 참조할 수 있다.

관찰이 없다는 사실은 반대 행동을 관찰했다는 뜻이 아니다. 과거 이력이 있고 최근 정보가 없다는 사실도 과거 이력이 사라졌다는 뜻이 아니다. 일반 가설은 직접 개인 관찰이 없더라도 사용할 수 있지만, 관찰 사실로 바꾸면 안 된다.

| 피처 | 해석할 내용 | 반드시 구분할 내용 | 우선 연결 후보 |
|---|---|---|---|
| 목적지 | 등록 장소별 과거 친숙함·최근 지향·추정 의도 | 시장 지향과 직진, 최근 선호와 과거 친숙함, 장소 미언급과 회피 | 장소별 상대 가중치. 특정 전략까지 바꾸려면 추가 근거 필요 |
| 머무름·이동 지속 | 길을 잃었을 때 계속 이동/근처 머무름, 관찰 상황 | 계속 이동과 방향 유지, 근처 종료와 실제 정지 시간 | staying_put과 나머지 이동 구성의 비율 |
| 방향·경로 형태 | 직진·잦은 전환·되돌아감·익숙한 길 이용 | 직진과 친숙한 경로, 잦은 전환과 완전 무작위, 되돌아감과 원점 근처 종료 | 관련 방향 선택·전략 구성. 현재 엔진 표현 가능 여부 확인 |
| 거리·이동 능력 | 실제 보행 제약·보조기구·관찰 거리/시간·이동 수단 | 누적 이동 길이와 직선 변위, 정보 부족과 능력 정상, 걷기 지속성과 장거리 능력 | 검증된 개인 축 및 기존 반경·신체 제약 경로 |

예시 입력: ‘시장을 향해 계속 걷는 모습을 봤지만 방향을 바꾸는지는 관찰하지 못했다.’

- 목적지: 시장 지향 관찰 있음.
- 이동 지속: 지속 보행 관찰 있음. 중간 휴식 시간은 미확인.
- 방향: 직진/전환 모두 개인 관찰 미확인. 도메인 가설은 별도로 유지 가능.
- 거리: 이 문장만으로 보행 속도·최대 이동 거리를 확정하지 않음.

이는 목표 정답 확률을 정하는 예시가 아니라, 입력 의미를 보존하는 검증 예시다.

## 4. 수치 변환 설계 원칙

1. 기준값, 근거에 따른 변경 요청, 코드 적용값, 제약 적용 후 최종값을 모두 구분해서 저장한다.
2. 증감 설명은 실제 전후 값으로 코드가 생성한다. 모델 설명과 숫자가 따로 움직이지 않게 한다.
3. 목적지만 바꾼 조건에서 다른 피처를 바꾸려면 명시적 근거나 승인된 상호작용 규칙이 필요하다. 모든 개인 특성이 완전히 독립적이라고 가정하지 않는다.
4. 머무름만 조정하는 분리 검증에서는 나머지 다섯 전략의 조건부 비율을 보존하는 변환을 검토한다. 합이 1인 전체 확률의 작은 변화는 정규화 결과일 수 있으므로 변화 자체를 오류로 판정하지 않는다.
5. 기존 코드의 0.02 확률 바닥값·정규화·신체 축 우선 정책을 먼저 계측한다. 원출력과 제약 적용값의 차이를 K의 판단 변화로 오인하지 않는다. 이를 즉시 제거하거나 바꾸지 않는다.
6. 과거 세 장소 모두 친숙하면서 최근에는 한 장소로 향하는 상황을 표현할 수 있어야 한다. 현재 상/중/하에서 모두 상이 되는 포화 문제를 해석과 상대 선호 표현 관점에서 검토한다.
7. 근거가 부족한 피처는 기존 기준을 유지하거나 불확실 상태로 남긴다. 보호자 관찰이 없다는 이유로 모든 일반 행동 가능성을 0으로 만들지 않는다.
8. 모호한 형식/의미 오류의 운영 fallback은 별도 설계한다. fallback을 사용한 사례를 K 해석 성공으로 집계하지 않는다.

## 5. 거리와 보행 표현 범위

기존 검토 문서에서 확인된 통계 변위 분포, 신체 상한, 누적 경과시간 처리, 개인 축 우선 정책은 먼저 보존한다. K가 임의로 km를 정하고 기존 반경을 덮어쓰게 하지 않는다.

현재 경로는 통계적 위치 표본을 만들기 위한 경로다. 정확한 한 시간의 이동·휴식 타임라인으로 해석하지 않는다. 마음 OFF에서의 초기 성향 안정화와 별개로 이 표현상의 한계를 명시한다.

- 머무름: 출발지 근처 종료와 실제 정지 시간을 구분한다.
- 직진/전환: 도로 굴곡 자체와 갈림길 선택을 구분한다.
- 익숙한 길: route_following이 실제 과거 경로 시퀀스를 사용한다고 가정하지 않는다.
- 거리: 누적 도로 길이, 출발지 대비 변위, 요청 경과시간, 내부 게이지 시간을 각각 기록할 필요가 있다.

새 계측·보행 정책 변경은 설계·검토 후 별도 작업으로 다룬다. 시연이 선명해진다는 이유만으로 임상적 타당성이 높아졌다고 판단하지 않는다.

## 6. 검증 사례 구성 — 실행 전 후보

결과를 보고 유리한 사례만 골라내지 않도록 호출 전에 사례·판정 규칙·실패 처리·통계 집계를 고정한다.

| 사례군 | 핵심 판정 |
|---|---|
| 목적지만 변경 | 최근 방향에 대응하는 장소 해석 변화, 근거 없는 직진/체력 변화 없음 |
| 머무름 ↔ 계속 이동 | 지속성 의미 보존, 방향 유지 관찰을 임의 생성하지 않음 |
| 직진 ↔ 잦은 방향 전환 | 명시된 갈림길 행동 반영, 일반 가설이 직접 관찰을 덮어쓰지 않음 |
| 이동 능력 정보 변경 | 명시된 제약 반영, 기존 개인 축·반경 연결 확인 |
| 관찰 없음 | 미확인 보존, SAR·RAG 가설을 개인 사실로 기재하지 않음 |
| 상충 관찰·시점 차이 | 두 근거를 보존하고 충돌·시점을 표현, 임의로 한쪽 삭제하지 않음 |
| 의미가 같은 재서술 | 핵심 피처 판정의 일관성 |
| 동일 입력 반복 | 핵심 판정·변환 결과 변동과 실패율 공개 |

현재 6사례만으로 이동 능력 차이·충돌 처리까지 검증했다고 할 수 없다. 새로운 사례 및 평가 기준은 출력 확인 전에 고정하고, 개발에 사용하지 않은 보류 사례를 둔다. 사람 검토를 받는 경우 구성명을 가리고 같은 기준으로 평가한다.

## 7. 다음 단계 진입 기준

### 필수 오류 기준

고정된 검증 집합에서 다음 오류가 남으면 원인을 해결하고 해당 단계 완료를 보류한다. 미리 정한 집합의 오류 0건은 전체 실제 사용자에서 오류가 없다는 보증이 아니다.

- 개인 관찰의 날조·반대 의미 변환·중요한 상충 근거 삭제.
- 등록되지 않은 장소나 근거 없는 개인 능력 생성.
- 사용 불가능한 필수 수치의 임의 채움.
- 증감 설명과 코드 적용값의 불일치.
- 도로·기존 신체 및 통계 제약을 설명 없이 벗어나는 변환.

### 반복성과 보행 전달 기준

판정 기준·허용 변동·집계 방식은 새 실행 전에 구체화한다. 현재는 숫자 기준이 확정되지 않았으므로 다음 API 비교를 시작할 준비가 끝난 상태가 아니다.

- 같은 의미 입력에서 핵심 해석이 얼마나 유지되는지.
- 의미 변경 효과가 같은 입력의 반복 변동과 구분되는지.
- 입력 → 해석 → 수치 → 보행 중 어디서 차이가 사라지거나 의도하지 않은 변화가 생기는지.
- 원출력 실패·형식 복구·fallback·성공을 따로 집계하는지.
- 두 구성의 같은 사례·반복·시드가 모두 있는 비교와 전체 결과를 구분하는지.

실제 확률의 정답은 미확보다. 행동 변화가 클수록 좋다는 판정이나, 서로 다른 행동이 보이면 정확한 개인 표상이라는 판정은 사용하지 않는다.

## 8. 실행 순서

1. 기존 형식 복구 후보와 검증기를 공통 입력 처리로 검토. 원문·복구 기록·나머지 오류 보존.
2. 피처별 출력 계약과 근거 추적 구조를 코드로 검증 가능하게 구체화.
3. 기존 보행 파라미터 연결을 확인하고, 수치 변환 후보·변경 이력을 명세화. 숫자 계수는 미확정.
4. 저장 출력과 합성된 코드 입력으로 로컬 불변조건 점검 준비. 새로운 보행/모델 실험은 포함하지 않음.
5. 사례·반복·호출 상한·토큰/비용 추정 또는 미확인 항목·사용 원장 경로를 포함한 다음 실험 패키지 작성.
6. 사용자 승인 범위에서 초기 성향만 비교. 완료 기준 충족 후 마음 재해석 실험을 별도로 설계.
